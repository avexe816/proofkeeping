# UI・文言・現場 UX ルール

画面を作るときは必ずこれを読む。

## 1. 言語

- UI 文字列を JSX に直書きしない。すべて `t("key")` 経由。
- ESLint の `no-literal-string`（JSX 限定）で強制。
- 既定は日本語。モバイルのみ英語対応。管理画面は日本語のみ。
- ブラウザの言語設定を参照しない（共用端末で誤動作するため）。ユーザー属性で保持。

## 2. 使ってはいけない言葉

| 使わない | 使う |
|---|---|
| 不正検知 | 稼働照合 |
| 疑わしい取引 | 要確認項目 |
| 監視レポート | 差異レポート |
| 証拠 | 証跡 |
| 従業員の監視 | 内部統制の支援 |
| 異常 | 通常と違う点 |
| 不審な点 | 気づいたこと |
| チェック（監視の意味） | 記録 |
| 報告義務 | 記録のお願い |
| やり直し | 再清掃 |

CI で禁止語の grep 検査を行う。UI・API レスポンス・PDF テンプレートすべてが対象。

## 3. 現場向け UI（`/m/*`）

清掃スタッフは手袋を着け、暗い客室や明るい屋外で、短時間で操作する。

**MUST**
- タップ領域は最小 48×48px。主要ボタンは 56px 以上。
- フォント最小 16px。
- 数値入力にキーボードを出さない。ステッパーとプリセットボタンのみ。
- 主要操作は 1 タップ。確認ダイアログを挟まない（「開始する」など）。
- コントラスト比 4.5:1 以上。
- プルダウン更新（pull-to-refresh）に対応。
- 30 秒ごとの自動更新。手動更新ボタンも置く。
- オフライン時は画面上部に「オフライン・N件未送信」バーを常時表示。

**やらない**
- 「すべてチェック」ボタン（チェックリスト・検査項目とも）
- 経過時間超過の赤色表示（オレンジとグレーまで。急かさない）
- 他人との比較・ランキング表示
- 検査項目の初期値を全 PASS にすること

## 4. 入力設計の原則

### 清掃員に「判断」させない
| 禁止 | 許可 |
|---|---|
| この部屋は使われましたか？ | ベッドはいくつ使われていましたか？（0/1/2） |
| 不審な点はありましたか？ | ゴミの量は？（なし/少ない/通常/多い） |
| 宿泊人数は何人だと思いますか？ | 使用済みバスタオルは何枚ありましたか？ |

観察するものだけを答えさせる。解釈と判定はサーバーが行う。

### 15 秒で終わる
- 全項目に既定値をプリセット（客室タイプ×稼働予定から推定）。
- 既定値のままなら 1 タップで確定。
- 入力項目は最大 7 つ。
- 入力所要時間を計測して記録する（`inputDurationMs`）。

### 強制しない
- 観察記録は「今回は記録しない」を必ず用意する。理由も聞かない。
- ただしスキップしたこと自体は記録する。
- 未記録率が閾値を超えたら管理画面で警告する。

## 5. オフライン

iOS では Background Sync が使えず、Safari タブでは 7 日で storage が消える。

**MUST**
- IndexedDB は「1 勤務内の送信バッファ」として扱う。永続ストアにしない。
- flush トリガー: `online` イベント / `visibilitychange` / 未送信バーのタップ / 30 秒ポーリング / 完了操作直後。
- 直列送信。指数バックオフ 1s→2s→4s→8s→16s。5 回失敗で赤バッジ。
- 409（処理済）は成功扱いでキューから削除。
- 楽観的更新。完了を押したら即座に完了表示。サーバー拒否時は赤バッジで復帰。
- 24 時間以上未送信が残っていたら赤い警告。
- ホーム画面追加は推奨するが必須にしない。1 回閉じたら 30 日再表示しない。

## 6. 通知

**通知が届かなくても全業務が成立すること。**

- Web Push は iOS 16.4+ かつホーム画面追加済み PWA でのみ動作。
- 条件を満たさない場合は自動的に IN_APP へフォールバック。
- 3 回連続失敗した購読は無効化。
- `CLEANER` への通知は `task.rework_assigned` のみ。
- 静音時間 22:00-07:00（`issue.critical` のみ例外）。
- LINE には件名と 1 行要約＋リンクのみ。個人情報・差異の詳細を含めない。
