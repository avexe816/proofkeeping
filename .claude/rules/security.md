# セキュリティ・個人情報ルール

認証認可・写真・ログ・外部連携を触るときは必ずこれを読む。

## 1. ロールと権限

| ロール | 表示名 | スコープ |
|---|---|---|
| `OWNER` | オーナー | 組織全体 |
| `ORG_ADMIN` | 運営管理者 | 組織全体 |
| `PROPERTY_MANAGER` | 施設責任者 | 割当施設 |
| `INSPECTOR` | 検査担当 | 割当施設 |
| `CLEANER` | 清掃スタッフ | 割当施設 |
| `VENDOR_ADMIN` | 清掃会社管理者 | 受託施設 |
| `AUDITOR` | 監査閲覧 | 組織全体・読取専用 |

### 絶対に守る境界
- `CLEANER` は差異レポート（`/app/audit/*`、`/api/v1/findings`）に到達できない → **404**
- `INSPECTOR` も同上 → **404**
- `CLEANER` は忘れ物の保管場所・返却先を見られない
- `INSPECTOR` は請求情報を見られない
- `VENDOR_ADMIN` は受託外施設を見られない
- `AUDITOR` は書き込み操作を一切できない
- 清掃担当者本人は自分のタスクを検査できない（緊急時の例外は理由必須＋監査ログ）

### 実装
権限判定は必ずサーバー側。
```ts
assertPermission(ctx, "finding.read", { propertyId });
```
フロントでのメニュー非表示は UX 上の措置であり、権限制御とみなさない。

## 2. 認証

| 対象 | 方式 | 有効期限 |
|---|---|---|
| 管理系 | メール＋パスワード | 12 時間 |
| 清掃スタッフ | 施設コード＋スタッフ番号＋PIN 4 桁 | 16 時間（1 勤務） |

- Cookie: `pk_session`、`httpOnly`、`Secure`、`SameSite=Lax`
- セッション実体は Workers KV。Cookie には署名付き ID のみ。
- パスワード: 10 文字以上、英大小・数字。bcrypt cost 12。10 回失敗で 30 分ロック。
- PIN: bcrypt cost 10。5 回失敗で 15 分ロック。連番・ゾロ目を登録時に拒否。初回変更を強制。
- PIN リセットは管理者のみ。必ず監査ログ。

## 3. 保存してはいけないデータ

**宿泊者の氏名・連絡先・住所・パスポート情報・クレジットカード情報を一切保存しない。**

- 稼働照合には人数と予約参照番号（`reservationRef`）のみで足りる。
- 忘れ物の所有者情報も保存しない。連絡は PMS 側で行い、`ownerContactedAt` のみ記録。
- 同期ログの `rawSample` に個人情報が含まれる場合はマスキング。保持 7 日。

新しいテーブルを作るとき、上記に該当するカラムを追加しようとしたら**作業を止めて確認する**。

## 4. 写真

- 撮影は `input[type=file][accept=image/*][capture=environment]`。`getUserMedia()` を使わない。
- クライアントで長辺 1600px・JPEG q=0.7 にリサイズ。1 枚 500KB 以下。
- **EXIF GPS をクライアントとサーバーの両方で除去する。** 撮影時刻のみ保持。
- 人物が写る写真はアップロード前に警告し、原則撮り直しを促す。
- パスポート・身分証・カード・予約票・PC 画面の撮影を促す UI を作らない。
- 閲覧は 15 分有効の署名付き URL。
- R2 キー: `photos/{orgId}/{propertyId}/{businessDate}/{taskId}/{photoId}.jpg`
- 既定保持 6 か月。上位プランで 13 か月。削除 30 日前に管理者へ通知。

## 5. 従業員データ

清掃スタッフの作業時間・検査結果は雇用管理に関する個人情報にあたりうる。

**MUST**
- 利用目的を「清掃業務の進捗管理、品質確認、請求根拠、内部統制」と明示する。
- 本人が自分の記録を閲覧できる画面（M-11）を用意する。
- 個人ランキング・最速比較・自動評価を実装しない。
- 個人単位の指標は対象期間 20 タスク未満なら表示しない。
- スタッフ別入力率などを表示する画面には「評価には使用しません」と明記する。

## 6. 監査ログ

以下は必ず `recordAudit()` を呼ぶ。

- 組織設定・税務プロファイルの変更
- 施設・客室マスタの作成・更新・無効化
- ユーザーの招待・ロール変更・無効化・PIN リセット
- タスクの完了・検査合格・差戻し・一括承認
- 客室ステータスの手動上書き（理由必須）
- 観察記録の事後修正
- 差異レポートのステータス変更
- 帳票の発行・訂正・送付
- データエクスポート・証跡 ZIP 出力
- エンタイトルメントの変更
- ログイン失敗（5 回目のみ）

`before` / `after` にパスワードハッシュ・PIN ハッシュを含めない。マスクする。

## 7. 外部連携

- API キー・パスワードを DB に平文保存しない。Workers KV に暗号化して保管し `credentialRef` で参照。
- Webhook は HMAC-SHA256 署名を必須検証。失敗は 401。
- タイムスタンプが 5 分以上ずれていたら拒否（リプレイ対策）。
- 受信は 200 を即返し、処理は Queue へ。
- 公開 API キーは作成時に 1 回だけ全体表示。以後はハッシュのみ。再表示できる実装にしない。
