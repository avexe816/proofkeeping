🎯 なぜPMS連携を分岐点にしたか

機能の強弱で分けるのではなく、技術的な依存関係で分けています。

PMS連携なし → 稼働予定データがない → P4が動かない → 差異が出ない → オーナーに共有する内容がない PMS連携あり → 稼働予定データがある → P4が動く → 差異が出る → オーナー画面に意味が生まれる

人為的に機能を止めているのではなく、データがないと動かないという構造です。顧客に説明したときに納得が得られます。

🚫 Baseで削らなかったもの

清掃員モバイル16画面と清掃会社PC12画面はBaseでも全機能提供します。

削らない理由
Baseの記録品質が落ちるとPro移行後もP4が機能しない
清掃員は契約の当事者ではない。体験を課金で削る根拠がない
Base→Proで現場の操作が変わらず、再研修が不要になる
在留期限管理は雇用主の法令上の義務。制限すべきでない
❗ 多言語対応を上位プラン限定にすると、Baseの清掃員が日本語だけのアプリを使うことになります。利用者の93%は日本語を読みません。多言語は増値機能ではなく動作の前提条件です（INV-35）。

📐 画面上での差の見せ方

BaseでもProの存在を隠しません。ただし邪魔にならない方法で示します。

  • サイドバーの「稼働の差異」は薄く表示し、PROバッジを付ける（消さない）
  • KPI枠の1つを未設定カードにして、PMS連携の効果を説明する
  • 作業画面の中に広告を差し込まない
  • 清掃員モバイルには一切アップセルを表示しない
💡 サイドバーから項目を消すと「機能がない」と誤解され、問い合わせになります。薄く表示してPROバッジを付けるほうが、何が使えないかが正確に伝わります。

💴 移行の判断基準

以下のいずれかに該当したらProを提案します。

  • PMSを導入した／導入予定がある
  • 施設オーナーから清掃実施の証跡提出を求められた
  • 稼働記録と実態の乖離が疑われる事案が発生した
  • 施設数が8を超えた
