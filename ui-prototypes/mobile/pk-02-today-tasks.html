✅ 今回の変更（Q1採用）

カウンタを5段に拡張。「入室不可」を独立表示にした。DND や施錠で入れない部屋は、後から再訪する必要があるため、未着手と混ぜると当日の残量を読み違える。

💡 5段になっても横幅は足りています。数値18px・ラベル8.5pxで、iPhone SE（375px）でも折り返しません。区切り線を入れて視認性を確保しました。

🎯 この画面の設計意図

「施設を切り替える」概念を持たせない。清掃会社のスタッフは1日2〜3施設を回る。切替UIを置くと、切替を忘れて別施設のタスクを開始する誤操作が起きる。施設ごとにグループ化した単一リストにした。

施設間に移動ブロックを挟む。「14:30 →」で次の施設への移動時間を示す。現場は1日の動線として把握しているため、時間軸に沿った並びが自然。

再清掃を最上部＋期限カウントダウン。日本のホテルは15:00チェックインが多く、再清掃の見落としが直接READY遅延になる。並び順だけでなく「残り18分」を赤字で表示する。

📐 5段カウンタの定義

段状態意味
1未着手CREATED / ASSIGNED
2作業中IN_PROGRESS / PAUSED
3再清掃REWORK（差戻し中）
4入室不可BLOCKED（DND・施錠・在室）
5完了AWAITING_INSPECTION / COMPLETED
💡「検査待ち」は完了に含めます。清掃員から見れば自分の作業は終わっているためです。検査員の画面（14）では別枠で扱います。

📐 並び順の規則

#優先理由
1再清掃READY遅延に直結
2作業中中断からの復帰を最短に
3未着手（優先度順）当日IN予定の部屋が先
4入室不可後で再確認するもの
5完了確認用。自動で折りたたむ

📡 オフライン時の挙動

  • 最上部にオレンジの帯で「未送信 N件」を常時表示
  • 「送信する」をタップすると即座に再送を試行
  • タスク一覧は最後に取得した内容を表示し、取得時刻を明示
  • 送信キューは施設をまたいで1本。施設ごとに分けない
  • 24時間以上未送信が残ると帯が赤くなる
  • Background Sync は使わない。画面表示時・オンライン復帰時・手動タップ時に flush

✅ 確認結果

✅ Q1. カウンタ5段（入室不可を追加） — 確定 後から再訪が必要な部屋を独立表示。当日の残量を正確に把握できる。
✅ Q2. 完了タスクは薄く表示 — 確定 不透明度72%で「すべて」タブに残す。自分の作業履歴の確認に使える。
✅ Q3. 移動時間は管理者が入力 — 確定 シフト作成時に入力。未登録なら移動ブロックを出さない。地図API自動計算は初期版では行わない。
✅ Q4. DND再確認は固定文 — 確定 「15時以降に再確認」を既定。施設ごとの時刻設定は将来の拡張とする。
✅ Q5. チェックイン時刻を表示 — 確定 稼働記録がある場合のみ「🕒 15:00 IN」を表示。優先度判断に有効。
