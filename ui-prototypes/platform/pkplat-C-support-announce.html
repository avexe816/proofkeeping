🎯 質問の内容を設計の入力にする

💡 チケットの種別に「差異の解釈に関する質問」を独立して設けているのはこのためです。「その他の質問」に混ぜると傾向が見えません。

⏱ 初回応答を優先する

KPIに「初回応答の中央値42分」を置いています。解決までの時間より初回応答を重視します。

  • 不具合の解決には14.2時間かかる（調査が必要なため）
  • その間、相手は放置されていると感じる
  • 「確認しています」の一報が信頼を保つ
  • 目標は2時間以内

✅ 確定事項

  • 「差異の解釈に関する質問」を独立した種別にする
  • 質問の傾向をUI改善の入力として扱う
  • 定型文は設計方針と同じ表現を使う
  • 初回応答の目標を2時間以内とする
  • 例外を作ってはならない項目を定型文で固定する

🚫 実装しないと決めた理由

🚫
清掃員別の作業時間ランキング（要望6件） 速さの競争になり、記録の正確さより速さが優先されます。P4の入力品質が落ち、システム全体の価値が下がります。
🚫
差異の自動通報機能（要望3件） P4は確信度付きの示唆を出す仕組みであり、判定する仕組みではありません。誤検知率31.2%の状態で自動通報すれば、無関係な宿泊者が通報されます。
🚫
宿泊者のブラックリスト共有（要望2件） 差異は事実確認を経ていない示唆です。テナント間で共有すると、記録の不備が原因だった宿泊者が複数施設で不利益を受けます。
🚫
客室内カメラとの連携（要望1件） 宿泊者と清掃員の双方を監視する構造になります。本サービスは記録を残す仕組みであり、監視の仕組みではありません。
実装しない判断とその理由は記録に残し、同じ要望が再度上がった際に同じ回答ができる状態にします。

🎯 実装しない判断を記録として残す

この画面で最も重要なのは「実装しないと決めた要望」を7件として可視化していることです。却下した要望を消さずに理由とともに残します。

要望件数
清掃員別ランキング6
差異の自動通報3
ブラックリスト共有2
客室内カメラ連携1
❗ これらは要望として繰り返し上がります。担当者が変わったときに「便利そうだから作ろう」と判断されないよう、理由を記録に残します。特にランキングは要望6件と最多であり、断り続ける根拠が必要です。

🚫 断る理由を方針に紐づける

4つの却下理由はいずれも、設計原則に直接紐づいています。

  • ランキング → 「記録は評価に使わない」（PK-SPEC-UI 1.1）
  • 自動通報 → 「P4は判定しない」（PK-SPEC-P4 §14）
  • ブラックリスト → 「差異は事実確認を経ていない」
  • カメラ連携 → 「記録の仕組みであり監視の仕組みではない」

「できない」ではなく「しない」と書きます。技術的制約ではなく方針上の判断であることを明示します。

🌐 多言語の不具合は報告が遅れる

BG-809（ミャンマー語で文字が重なる）に注記を付けました。日本語では発生しないため報告が遅れたという事実です。

利用者の93%は日本語を読みません（03画面）。開発者が日本語で確認するだけでは、多数の利用者に影響する不具合を見逃します。

💡 対策として「全7言語での表示確認」をリリース前チェックに追加しています。これは第1批の受け入れ基準第6条と同じ項目です。

✅ 確定事項

  • 実装しない要望を削除せず理由とともに残す
  • 却下理由を設計原則に紐づけて記述する
  • 「できない」ではなく「しない」と書く
  • 多言語表示の確認をリリース前チェックに含める
  • 要望数を表示し、繰り返し上がるものを把握する

🎯 全言語完了まで配信しない

清掃員向けのお知らせは、7言語すべての翻訳が完了してから配信します。一部言語だけで配信すると、その言語以外の利用者に情報格差が生まれます。

下書きの例では3言語が未完了で、該当する利用者は474名います。配信を待つ判断を画面上で促します。

❗ 例外は障害告知など時間が優先される場合のみで、その場合も日本語＋英語で先行配信し、残りは翻訳完了後に追加配信します。「日本語だけで配信して後で翻訳」を常態にしません。

🌐 翻訳は現場確認を経る

翻訳状況テーブルの確認者欄に「現場確認済」と記載しています。機械翻訳のままでは業務用語が正しく伝わりません。

  • 中国語・ベトナム語は現場スタッフが確認済み
  • 確認者の名前を記録に残す
  • 用語の統一は用語集（PK-SPEC-UI 第7章）に従う

📖 既読率100%を目指さない

既読率78.2%を100%にしようとしません。既読を強制すると作業開始前に閉じるだけの操作が増え、実質的に読まれなくなります。

方針理由
既読を強制しない形式的な既読を防ぐ
個人別に集計しない既読率が評価指標になるのを防ぐ
月4件以内頻度を抑えて読まれる状態を保つ
1件2文まで手袋で操作する現場を想定

  • 緊急時のみ日本語＋英語で先行配信する
  • 翻訳は現場スタッフの確認を経る
  • 既読を強制する画面は作らない
