## 0. この文書の使い方

### 0.1 生成AIへの指示

この文書は**実装契約**です。設計の背景説明ではなく、守るべき条件の一覧です。

1. 第1章の不変条件（INV）は**いかなる理由でも破ってはならない**。「より良い実装」として変更してはならない
2. フィールド名は第2章の辞書に従う。別の名前を発明してはならない
3. 画面を追加・変更する場合は第3章のインベントリに沿う
4. UI文言は第5章の禁止語リストに違反してはならない
5. 第11章に、生成時にやりがちな逸脱をまとめている。**実装前に必ず読むこと**
6. 判断に迷う場合は実装せず、該当するINV番号を挙げて確認を求めること

### 0.2 用語の前提

| 用語 | 意味 |
|---|---|
| 清掃員 | 客室清掃を行う作業者。モバイルアプリの利用者 |
| オーナー | 施設の所有者・施設管理者。清掃会社の発注元 |
| 運営管理者 | 清掃会社の管理者。清掃員の雇用主側 |
| 現場責任者 | 清掃会社の現場リーダー |
| プラットフォーム運営 | ProofKeeping 提供者 |
| P4 | 稼働照合エンジン。記録と稼働予定を突き合わせ差異を検出する |
| 差異（finding） | P4が検出した「確認する価値がある事象」。判定ではない |
| 確信度（confidence） | 根拠の強さを0〜100で表した数値。確率ではない |

## 1. 不変条件（INV）

破った場合は実装の欠陥として扱う。設定項目として外部化してはならないものを含む。

### 1.1 記録の目的に関する不変条件

| ID | 条件 | 破った場合に起きること |
|---|---|---|
| **INV-01** | 記録を清掃員個人の評価に使う機能を実装しない | 清掃員が正確さより見た目を優先し、P4の入力品質が崩壊する |
| **INV-02** | 清掃員個人のランキング・順位・他者比較を表示しない | 同上。速さの競争になる |
| **INV-03** | 清掃員個人の作業時間平均・入力率・再清掃率を集計しない。集計単位は施設・客室タイプ・作業種別のみ | 個人別に分解された瞬間に評価指標になる |
| **INV-04** | バッジ・連続達成日数・目標達成率などのゲーミフィケーションを実装しない | 記録の目的がバッジ獲得に変わる |
| **INV-05** | 目安時間の超過に赤色を使わない。オレンジ→グレーとする | 赤は失敗を意味し、丁寧に作業する者を追い詰める |

### 1.2 個人情報に関する不変条件

| ID | 条件 |
|---|---|
| **INV-06** | オーナーの画面に清掃員の氏名を表示しない。空欄にせず「非表示」バッジを表示する |
| **INV-07** | オーナーの画面に清掃員の操作履歴を表示しない（勤務時間が間接的に判明するため） |
| **INV-08** | 在留資格の情報は運営管理者のみが閲覧できる。現場責任者・オーナー・プラットフォーム運営に公開しない |
| **INV-09** | 検査結果を入力するまで担当者名を表示しない（清掃会社の画面でも同様） |
| **INV-10** | プラットフォーム運営は清掃員の個人情報に既定でアクセスできない。一時アクセスは理由記録＋承認者2名＋最長4時間、アクセス記録は削除不可 |
| **INV-11** | 写真のEXIF位置情報は端末側で削除してからアップロードする。サーバーに保存しない |
| **INV-12** | 顔検出・顔認識を実装しない |

### 1.3 P4に関する不変条件

| ID | 条件 |
|---|---|
| **INV-13** | 単一シグナルのみで確信度50を超えてはならない。この上限は**コード上の定数**とし、設定項目として外部化しない |
| **INV-14** | 差異の説明文に断定的表現を使わない（第5章の禁止語に従う） |
| **INV-15** | 差異の自動通報機能を実装しない（警察・管理会社等への自動連絡） |
| **INV-16** | 宿泊者のブラックリスト機能・テナント間共有を実装しない |
| **INV-17** | 差異率0%を目標値・目標達成率として表示しない |
| **INV-18** | 確信度を「その差異が本当である確率」と説明しない |
| **INV-19** | 減点シグナルは0点であっても内訳に表示する |

### 1.4 清掃員の入力に関する不変条件

| ID | 条件 |
|---|---|
| **INV-20** | 清掃員に解釈・判断を求める設問を作らない。観察したことのみを問う（第5章の設問対照表に従う） |
| **INV-21** | 入室時の記録に「今回は記録しない」を常設する。スキップの理由を問わない |
| **INV-22** | チェックリストは3値入力（○／×／該当なし）とする。2値にしない |
| **INV-23** | 数値入力にキーボードを使わない。ステッパーまたは選択のみ |
| **INV-24** | 中断・入室不可の理由選択に「その他」を常設し、説明を求めない |
| **INV-25** | 最小タップ領域を48×48pxとする |
| **INV-26** | 詳細記録（アメニティ等）は全項目任意とする |

### 1.5 データの取り扱いに関する不変条件

| ID | 条件 |
|---|---|
| **INV-27** | 同期完了まで端末内のデータを削除しない |
| **INV-28** | 競合が発生しても清掃員の記録を削除しない。採用されなかった記録も `conflictLog` に保持する |
| **INV-29** | 再清掃時に元の清掃記録を削除しない。新規タスクとして作成する |
| **INV-30** | 監査ログ（`auditLog`）は削除できない実装とする |
| **INV-31** | 権限外の `propertyId` へのアクセスには **404** を返す。403 を返さない（資源の存在を示唆するため） |
| **INV-32** | クライアントから送信された `propertyId` を信用しない。`taskId` から解決し `allowedPropertyIds` で検証する |
| **INV-33** | 請求は記録から自動生成する。手入力での件数調整機能を実装しない |

### 1.6 課金に関する不変条件

| ID | 条件 |
|---|---|
| **INV-34** | 課金単位は客室数とする。記録件数・写真枚数・ストレージ容量で課金しない |
| **INV-35** | 多言語対応をプランで制限しない |
| **INV-36** | 記録の保存期間をプランで制限しない |
| **INV-37** | 再清掃を無償とする。件数は表示し金額は0とする |

## 2. データ辞書

フィールド名は以下に固定する。別名を発明してはならない。

### 2.1 タスク

| フィールド | 型 | 説明 |
|---|---|---|
| `taskId` | string | タスク識別子 |
| `propertyId` | string | 施設識別子。クライアント送信値は信用しない（INV-32） |
| `roomNumber` | string | 客室番号 |
| `taskType` | enum | `CHECKOUT_CLEAN` / `STAY_CLEAN` / `INSPECTION` / `REWORK` |
| `floor` | string | 階 |
| `roomType` | string | 客室タイプ |
| `standardMinutes` | int | 目安時間（分） |
| `status` | enum | `TODO` / `IN_PROGRESS` / `PAUSED` / `ON_HOLD` / `COMPLETED` / `REWORK_REQUIRED` |
| `startedAt` | timestamp | 開始時刻（サーバー時刻） |
| `completedAt` | timestamp | 完了時刻（サーバー時刻） |
| `actualMinutes` | int | 実作業時間。中断時間を除いた合計 |
| `pauseCount` | int | 中断回数 |

### 2.2 時間ログ

| フィールド | 型 | 説明 |
|---|---|---|
| `taskTimeLog` | array | 開始・中断・再開・完了のイベント列 |
| `taskTimeLog[].event` | enum | `START` / `PAUSE` / `RESUME` / `COMPLETE` |
| `taskTimeLog[].at` | timestamp | 発生時刻 |
| `taskTimeLog[].reasonCode` | string | 中断・入室不可の理由コード |

`actualMinutes` は `taskTimeLog` から算出する。中断を3回挟んでも正しく計算されることを必須テスト項目とする（PK-SPEC-P1 §14.1）。

### 2.3 入室時の記録

| フィールド | 型 | 説明 |
|---|---|---|
| `bedsUsed` | int | 使用ベッド数（0〜2） |
| `trashLevel` | enum | `NONE` / `LOW` / `NORMAL` / `HIGH` |
| `towelCounts` | object | `{bathTowel, faceTowel, bathMat}` |
| `amenityCounts` | object | 品目コードをキーとした数量 |
| `usedDefaults` | boolean | 既定値のまま確定した場合 true |
| `inputDurationMs` | int | 入力所要時間。受け入れ基準は中央値20秒以内 |
| `observationSkipped` | boolean | 「今回は記録しない」を選択した場合 true |

`observationSkipped = true` のタスクはP4の照合対象から除外する。
施設単位の `usedDefaults` 比率が90%を超える場合、該当する差異の確信度を20下げる。

### 2.4 チェックリスト

| フィールド | 型 | 説明 |
|---|---|---|
| `checklistItems[].itemId` | string | 項目識別子 |
| `checklistItems[].value` | enum | `DONE` / `COULD_NOT` / `NOT_APPLICABLE` |
| `checklistItems[].reasonCode` | string | `COULD_NOT` の場合の理由 |
| `checklistItems[].required` | boolean | 必須項目 |
| `checklistItems[].photoRequired` | boolean | 写真必須 |

進捗の分母は `NOT_APPLICABLE` を除いた件数。分子は `DONE` の件数。

### 2.5 写真

| フィールド | 型 | 説明 |
|---|---|---|
| `photos[].photoId` | string | 写真識別子 |
| `photos[].purpose` | enum | `AFTER_SHEET` / `AFTER_BATHTUB` / `FIXTURE_SHELF` / `ROOM_OVERVIEW` / `OTHER` |
| `photos[].capturedAt` | timestamp | サーバー時刻で上書き |
| `photos[].queuedAt` | timestamp | オフライン時のキュー投入時刻 |
| `photos[].sizeBytes` | int | 目標250KB以下 |

### 2.6 リネン

| フィールド | 型 | 説明 |
|---|---|---|
| `linenRecords[].itemCode` | string | 品目コード |
| `linenRecords[].collected` | int | 回収数 |
| `linenRecords[].restocked` | int | 補充数 |

差分は `restocked - collected` と定義する。UI上でも「補充 − 回収」と明記する。

### 2.7 品目コード

`SHEET` / `BATH_TOWEL` / `FACE_TOWEL` / `BATH_MAT` / `YUKATA` / `TOOTHBRUSH` / `RAZOR` / `SHAMPOO` / `SLIPPERS` / `BOTTLED_WATER` / `TEA_BAG`

施設ごとの有効化は `observationConfig.enabledItemCodes` で管理する。

### 2.8 差異

| フィールド | 型 | 説明 |
|---|---|---|
| `findingId` | string | 差異識別子 |
| `ruleId` | string | `R001`〜`R009` |
| `confidence` | int | 0〜100。単一シグナルでは50を超えない（INV-13） |
| `severity` | enum | `HIGH`（80〜）/ `MEDIUM`（50〜79）/ `LOW`（〜49） |
| `signals[]` | array | 寄与シグナルの内訳。減点も含む（INV-19） |
| `signals[].points` | int | 寄与点数。減点は負値 |
| `reviewResult` | enum | 第9章参照 |
| `reviewedBy` | string | 確認者 |

### 2.9 監査

| フィールド | 型 | 説明 |
|---|---|---|
| `auditLog[].actorId` | string | 操作者 |
| `auditLog[].action` | string | 操作種別 |
| `auditLog[].targetId` | string | 対象 |
| `auditLog[].before` | object | 修正前の値 |
| `auditLog[].after` | object | 修正後の値 |
| `auditLog[].at` | timestamp | 操作時刻 |
| `auditLog[].ip` | string | IPアドレス |

削除不可（INV-30）。保存期間5年。

### 2.10 権限

| フィールド | 型 | 説明 |
|---|---|---|
| `role` | enum | `CLEANER` / `SITE_LEAD` / `OPS_MANAGER` / `OWNER` / `VIEWER` / `PLATFORM_ADMIN` |
| `allowedPropertyIds` | array | アクセス可能な施設ID |

### 4.1 サーバー側検証の必須手順

```
1. リクエストの taskId から propertyId を解決する
2. propertyId が actor の allowedPropertyIds に含まれるか検証する
3. 含まれない場合は 404 を返す（403 ではない：INV-31）
4. クライアントから送られた propertyId は一切信用しない（INV-32）
```

### 4.2 再清掃依頼の経路

オーナーからの依頼は運営管理者を経由する。オーナーから清掃員へ直接届く経路を実装しない。

```
OWNER が依頼 → OPS_MANAGER が確認 → 清掃タスク作成 → 完了通知
```

## 5. 文言規則

### 5.1 禁止語と置換

自動検査可能。以下の語がUI文言に含まれてはならない。

| 禁止語 | 置換 |
|---|---|
| エラー | （状態を事実として述べる） |
| 失敗 / 失敗しました | （同上） |
| 保存に失敗しました | 端末に保存されています |
| 接続できません | オフラインで動作中 |
| 接続してください | 接続が戻ると自動で送信されます |
| 未送信のデータがあります | 送信待ちの記録 |
| 不審な点 | 気づいたこと |
| 異常 | 通常と違う点 |
| チェック（監視の意味） | 記録 |
| 報告義務 | 記録のお願い |
| 未実施の項目 | できなかった項目 |
| 不備あり | 記録された内容 |
| 無断宿泊 / 不正 | （使用しない） |
| 疑い | （使用しない） |

### 5.2 差異の説明文

| 使わない | 使う |
|---|---|

## 8. オフラインと同期

### 8.1 オフラインで動作する機能

| 機能 | オフライン |
|---|---|
| タスク一覧の閲覧 | ○ |
| タスクの開始・完了 | ○ |
| 入室時の記録 | ○ |
| 写真の撮影 | ○ |
| チェックリスト | ○ |
| リネン記録 | ○ |
| 当日タスクの再取得 | × |
| 他人の実績の閲覧 | × |

当日のタスクは朝の初回同期で全件取得する。1日分は数百KB程度。

### 8.2 同期の仕様

```
1. 記録は即座に IndexedDB へ暗号化保存
2. 接続検知で自動送信
3. 送信順：完了記録 → 入室時の記録 → 写真
4. 写真は1枚ずつ送信。失敗しても他は継続
5. 3回失敗した項目は指数バックオフで再試行
6. 同期完了まで端末内データを削除しない（INV-27）
7. 写真キューは1端末200枚上限。超過時は古い任意写真から削除、必須写真は保持
```

### 8.3 競合の解決

| 状況 | 解決 |
|---|---|
| 同一タスクを2端末で完了 | 先着を採用。後着は `conflictLog` に記録 |
| オフライン中に担当者変更 | 記録を保持。管理者に通知 |
| オフライン中にタスク削除 | 記録を保持。削除は取り消さない |
| 端末時刻のずれ | サーバー時刻で補正し差分をログに残す |

いずれの場合も清掃員の記録を削除しない（INV-28）。

## 9. P4ルールと確信度

### 9.1 ルール一覧

| ID | 内容 | 重要度 | 確信度上限 |
|---|---|---|---|
| R001 | 稼働記録なしの使用痕跡 | HIGH | 100 |
| R002 | 連泊中の未申告の追加利用 | MEDIUM | 79 |
| R003 | 宿泊人数の相違 | MEDIUM | 79 |
| R004 | 喫煙の痕跡 | MEDIUM | 79 |
| R005 | チェックアウト後の再使用 | MEDIUM | 79 |
| R006 | ペット同伴の痕跡 | LOW | 49 |
| R007 | 長時間の在室 | LOW | 49（**無効**） |
| R008 | アメニティ消費の異常 | LOW | 49 |
| R009 | リネン使用量の相違 | LOW | 49 |

R007 は無効。チェックアウト時刻の超過は清掃員の観察から判断できないため。

### 9.2 確信度の算出

| シグナル | 寄与 |
|---|---|
| 複数項目の一致 | 最大 +38 |
| 写真の記録あり（3枚以上） | +22 |
| 既定値からの変更あり（`usedDefaults = false`） | +18 |
| ベースラインからの乖離（2σ以上） | 最大 +14 |
| 入力所要時間が妥当（10〜60秒） | +8 |
| 前日の清掃記録が欠落 | **−25** |
| 施設の `usedDefaults` 比率が90%超 | **−20** |
| 単一シグナルのみ | **上限50**（INV-13） |

### 9.3 誤検知率の目標

| 重要度 | 目標 |
|---|---|
| HIGH | 10%以下 |
| MEDIUM | 30%以下 |
| LOW | 40%以下 |

### 9.4 確認結果の選択肢

```
FRONT_RECORD_ERROR    フロント記録と一致（記録の不備）
OPERATIONAL_USE       運用上の使用（スタッフ・業者）
DAY_USE_MISSING       デイユースの記録漏れ
WRONG_ROOM_NUMBER     客室番号の入力間違い
UNIDENTIFIED          原因を特定できなかった
POSSIBLE_VIOLATION    宿泊約款に関わる可能性がある
```

`POSSIBLE_VIOLATION` を選択してもシステムは何も実行しない。通報・通知・ブラックリスト等の副作用を持たせない（INV-15, INV-16）。

### 9.5 ベースラインの再学習

| 項目 | 値 |
|---|---|
| 学習対象期間 | 直近90日 |
| 学習単位 | 施設 × 客室タイプ |
| 最小サンプル数 | 30件（下回る場合は全社平均） |
| 実行頻度 | 週次（日曜 03:00） |
| 除外データ | `usedDefaults = true` の記録、差異と判定された記録 |

### 9.6 ルール変更の手続き

1. シャドー実行（差異を生成せず影響件数のみ算出。通知も送らない）
2. 採用基準：誤検知の削減が正しい検出の減少の**3倍以上**。HIGHは**5倍以上**
3. 承認者2名の承認
4. 却下の記録も理由とともに残す（削除不可）

**見逃しより誤検知を避ける。** 見逃しは気づかなかったで済むが、誤検知は宿泊者への誤った問い合わせを生み、回復できない。

## 11. 生成時のアンチパターン

コード生成AIが**善意で逸脱しやすい箇所**を列挙する。実装前に必ず確認すること。

### 11.1 「便利だから」追加してしまうもの

| やりがちな実装 | なぜ禁止か | 該当INV |
|---|---|---|
| 清掃員別の作業時間ランキング | 速さの競争になり記録の質が落ちる | INV-02 |
| 清掃員別の入力率・完備率 | 個人別に分解した瞬間に評価指標になる | INV-03 |
| 「今月の目標達成率」表示 | 未達が失敗に見える | INV-04 |
| 連続無遅刻バッジ | 休むことに罪悪感が出る | INV-04 |
| 既読を強制するお知らせ | 形式的な既読が増え実質読まれなくなる | — |
| 差異が出たら管理者へ自動通報 | P4は判定する仕組みではない | INV-15 |
| 宿泊者の要注意リスト | 差異は事実確認を経ていない | INV-16 |
| 顔にモザイクをかける機能 | 顔検出自体を実装しない | INV-12 |

### 11.2 色を「わかりやすく」してしまうもの

| やりがちな実装 | 正しい実装 |
|---|---|
| 目安時間の超過を赤で表示 | オレンジ→グレー。赤を使わない（INV-05） |
| リネン差分を赤で警告 | オレンジ。かつ「問題ではありません」を併記 |
| オフラインを赤で表示 | オレンジ。異常ではなく正常な一状態 |
| 保留（入室不可）を赤で表示 | 青。清掃の遅れではない |
| 完備率が100%未満を赤で表示 | 色を変えない。100%は目標ではない |

### 11.3 文言を「自然に」してしまうもの

| やりがちな実装 | 正しい実装 |
|---|---|
| 「保存に失敗しました」 | 「端末に保存されています」 |
| 「エラーが発生しました」 | 状態を事実として述べる |
| 「未実施の項目が1件あります」 | 「できなかった項目（1件）」 |
| 「無断宿泊の可能性があります」 | 「空室予定でしたが、使用痕跡が記録されています」 |
| 「対策が必要です」 | 「見直しをご検討いただけます」 |
| 「品質が改善しました」 | 「前月比0.3pt減少しました」 |

### 11.4 設定項目にしてしまうもの

以下は**コード上の定数**として実装する。設定画面・環境変数・DBの設定テーブルに置いてはならない。

- 単一シグナルの確信度上限50（INV-13）
- オーナーへの氏名開示（不可）（INV-06）
- 個人別ランキングの有効化（実装なし）（INV-02）
- 差異の自動通報（実装なし）（INV-15）
- ブラックリスト共有（実装なし）（INV-16）
- 顔検出（実装なし）（INV-12）
- 写真のEXIF位置情報の保存（不可）（INV-11）
- `auditLog` の削除（不可）（INV-30）

設定可能にすると、運用中の判断でいずれ変更されます。変更にリリースを必要とする状態を維持してください。

### 11.5 権限を「管理職だから」広げてしまうもの

| やりがちな実装 | 正しい実装 |
|---|---|
| 現場責任者が在留資格を閲覧できる | 運営管理者のみ（INV-08） |
| オーナーが清掃員名を閲覧できる | 表示しない（INV-06） |
| プラットフォーム運営が全データを閲覧できる | 既定でマスク。一時アクセスは承認2名（INV-10） |
| 管理者が清掃員の操作履歴を閲覧できる | 表示しない（INV-07） |

権限は「役職の高さ」ではなく「業務に必要か」で決めます。

### 11.6 エラー処理で壊してしまうもの

| やりがちな実装 | 正しい実装 |
|---|---|
| 権限外アクセスに403を返す | 404を返す（INV-31） |
| 同期失敗時に端末内データを削除 | 同期完了まで保持（INV-27） |
| 競合時に後着を破棄 | `conflictLog` に保持（INV-28） |
| 再清掃時に元記録を上書き | 新規タスクとして作成（INV-29） |
| バリデーション失敗を「エラー」と表示 | 何が足りないかを事実として述べる |

### 11.7 効率化で壊してしまうもの

| やりがちな実装 | 正しい実装 |
|---|---|
| 入室時の記録を必須にする | 「今回は記録しない」を常設（INV-21） |
