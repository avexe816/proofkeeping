# 管理者マニュアル

**版**: v1.0（2026-08-15）
**対象**: オーナー / 運営管理者 / 施設責任者 / 清掃会社管理者 / 監査閲覧
**前提**: 初期設定が済んでいること（`getting-started.md`）

ProofKeeping の全機能を、**画面・API・見える範囲**の 3 つで説明します。
「準備中」と書いた機能は、実体はあるが管理画面からの導線がまだ無いものです。
その場合の代替手段（API）を併記しています。

---

## 1. ログインとセッション

### 1.1 3 つの入力

| 入力 | 桁 | 備考 |
|---|---|---|
| 組織 ID | 6 桁 | 組織ごとに固定。全ユーザー共通 |
| スタッフ番号 | 組織内で一意 | 変更できません |
| パスワード / PIN | 10 文字以上 / 4 桁 | 管理系はパスワード、現場系は PIN |

**メールアドレスではログインしません。**
メールは通知の宛先としてのみ保持します。

| 対象 | 方式 | 有効期限 |
|---|---|---|
| 管理系（オーナー / 運営管理者 / 施設責任者 / 清掃会社管理者 / 監査閲覧） | パスワード | 12 時間 |
| 現場系（検査担当 / 清掃スタッフ） | PIN 4 桁 | 16 時間（1 勤務） |

### 1.2 ロックとリセット

- パスワードは 10 回失敗で 30 分ロック、PIN は 5 回失敗で 15 分ロックします。
- **失敗の理由は画面に出しません。** 番号が存在しない・情報が違う・
  ロック中の区別がつく応答を返さない設計です。
- PIN のリセットは管理者のみ。**必ず記録が残ります。**

### 1.3 権限の反映

ロールの変更・担当施設の解除は**次のリクエストから効きます。**
ログインし直す必要はありません（セッションに焼き込んでいないため）。

## 2. 見える範囲（ロール）

| ロール | 範囲 | 差異レポート | 請求 | 忘れ物の保管先 | 書き込み |
|---|---|---|---|---|---|
| オーナー | 組織全体 | ○ | ○ | ○ | ○ |
| 運営管理者 | 組織全体 | ○ | ○ | ○ | ○ |
| 施設責任者 | 割当施設 | ○ | — | ○ | ○ |
| 検査担当 | 割当施設 | **到達しません** | — | — | 検査のみ |
| 清掃スタッフ | 割当施設 | **到達しません** | — | **見られません** | 自分の記録のみ |
| 清掃会社管理者 | 受託施設 | ○ | 受託分 | ○ | ○ |
| 監査閲覧 | 組織全体 | ○ | ○ | ○ | **一切できません** |

> **「到達しません」はメニューに出ないという意味ではありません。**
> URL を直接開いても、その画面と API は存在しないものとして応答します。
> 「権限がありません」という応答も返しません（存在を示唆するため）。

## 3. 施設・客室のマスタ

| 対象 | 画面 | できること |
|---|---|---|
| 客室 | `/app/settings/rooms` | 一覧・作成・CSV 一括登録・無効化 |
| 客室タイプ | `/app/settings/room-types` | 作成・更新・無効化 |
| チェックリスト | `/app/settings/checklists` | 客室タイプ別のテンプレート |
| 標準時間 | `/app/settings/standard-times` | 客室タイプ × 作業種別の目安 |
| 観察項目 | `/app/settings/observation` | 現場に聞く項目の増減 |
| 消耗の基準値 | `/app/settings/baseline` | 学習結果の確認と上書き |
| ルール設定 | `/app/settings/rules` | 差異ルールの有効・重要度・閾値 |
| 事業者の税務情報 | `/app/settings/tax-profile` | 登録番号・端数処理 |
| 取引先と料金 | `/app/settings/counterparties` | 請求先と単価 |
| 連携設定 | `/app/settings/integrations` | 外部連携と同期ログ |

### 3.1 CSV 一括登録の作法

```csv
room_number,room_type_code,floor_name
301,DBL,3F
```

- `room_number` が無い行、列が足りない行は取り込まず、**件数を画面に出します。**
- 未知の `room_type_code` は**コードを画面に一覧で出します。** 黙って捨てません。
- 何度取り込んでも重複しません。

### 3.2 客室の無効化

清掃タスクが残っている客室は無効化できません。
先にタスクを片づけてください。**過去の記録は無効化後も残ります。**

## 4. 日々の運用

### 4.1 タスクの生成と配分

```
客室状況（/app/p/{施設}/plan）
   ↓ 自動生成（1 日 1 回 + 手動実行）
清掃タスク
   ↓ 配分（/app/p/{施設}/tasks）
担当者ごとの「本日のタスク」
```

- **自動生成は何度実行しても増えません。** 同じ業務日・同じ客室・
  同じ作業種別のタスクは 1 件に収束します。
- 配分は施設責任者が行います。盤面を見られること（`property.read`）と
  配れること（`task.manage`）は別の権限です。

### 4.2 客室ボード

`/app/p/{施設}/board`。客室の現在の状態がリアルタイムで並びます。
PC とモバイル（M-10）で**同じ並び順**です。

状態を手動で上書きするときは**理由が必須**で、記録が残ります。
清掃スタッフは上書きできません。

### 4.3 検査と再清掃

- 同じ部屋を 2 人が同時に検査することはできません（先に開始した人が担当）。
- **検査項目の初期値はすべて未選択**です。「全て合格」ボタンはありません。
- 不合格の項目だけが現場の再清掃画面に出ます。
- 清掃担当者本人は自分のタスクを検査できません。
  やむを得ない場合は理由の入力が必要で、記録が残ります。

### 4.4 忘れ物・不具合の報告

現場からの報告は `/m/report` で受け付けます。

**忘れ物の所有者情報は保存しません。** 連絡は PMS 側で行い、
ProofKeeping には「連絡した時刻」だけを記録します。
保管場所・返却先は**清掃スタッフには表示されません。**

## 5. 記録の確認（証跡）

| 画面 | 内容 |
|---|---|
| `/app/p/{施設}/evidence` | 業務日ごとのタスク一覧 |
| `/app/p/{施設}/evidence/{タスク}` | 1 タスクの記録すべて |

証跡には、開始・完了の時刻、チェックリストの 3 値、写真、観察記録、
検査結果、再清掃の履歴が入ります。

- 証跡は**追記のみ**です。訂正は新しい記録の追加で行い、元の記録は残ります。
- ZIP での持ち出しは別の権限（`evidence.export`）です。実行は記録に残ります。
- ハッシュによる改変の検証ができます（`GET /api/v1/tasks/{id}/evidence/verify`）。

---

## 6. 写真

- 撮影はブラウザのファイル選択（カメラ起動）で行います。
- **位置情報（EXIF GPS）は端末側とサーバー側の両方で除去します。**
  残るのは撮影時刻だけです。
- 長辺 1600px・500KB 以下に縮小して送ります。
- 閲覧は 15 分だけ有効な URL で行います。URL を貼り付けて共有しないでください。
- 保持期間は既定 6 か月、上位プランで 13 か月です。
  **削除の 30 日前に管理者へ通知します。**
- 期間を延ばした場合、短くする方向には戻せません
  （版数の既定が下限になります）。

## 7. 差異レポート（Audit モジュール）

**有効化の前に `finding-report-reading.md` を必ずお読みください。**
有効化のときに、その内容への同意を求めます。

| 画面 | 内容 |
|---|---|
| `/app/audit/findings` | 一覧。施設・状態・対象月で絞り込み |
| `/app/audit/findings/{id}` | 詳細。3 系統の記録と参考情報 |

### 7.1 状態

未対応 → 確認中 → 対応済 / 対象外。
ほかに「抑制」（点検の登録・自社利用・販売停止など、あらかじめ説明がつくもの）
があり、件数だけを表示します。

### 7.2 調整

`/app/settings/rules` で、施設ごとに次を変更できます。

- ルールの有効・無効
- 重要度の引き下げ（高 → 中 → 低。1 段階ずつ）
- 閾値

ルールの条件そのものは変更できません。
**未実装のルールも一覧に出します。** 隠すと「設定したのに何も起きない」
理由が画面から読めなくなるためです。

### 7.3 やらないこと

- 個人ランキング・最速比較・自動評価の画面はありません。
- 個人単位の指標は、対象期間 20 タスク未満なら表示しません。
- 差異に清掃担当者名を主語にした文言は出しません。

## 8. データ品質

`/app/p/{施設}/data-quality`。施設と月で見ます。

| 指標 | 見かた |
|---|---|
| 観察記録の入力率 | 低いと差異レポートの精度が落ちます |
| 「今回は記録しない」の割合 | 急に上がったら現場に事情を聞いてください |
| 基準値の信頼度 | `isReliable` になるまで消耗系のルールは弱く働きます |

**スタッフ別の入力率を評価に使わないでください。**
画面にもその旨を明記しています。

## 9. 請求と領収

### 9.1 流れ

```
月次締め → 請求書の下書き → 確定（採番）→ PDF 生成 → 送付 → 領収書
```

| 操作 | 現在の入口 |
|---|---|
| 取引先・料金の設定 | 画面 `/app/settings/counterparties` |
| 事業者の税務情報 | 画面 `/app/settings/tax-profile` |
| 締め・請求書・領収書 | **API**（`/api/v1/billing-periods`, `/api/v1/invoices`, `/api/v1/receipts`）。専用画面は準備中 |
| 受託の収支 | 画面 `/app/org/vendor-plan` |

### 9.2 決まりごと

- 番号は `INV-{西暦}-{連番4桁}` / `RCP-{西暦}-{連番4桁}`。
  **一度使った番号は再利用しません。** 取消しても欠番のまま残します。
- **発行済みの帳票は削除も上書きもできません。**
  訂正はマイナス伝票（赤伝）と再発行で行います。
- 金額はすべて整数（円）です。端数処理は**税率ごとに 1 回だけ**行います。
  明細行ごとには行いません。
- 電子的に発行する領収書に**収入印紙は不要**です。5 万円超でも同じです。
- 料金設定が見つからないタスクは**単価 0 円の明細として計上**し、
  画面に警告を出します。黙って除外しません。

### 9.3 電子帳簿保存法

ProofKeeping は「訂正・削除の履歴が残るシステム」方式です。
**外部タイムスタンプは使いません。** そのため次を守っています。

- 発行済み帳票を物理削除しない（API と DB の両方で禁止）
- 元の PDF を残し、閲覧可能なまま維持する
- 取引年月日・取引金額・取引先の 3 項目で検索できる

## 10. 外部連携

| 種類 | 内容 |
|---|---|
| CSV 取込 | 稼働記録。常時利用できます |
| 公開 API | 稼働記録の投入と、タスク・差異の読み取り（`docs/PK-API.md`） |
| 送信 Webhook | 自社システムへの通知。HMAC-SHA256 で署名します |
| PMS 連携 | 個別対応 |

- API キーは**作成時に 1 回だけ全体を表示します。** 再表示はできません。
  紛失した場合は作り直してください。
- 受信 Webhook は署名を必ず検証します。
  時刻が 5 分以上ずれているものは受け付けません。
- 同期ログは `/app/settings/integrations` の下に出ます。保持は 7 日です。

## 11. アーカイブと保持

| 対象 | 既定 | 備考 |
|---|---|---|
| 写真 | 6 か月（上位 13 か月） | 削除 30 日前に通知 |
| 業務データ | 年次で退避 | **削除ではありません** |
| 同期ログ | 7 日 | 個人情報はマスクします |

退避したデータは `/app/archive` から復元して閲覧できます。

- 1 回の復元は最大 3 か月分、組織あたり同時 1 件です。
- 復元した写しは **7 日間**閲覧できます。
- 期限が来ると写しが消えます。**退避した元データは残っています。**
  もう一度復元できます。

## 12. 記録に残る操作（監査ログ）

次の操作は、誰が・いつ・何を変えたかが残ります。

- 組織設定・税務情報の変更
- 施設・客室マスタの作成・更新・無効化
- ユーザーの招待・ロール変更・無効化・PIN リセット
- タスクの完了・検査合格・差戻し・一括承認
- 客室ステータスの手動上書き（**理由が必須**）
- 観察記録の事後修正
- 差異レポートの状態変更
- 帳票の発行・訂正・送付
- データエクスポート・証跡 ZIP 出力
- 契約モジュールの変更
- ログインの失敗（5 回目のみ）

**パスワードと PIN は、変更前後のどちらもマスクして記録します。**

## 13. オフラインと通知

### 13.1 オフライン

現場画面は電波が無くても操作できます。
未送信は端末に貯まり、復帰時・画面復帰時・完了操作の直後などに自動送信します。

- **24 時間以上送信できていない記録があると、赤い警告が出ます。**
  その端末でブラウザを開き直してください。
- サーバー側で処理済みだった記録は成功として扱い、二重登録しません。

### 13.2 通知

**通知が届かなくても、すべての業務は成立します。**

- 22:00–07:00 は送りません（緊急の不具合のみ例外）。
- 清掃スタッフに送るのは再清掃の割当だけです。
- 外部のメッセージには件名と 1 行の要約、リンクだけを載せます。
  差異の詳細や個人情報は含めません。

---

## 14. 保存しないもの

**宿泊者の氏名・連絡先・住所・パスポート情報・カード情報を一切保存しません。**

稼働照合に使うのは**人数と予約参照番号**だけです。
忘れ物の所有者情報も保存しません。

これらの列を含む CSV や API リクエストを送らないでください。
受け取る口がありません。

---

## 15. 困ったとき

| 症状 | 最初に見るところ |
|---|---|
| タスクが出ない | 担当施設の割当、客室状況の登録 |
| 現場が「送れない」と言う | 画面上部の未送信バー。24 時間超なら赤 |
| 差異が大量に出る | 基準値の学習状況、ルールの閾値 |
| 請求に部屋が載らない | 料金設定（単価 0 円の警告が出ていないか） |
| PDF が出ない | 生成は順番待ちです。数分待って再読込 |

解決しない場合は、**施設名・業務日・部屋番号・操作した時刻**を添えて
お問い合わせください。

- よくある質問: `docs/guides/faq.md`
- 差異レポートの読み方: `docs/guides/finding-report-reading.md`
- 公開 API: `docs/PK-API.md`
