# はじめかたガイド

**版**: v1.0（2026-08-15）
**対象**: オーナー / 運営管理者
**所要**: 初期設定 30〜60 分（100 室・スタッフ 30 名の場合）

申込みから、現場が初日の清掃を記録し終えるまでの手順です。
**上から順に進めれば終わります。** 途中で止めても、続きから再開できます。

---

## 0. 全体の流れ

```
 ① 申込み ─── 組織が作られ、ログイン情報が届く          （当社）
 ② 施設と客室を登録する                                 30 分
 ③ チェックリストと標準時間を決める                     15 分
 ④ スタッフを登録する                                   15 分
 ⑤ 稼働記録の入れ方を決める                             15 分〜
 ⑥ 現場の準備（端末・貼り紙）                           30 分
 ⑦ 初日を回す
```

**②〜④ が終われば清掃タスクは回せます。** ⑤ は稼働照合（Audit）を
使う場合に必要で、後から足しても構いません。

---

## 1. 申込み（当社が行います）

申込み後、当社が組織を作成し、次の 3 つをお伝えします。

| 項目 | 例 | 使いみち |
|---|---|---|
| 組織 ID | `o7k2m9` | 全員が毎回ログインで入力する 6 桁 |
| スタッフ番号 | `0001` | 最初のオーナーの番号 |
| 初期パスワード | （別便） | 初回ログイン後に変更してください |

**ログインは 3 つの入力で固定です。**
メールアドレスではログインしません（メールは通知の宛先としてのみ使います）。

> セットアップウィザードは提供準備中です。現時点では、組織の作成と
> 最初のオーナーの登録は当社側で行います。②以降はお客様側で操作できます。

管理画面 `/app/*` は PC のブラウザ、現場画面 `/m/*` はスマートフォンで開きます。

---

## 2. 施設と客室を登録する

### 2.1 施設

施設ごとに次を決めます。**あとから変更できますが、日締め時刻だけは
変更すると過去の集計の区切りが変わる**ので、最初に決めてください。

| 項目 | 既定 | 補足 |
|---|---|---|
| 施設名 | — | 現場の呼び方に合わせてください |
| タイムゾーン | `Asia/Tokyo` | 組織の設定を引き継ぎます |
| 日締め時刻 | `05:00` | この時刻より前の作業は前日の業務日として集計します |

**日次の集計はすべて「業務日」で行います。**カレンダー日ではありません。
深夜 2 時に終わった清掃は、既定では前日の実績になります。

### 2.2 客室タイプ

**客室より先に客室タイプを作ってください。** 標準時間・チェックリスト・
消耗の基準値は、すべて客室タイプに紐づきます。

`/app/settings/room-types` で、コードと名称を登録します。
コードは CSV 取込で使うので、短く安定した文字列にしてください（例: `DBL`）。

### 2.3 客室（CSV で一括登録）

`/app/settings/rooms` の CSV 取込を使います。100 室でも数分で終わります。

```csv
room_number,room_type_code,floor_name
301,DBL,3F
302,DBL,3F
303,TWN,3F
```

- `room_number` が空の行は取り込みません（件数を画面に出します）。
- `room_type_code` がマスタに無い場合、**そのコードを画面に一覧で出します。**
  黙って捨てません。客室タイプを足してから、もう一度取り込んでください。
- 同じ CSV を 2 回取り込んでも部屋は重複しません。

## 3. チェックリストと標準時間

### 3.1 チェックリスト（`/app/settings/checklists`）

客室タイプごとに、清掃スタッフが記録する項目を決めます。

**MUST に指定した項目は、埋まるまで「完了する」が押せません。**
最初は少なめ（10〜15 項目）から始めることをおすすめします。
現場が「とりあえず全部つける」動きに入ると、記録の価値が下がります。

記録は 3 値（済 / 対象外 / 未）です。「すべてチェック」ボタンはありません。

### 3.2 標準時間（`/app/settings/standard-times`）

客室タイプ × 作業種別ごとの目安時間です。
**超過しても現場の画面は赤くなりません。**オレンジとグレーまでです。
急かすための数字ではなく、配分と請求の根拠に使います。

---

## 4. スタッフを登録する

ロールは 7 種類です。**必要な範囲だけを渡してください。**

| ロール | 見える範囲 | 主な用途 |
|---|---|---|
| オーナー | 組織全体 | 契約・設定・すべての記録 |
| 運営管理者 | 組織全体 | 日々の管理 |
| 施設責任者 | 割当施設 | 配分・盤面・検査の管理 |
| 検査担当 | 割当施設 | 検査と再清掃の指示 |
| 清掃スタッフ | 割当施設 | 自分のタスクと記録 |
| 清掃会社管理者 | 受託施設 | 受託分の実績と収支 |
| 監査閲覧 | 組織全体・**読取専用** | 監査・確認 |

- 現場系（清掃スタッフ / 検査担当）は **4 桁の PIN** でログインします。
  有効期限は 16 時間（1 勤務）です。
- 管理系は**パスワード**（10 文字以上・英大小・数字）で、有効期限は 12 時間です。
- PIN は**初回ログイン時に必ず変更**します。連番・ゾロ目は登録できません。
- PIN を忘れた場合のリセットは管理者だけが行えます。記録が残ります。

> **担当施設の割当を忘れないでください。** 施設スコープのロールは、
> 割当が無いとタスクが 1 件も表示されません。

## 5. 稼働記録の入れ方を決める

稼働照合（Audit）を使う場合のみ必要です。3 つの入れ方があります。

| 方法 | 向いている場合 | 参照 |
|---|---|---|
| CSV 取込 | まず試したい / PMS に API が無い | 下記 5.1 |
| 公開 API | 自社システムから毎日入れたい | `docs/PK-API.md` |
| PMS 連携 | 対応 PMS を使っている | 個別にご相談ください |

**どれも入れないままでも清掃タスクは回ります。**
その場合、差異レポートは「稼働記録なしの清掃発生」だけが立ちます。

### 5.1 CSV の形

```csv
room_number,business_date,is_occupied,guest_count,reservation_ref,check_in_at,check_out_at,is_stayover,night_index,nights_total,is_house_use
302,2026-09-09,true,2,RSV-0012,,,false,,,false
```

**宿泊者の氏名・連絡先・パスポート番号の列はありません。**
ProofKeeping はこれらを保存しません。稼働照合には**人数と予約参照番号**で足ります。
これらの列を含む CSV を作らないでください。

## 6. 現場の準備

1. **端末**。清掃スタッフのスマートフォン、または共用端末を用意します。
   ブラウザで `/m/` を開き、ホーム画面に追加すると起動が速くなります
   （必須ではありません）。
2. **貼り紙**。`docs/guides/cleaner-guide.html` を印刷して休憩室に貼ってください。
   **A4 1 枚・日本語と英語**です。
3. **説明**。記録の使いみちを、初日の前に口頭で伝えてください。
   何を伝えるかは `docs/guides/finding-report-reading.md` §7 にあります。
4. **電波**。客室内は電波が届かないことがあります。
   オフラインでも操作でき、復帰時に自動で送信されます。
   画面の上に「オフライン・N 件未送信」と出ている間も、作業は続けられます。

## 7. 初日の流れ

```
前日夜 or 当日朝   タスクが自動生成される（客室状況から）
   ↓
朝                施設責任者が /app/p/{施設}/tasks で担当を配る
   ↓
現場              清掃スタッフが /m/ でログイン → 本日のタスク
                    → 開始 → 入室時の記録 → チェックリスト
                    → 写真 → リネン枚数 → 完了
   ↓
検査              検査担当が /m/inspections から検査
                    → 合格 or 再清掃（不合格項目だけが現場に出ます）
   ↓
夜                日報が自動生成される
```

**初日は「完了まで通ること」だけを確認してください。**
記録の粒度や閾値の調整は、2 週目以降で構いません。

## 8. 運用開始後のチェックポイント

| 時期 | 見るところ | 判断 |
|---|---|---|
| 1 週間後 | `/app/p/{施設}/data-quality` | 観察記録の入力率が 80% を超えているか |
| 2 週間後 | 同上 | 紙の記録を止められるか |
| 4 週間後 | 消耗の基準値 | `isReliable` になった客室タイプが増えているか |
| 4 週間後以降 | 差異レポート | ここで初めて Audit を有効化することをおすすめします |

**稼働照合は、記録が溜まる前に有効化しても意味のある結果を出しません。**
基準値の学習が終わっていない状態では、差異のほとんどが「基準値のずれ」です。
