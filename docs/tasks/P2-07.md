  - 28 テスト（正例 7 / 負例 5 / 表の走査 3 / 絞り 8 / 免除 5）。

**DB**
- `rework_cycle.waived_issue_id` を追加（migration 0008）。§3.4 に列が無い
  ので足した。**DECISIONS #071。**
- `findReworkCycleById()` / `findOpenReworkCycleByTask()` / `advanceReworkCycle()`。
  更新は `status = from` の行にだけ当たる（楽観的排他）。**削除しない。**
- 監査: `rework.resolved` / `rework.waived`（**理由必須**）。

**contracts**
- `packages/contracts/src/rework.ts`。**合格した項目を返す口を作っていない**
  （§4.6 を型の側でも満たす）。検査者の ID も返さない（§1.2）。

**API**
- `GET /api/v1/reworks/:id` / `POST .../start` / `.../complete` / `.../waive`。
  **一覧の口は作っていない**（担当者ごとの差戻し件数を並べる画面へ育つ余地を
  作らない / §1.3）。差戻しはタスクから辿る。
- 開始・完了はタスク側の遷移（`runTransition()`）を**先に**動かし、
  そのあと差戻しを 1 段進める。順序を逆にすると、拒否される操作で
  差戻しだけが進む。
- **免除はタスクの状態を動かさない。** 客室だけを READY / BLOCKED へ。
  `COMPLETED` へ動かすと §10.1 の合格率が実態と合わなくなる。

**権限**
- `rework.read` / `rework.write` / `rework.waive` を追加。
  `rework.read` と `rework.write` は **`CLEANER` を許す唯一の検査系アクション。**
  「自分の差戻しか」は `assertReworkVisible()` が別に絞る（他人のものは 404）。
  免除は §4.7 の「PROPERTY_MANAGER 以上」で `VENDOR_ADMIN` は DENY。

**画面**
- M-12 `/m/task/:taskId/rework`。**`taskId` で開く**（清掃者は差戻しの ID を
  知らない）。§11.4 のワイヤーどおり、差し戻された項目・理由コード・指示・
  検査写真を並べ、操作は「開始」「写真」「完了」の 3 つだけ。
- M-02 の `REWORK` のカードから入る（§4.5 の「M-02 上部へ優先表示」の受け側）。
- 文言は ja / en 両方に 21 キー。
