#### 決めたこと

- **読み取り専用は middleware 1 か所**（DECISIONS #182）。書き込み経路は
  API だけで 38 本あり、経路ごとに `if` を撒くと必ず漏れる。
  トライアルの期限は**組織全体の状態**で、資源によって答えが変わらない。
- **優先度 1（§5.2）の 4 操作だけ通す**（#183）。402 は 4xx で、
  オフラインキューが `GIVE_UP` にする。**夜中に期限が切れると、その勤務で
  記録した完了が捨てられる。** §5.2 の「何があっても維持する」を優先した。
  §2.5 の字面との差は OPEN_QUESTIONS #104。
- **超える取込はまとめて拒む。** 先頭 150 室だけ入れると、どの行が入ったかを
  利用者が追えない。
- **期限が無いトライアルは `ACTIVE`。** 設定漏れで即座に読み取り専用に
  ならないよう、迷ったら止めない側へ倒した。
- **消す関数を置いていない。** §2.5 MUST は「即削除しない」。
  90 日が過ぎたら消す仕組みはまだどの task にも無く、
  `retentionEndsAt()` は期限を計算するだけ（＝現状は保持され続ける）。

#### 積み残し

- **施設 3 件の上限は掛けようが無い。** 施設を作る経路（画面も API も）が
  存在しない（OPEN_QUESTIONS #103）。`remainingProperties()` は用意してある。
- **画面（react-router の `action`）には読み取り専用が掛かっていない。**
  掛けるなら `requireAppContext()` が同じ役目を果たせる。
- テストで `deps` を渡す経路では契約を引かない（#182）。本番の判定は変わらない。
