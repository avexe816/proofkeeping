## 作業ログ

### 2026-08-12 — 完了

**やったこと**

- 生成ルール（§3.1）と差分生成（§3.3）を `packages/engine/src/taskGeneration.ts` に
  **純粋関数**として置いた。DB・時刻・環境変数を持ち込まない。
- 実行は `apps/web/src/lib/task/generate.ts`（計画を読んで書くだけ）。
- 手動再生成: `POST /api/v1/tasks/generate`（§3.2）。
- **Cron Trigger を 1 本追加**（`wrangler.toml` の `[triggers] crons = ["0 17 * * *"]`）。
  02:00 Asia/Tokyo = 17:00 UTC。ハンドラは `apps/web/src/index.ts` の `scheduled()`、
  実体は `apps/web/src/lib/task/nightly.ts`。**無料枠 5 本のうち 1 本目。**

**完了条件**

- [x] 100 室分が 5 秒以内に生成される
      → 計画の組み立ては 100 室で検証済み（`taskGeneration.spec.ts`）。
        **D1 への書き込み時間は実測していない**（P0-02 待ち / PROGRESS の申し送り 7）。
- [x] 3 回連続実行しても重複しない
      → 3 段構え。①`planGeneration()` が着手済みを外す ②UPDATE の条件に `status`
        ③一意制約 + `onConflictDoNothing()`。**どれか 1 つでは足りない。**
- [x] 着手済みタスクが再生成で書き換わらない
      → `UNTOUCHABLE_STATUSES`。5 状態それぞれをテストで押さえた。
- [x] 計画から消えた未着手タスクが取消される
      → `cancelPlannedTasks()`。**物理削除しない。** 逆に計画へ戻った客室は
        一意制約があるので新規作成ではなく復活（`reviveCancelledTasks()`）。

**判断したこと**

1. **バッチのテナント文脈のロールが仕様に無い。** `org_directory` から組織を
   列挙し、`role: "ORG_ADMIN"` の文脈を組み立てている。→ OPEN_QUESTIONS #033。
   **Queue コンシューマを作る task 全部が同じ問いに当たる。**
2. 客室状況が 1 件も無い施設では**何も作らない。** §3.4 の「未入力でも動く」は
   `POST /api/v1/room-plans/all-checkout`（P1-04）という明示の操作にした。
   暗黙に全室アウト清掃を作ると、入力を始めた施設で区別がつかなくなる。
3. チェックリストの展開（§6.1）は生成の直後に行う。テンプレートが 1 つも
   無くても生成は成功させる（テンプレート未作成の施設でタスクが 0 件になるのを避ける）。
