## 作業ログ

### 2026-08-13

**「集計値と明細が一致する」を、突き合わせずに満たす形にした。**

`buildDailyReportPayload()`（`packages/engine/src/dailyReport.ts`）が
唯一の集計者で、**PDF もそこから描き、DB の集計列もそこから入れる。**
サマリーの各項目は同じ関数に渡された明細を数えた結果でしかなく、
引数でサマリーを受け取る口が無い。「明細は 50 行あるのに完了 44 件」の
日報を作れる経路が存在しない。

```
listTasks / listInspectionsByTaskIds / listReworkCyclesByTaskIds …
      ↓  lib/report/dailyReport.ts（集めるだけ。数えない）
buildDailyReportPayload()  ← 唯一の集計
      ├→ canonicalJson → payloadSha256 → 紙の「文書ハッシュ」
      ├→ renderDailyReportPdf() → R2（documents/…-r{revision}.pdf）
      └→ dailyReportCounters() → daily_report の 5 列
```

**検査対象を「検査の記録があるタスク」と定義した。** `inspectionRequired`
の設定で数えると、抽出検査（§2.1 の `SAMPLE`）の施設で「検査対象 100 件・
初回合格 12 件」という読めない表になる。§9.2 の例（完了 50 = 検査対象 50、
初回合格 44 + 差戻し 6）とも一致する。

**版はキーに入れた。** `documents/{orgId}/{propertyId}/daily-reports/
{YYYY}/{MM}/{documentNo}-r{revision}.pdf`。上書きは構造として起こらない。
「消さない運用」に頼らない。文書番号は初版でだけ採番し（`DocumentSequencer`）、
**版が変わっても同じ番号**（§9.3）。

**自動生成は 10 分ごとの cron で拾う**（DECISIONS #085）。日締め時刻は
施設が設定できるので、`10 5 * * *` に固定すると設定を変えた施設の日報が
永久に出ない。`[日締め + 10 分, +20 分)` の窓に入った施設だけを
`QUEUE_PDF_GENERATION` へ投げる。1 日にちょうど 1 回だけ窓に入る。

**冪等**（testing.md §4）: ① 自動生成は既に日報がある業務日には何もしない
② R2 のキーが版から決まる ③ payload の生成時刻はメッセージが持つ
（`new Date()` を使わない）④ 一意制約 `(propertyId, businessDate, revision)`。

### 止まらずに判断したこと

- **和文フォントは R2 に置く**（DECISIONS #086 / OPEN_QUESTIONS #054）。
  `@react-pdf/renderer` の既定書体は CJK のグリフを持たず、和文が
  **例外にならずに空白になる。** TTF（数 MB）はバンドルに含めず
  `DOCUMENTS` の `fonts/pk-jp-regular.ttf` から読む。**無ければ
  日報を作らない**（`FONT_ASSET_MISSING` で retry）。
  **置く作業は人間**。置くまで日報は 1 通も出ない。
- **自動生成は監査ログを書かない**（DECISIONS #084）。cron には
  名乗れる `membership.id` が無い（OPEN_QUESTIONS #033 が予告した場面）。
  記録は追記しかできない `daily_report` の行そのもの。手動再生成
  （`MANUAL`）だけ `document.issued` を書く。
- **日報に載せる不具合はその業務日のタスクに紐づくものだけ**
  （DECISIONS #087）。`issue_report` は業務日の列を持たず、現地時刻の
  境界を UTC の瞬間へ逆変換する手段をアプリは持たない。
- **ID の接頭辞は `rpt`**（DECISIONS #083）。帳票番号 `RPT-` と同じ綴り。

### 申し送り

1. **フォントを置くまで日報は出ない**（OPEN_QUESTIONS #054）。
   `wrangler r2 object put pk-documents/fonts/pk-jp-regular.ttf --file <TTF>`。
   4 環境ぶん要る（bucket 名は wrangler.toml）。
2. **cron が 2 本になった。** `scheduled()` は `controller.cron` で分岐する。
   **wrangler.toml の式と `DAILY_REPORT_CRON` がずれると、日報の回で
   タスク生成が走る。** 片方だけ変えないこと。
3. **`nodejs_compat` を足した。** `@react-pdf/renderer` が Node の API を
   使う。継承されるキーなので `[env.*]` へは書き写していない。
4. P2-15（指標算出）は日報と同じ行から作れる。`buildDailyReportPayload()`
   の `summary` は 8 項目で、§10.1 の 7 指標とは別物（あちらは率と平均）。
   engine に別モジュールを足すこと。**サマリーを率に変えないこと。**
