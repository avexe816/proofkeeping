# P7-21 サイドバーの折りたたみ

**Phase**: 7（追加起票 / 2026-08-19 / オーナー指示）
**仕様**: docs/PK-SPEC-UI-A01.md 第2版 §1.1・§4.4（この task と同時に改訂）
**依存**: なし（レイアウトのみ）
**見積**: 1日
**ステータス**: 実装済み（2026-08-19）

## この task が起票された理由

オーナー指示（2026-08-19）。競合の管理画面（ResortCleaning 等）はサイドバーを
折りたたんで作業領域を広げられる。ProofKeeping の PC 画面は横に広い表
（進捗モニタ・証跡一覧・監査ログ・請求明細）が多く、214px 固定は狭い画面で
コンテンツを圧迫する。

A01 第1版は「サイドバー 214px 固定・ブランド幅と一致（受け入れ基準 #13）」の
ため、**先に A01 を第2版に改訂**してから実装する（勝手に実装しない）。
プロトタイプに折りたたみは存在しないため、PROTOTYPE_GAP.md の原則への例外根拠も
A01 に明記する。

## 読むべきルール
- `.claude/rules/ui-writing.md` §1（i18n。aria-label も `t()` 経由）
- `docs/PK-SPEC-UI-A01.md` 第2版

## やること

### 1. A01 第2版の改訂（実装より先）
- §1.1 にレール状態 56px を追記。
- 受け入れ基準 #13 を「**ブランド領域幅は常にサイドバー幅と同期**
  （展開 214px / レール 56px）」に改訂。縦のラインの原則は両状態で維持。

### 2. 全体折りたたみ（アイコンレール）
- 状態はセッション保持（localStorage は SSR 初回にちらつくため不採用）。
  `routes/app/switchProperty.ts` と同型の action-only ルート
  `app/toggle-sidebar` を layout の外に追加。
- `ShellData` に `sidebarCollapsed: boolean` を追加（子画面の loader に影響なし）。
- `app.css` に `--sidebarWidthCollapsed: 56px` と `.pk-shell--nav-collapsed` 修飾子。
  `.pk-sidebar` と `.pk-topbar__brand` の幅を同時に切替。レール時はラベル・
  フッター注記を隠し、アイコン＋`title` のみ。トグルはサイドバー最下部。

### 3. セクション開閉（アコーディオン）
- `Sidebar.tsx` にクライアント `useState`（既定は全展開）＋ localStorage 永続。
  SSR は常に展開で描画し、閉じた状態だけ hydration 後に反映。
- Storage 注入パターンは `lib/mobile/installBanner.ts` の流儀を PC 用に移植。

### 4. i18n
- `ja.json` に `sidebar.collapse` / `sidebar.expand` / `sidebar.section.toggle`。

## 完了条件
- [ ] トグルでレール（56px）⇔ 展開（214px）が切り替わり、リロード後も保持される
- [ ] レール時もブランド幅が同期し、縦のラインが通る（A01 第2版 #13）
- [ ] レール時に現在地（active）と locked がアイコンで判別できる
- [ ] セクション見出しのクリックで項目群が開閉し、選択が保持される
- [ ] SSR 初回描画にちらつきが無い（折りたたみ状態がサーバー側で確定している）
- [ ] モバイル（`/m/*`）に影響が無い
- [ ] `pnpm check` 通過（no-literal-string / navigation.spec は不変）

## やらないこと
- **レスポンシブブレークポイントの導入。** 手動トグルのみ。自動折りたたみは
  A01 にメディアクエリの規定が無いため別途起票。
- **モバイルレイアウトへの適用。**（`/m/*` は別シェル）
