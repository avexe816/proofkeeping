## 作業ログ

- 取引年月日（`from` / `to`）と取引金額（`minAmount` / `maxAmount`）は
  P5-07 / P5-08 が既に入れていた。**足りなかったのは取引先。**
  `counterpartyId`（内部の ID）でしか引けず、**人が検索するのは名前**。
- `counterpartyName` の部分一致を足した。使うのは**発行時に固定した
  非正規化列**（§1.2 のために P5-01 が入れ、`idx_inv_party` を張った列）。
  **取引先マスタと JOIN しない** — 名前を変えても過去の帳票は
  発行時の名前で引ける（billing.md §6）。
- §9 の `&counterparty=` に合わせ、クエリ名は `counterparty`。
- 請求書と領収書の**両方**に同じ検査を掛けた（`search.spec.ts`）。
  片方だけ通っても要件は満たされない。

### 止まらずに判断したこと
- **前方一致ではなく部分一致にした。** 前方一致なら `idx_inv_party` が
  効くが、株式会社の前後表記（前株・後株）が揺れる相手を引けない。
  電帳法が求めるのは「取引先で検索できる」こと。走査は組織 1 件ぶんに
  閉じている（`withTenantScope()`）ので、テナントを越えて重くならない。
- **画面は作っていない。** この task の完了条件は検索そのもの。
  W-3x の画面は UI の task が持つ（並行セッションが P5-02・P5-03 の
  画面を作った形と同じ）。
