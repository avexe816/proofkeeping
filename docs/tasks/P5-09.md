## 作業ログ

- `lib/billing/creditNote.ts` — §5.2 の 1〜4 と 6。
  **取消が先、赤伝はそのあと。** 取消が取れなければ番号を消費しない
  （2 回押しても赤伝が 2 通出ない）。
- 赤伝の税額は `summarizeTax()` で引き直す。**元の税額を反転して
  足さない。** 符号対称な丸め（`calcTaxAmount()`）なので結果は
  元伝票の符号違いにちょうど一致する。`Math.floor()` で実装して
  いたら -1235 と -1234 に割れていた。
- `voidInvoice()` は **`pdfStorageKey` に触らない。**
  `repositories.spec.ts` が「`VOIDED` を書く `set()` に PDF の列が
  入っていないこと」を走査して固定する。
- `GET /invoices/:id/download` は **`VOIDED` を弾かない**（§5.2 MUST
  「ダウンロードリンクを無効化しない」）。`findSendableInvoice()` を
  使っていないのはそのため（あれは送付の判定）。
- 赤伝は新しい番号を採る。元の番号は使われたまま残る（§5.3）。
  `DocumentSequencer` は減らない。
- 監査 `document.corrected` を**理由必須**にした（§5.2 の 2）。

### 止まらずに判断したこと
- **DECISIONS #126 `REOPEN`（`INVOICED → REVIEWING`）を足した。**
  §5.2 は訂正のあと再発行すると定めるが、§6.1 の図に戻る矢印が無く、
  戻れないと訂正が完了しない（赤伝は出せるが正しい請求書を出せない）。
- **`void` 単独の口を作っていない。** §5.2 の取消は赤伝と同時にしか
  起こらない。単独で取り消せると、赤伝の無い `VOIDED` が作れてしまう。
