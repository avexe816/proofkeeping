# P5-24 Resend の秘密と設定を消す（**前提条件が揃うまで着手しない**）

**系列**: P5（起票 2026-08-21 / オーナー指示） **依存**: **P5-21 / P5-23**
**見積**: 0.5 日 **ステータス**: **着手不可**（下の前提条件が未達）

## 背景
P5-21 でメール送信を Lark Mail SMTP へ移した（DECISIONS #248）。
`RESEND_API_KEY` / `RESEND_WEBHOOK_SECRET` / `RESEND_FROM_ADDRESS` は
**送信にはもう使われていない**が、**消していない。**

消さない理由は 1 つ。**確認できているのは開通リンクの経路だけ**で、
帳票の送付と業務通知は実送信を通していない。ここで鍵を消すと、
不具合が出たときに**戻す先が無くなる。**

## 着手の前提条件（**すべて満たすまで消さない**）

- [ ] **帳票送付の実送信確認**（P5-07 / P5-10）
      請求書 PDF を実際に送り、受信箱で開けること。
      送付ログが `SMTP_ACCEPTED` になること
- [ ] **業務通知の実送信確認**（P6-08）
      通知メールが届くこと
- [ ] 上記が **staging で 2 週間**再現すること（散発的な失敗が無い）

**開通リンク（PF-16）の確認だけでは足りない。** あれは 1 通・固定の宛先で、
`cc` も添付も通っていない。帳票の送付は `cc` を使う（`Cc` ヘッダと複数
`RCPT TO`）。

## 前提が揃ったら消すもの

| 対象 | 場所 |
|---|---|
| `RESEND_API_KEY` | secret（staging / production） |
| `RESEND_WEBHOOK_SECRET` | secret（同上） |
| `RESEND_FROM_ADDRESS` | vars（`wrangler.toml` の 4 環境） |
| 上記の型 | `packages/db/src/env.ts` の `EnvVars` / `EnvSecrets` |
| 名前の一覧 | `tests/toolchain/wrangler.spec.ts` の `SECRET_NAMES` |
| `.dev.vars.example` の行 | 同ファイル |

## **消さないもの**（将来のために残す）

**webhook の受信側の実装一式を消さない。**

- `routes/api/v1/webhooks.ts`
- `lib/billing/webhookEvent.ts` / `webhookSignature.ts`
- `consumers/notification.ts` の `handleDeliveryEvent()`
- `document_delivery.provider_message_id` 列（いまは常に `null`）
- `DELIVERY_STATUSES` の `DELIVERED` / `BOUNCED` / `SENT` / `FAILED`
- `PK_DELIVERY_TAG` / `PK_DELIVERY_HEADER`

理由: SMTP には webhook が無く、**配達・開封・バウンスが分からない**
（OPEN_QUESTIONS #118）。取り戻す task は `docs/tasks/P5-22.md` で、
そのときに**署名検証と受信の口を作り直さずに済む**ようにしておく。
`RESEND_WEBHOOK_SECRET` という**名前**は消してよいが、**仕組みは残す。**

## やらないこと
- 前提条件が揃う前に鍵を消すこと
- 受信側の実装・列・状態を消すこと
- 消すのと同時に webhook を作り直すこと（それは P5-22）
