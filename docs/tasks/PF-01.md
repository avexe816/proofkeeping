architecture.md §3（横断の集計を書かない）か security.md §2（全シャード走査の禁止）を
必ず破る。#220 が決めた形をここで敷く。

## やること

### `packages/db/src/schema/platform.ts`（新規・SHARD_00 のみ実体を使う）
- `platform_operator` — 運営担当者。**`Role` に `PLATFORM_ADMIN` を足さない**
  （PK-IMPL-CONTRACT §2 も「組織内ロールではなく未実装」と書いている）。
  列: `id` / `email` / `displayName` / `passwordHash` / `status` /
  `failedAttempts` / `lockedUntil` / `twoFactorSecret`（**列だけ置く。
  方式は OPEN_QUESTIONS #109**）/ `createdAt` / `updatedAt`
- `platform_audit_log` — **削除・更新の口を作らない**（INV-30 と同じ）

`org_directory` に列を足さない。あれは採番レジストリのまま。

### 認証 `/plat/login`
- **メール＋パスワード**（PK-IMPL-CONTRACT §3.5）。
  現場系の `orgShortId`＋スタッフ番号は使わない
  （運営担当者はどの組織にも属さないので解決できない）。
- ハッシュは **PBKDF2-SHA256 210,000 回**、10 回失敗で 30 分ロック（security.md §2）。
- Cookie は `pk_plat_session`。**`pk_session` と別名にする。**
  テナント用のセッションで `/plat/*` に入れない・その逆も同じ。
- 失敗応答は一律（security.md §2）。レート制限は `/auth/login` と同じ 10 req/分/IP。

### シェル
プロトタイプ共通のシェルどおり。
- topbar: ブランド `ProofKeeping / PLATFORM ADMIN` → テナントセレクタ
  （既定「全テナント」）→ 🔔 → ユーザー
- ユーザーメニューのロールバッジ = **「プラットフォーム運営 · 全テナント」**（A01 §3.3）
- サイドナビ 4 群 12 項目（稼働状況 / P4エンジン / サポート / 経営・統制）
- サイドバー脚注 = **「プラットフォーム運営 / 個人情報へのアクセスは制限されます」**
- ルートは PK-IMPL-CONTRACT §3.4 の路を `/plat` の下へ:
  `/plat/status` `/plat/tenants` `/plat/usage` `/plat/rules` `/plat/accuracy`
  `/plat/validation` `/plat/tickets` `/plat/issues` `/plat/announcements`
  `/plat/revenue` `/plat/compliance` `/plat/config`
