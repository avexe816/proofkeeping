## やること

### `packages/db/src/schema/platform.ts`（新規・SHARD_00 のみ実体を使う）
- `platform_operator` — 運営担当者。**`Role` に `PLATFORM_ADMIN` を足さない**
  （PK-IMPL-CONTRACT §2 も「組織内ロールではなく未実装」と書いている）。
  列: `id` / `email` / `displayName` / `passwordHash` / `status` /
  `failedAttempts` / `lockedUntil` / `twoFactorSecret`（**列だけ置く。
  方式は OPEN_QUESTIONS #109**）/ `createdAt` / `updatedAt`
- `platform_audit_log` — **削除・更新の口を作らない**（INV-30 と同じ）

`org_directory` に列を足さない。あれは採番レジストリのまま。

### 認証 `/plat/login`
- **メール＋パスワード**（PK-IMPL-CONTRACT §3.5）。
  現場系の `orgShortId`＋スタッフ番号は使わない
  （運営担当者はどの組織にも属さないので解決できない）。
- ハッシュは **PBKDF2-SHA256 210,000 回**、10 回失敗で 30 分ロック（security.md §2）。
- Cookie は `pk_plat_session`。**`pk_session` と別名にする。**
  テナント用のセッションで `/plat/*` に入れない・その逆も同じ。
- 失敗応答は一律（security.md §2）。レート制限は `/auth/login` と同じ 10 req/分/IP。

## 作業ログ

**2026-08-20 データ面と認証まで。** 画面（シェル・ナビ・`/plat/login` の
ルート）は次の PR。**この task はまだ閉じない。**

できたもの:

- `packages/db/src/schema/platform.ts` — `platform_operator` /
  `platform_audit_log`。**`schema/index.ts` に載せない** — あちらは
  テナントスコープの表だけで、`schema.spec.ts` が `organization_id` と
  index の不変条件をそこに掛けている（`global.ts` と同じ扱い）。
- `getPlatformDb()`（`router.ts`）— SHARD_00 固定。**返るスキーマに
  `task` も `room` も載っていない**ので、ここからテナントのデータへは
  型として到達できない。逆も同じ。
- `repositories/platform.ts` — 取得・ログイン試行の記録・監査の追記。
  **`TenantContext` を取らない**（運営担当者はどの組織にも属さない）。
  失敗回数の加算は SQL 側（読んで足して書くと同時実行で取りこぼす）。
- `lib/platform/session.ts` — Cookie `pk_plat_session`、KV の接頭辞 `plat:`。
  **テナントの `pk_session` / `sess:` と交わらない。**
- `lib/platform/login.ts` — メール＋パスワード。存在しない・違う・ロック中・
  無効化済みの**どれでも `AUTH_FAILED` 1 種類**。該当が無くても 1 回
  PBKDF2 を回して応答時間を揃える。失敗は**毎回**記録する（テナント面は
  5 回目だけだが、運営面は母数が桁違いに小さい）。
- 走査テスト `repositories/platform.spec.ts` が上の 3 つの完了条件を固定。

## 申し送り
- **「`/app/*` に運営用セッションで到達すると 404」は、そのままでは
  実装できない。** テナント面のハンドラが運営の Cookie を知る必要があり、
  DECISIONS #220 の「テナント面のハンドラは `platform_*` を読まない」と
  正面から衝突する。現状は Cookie が別なので、運営のセッションだけを
  持つ相手は `/app/*` で**未ログインとして扱われ `/login` へ戻る**
  （テナントのデータは 1 行も出ない）。404 でなければならない理由が
  あるかを人間に確認したい。→ `docs/OPEN_QUESTIONS.md` #113
