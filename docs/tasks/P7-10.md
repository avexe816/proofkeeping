### 判断したこと（止まらずに進めた）

- **通知イベントを 11 件目として足した**（DECISIONS #163 /
  OPEN_QUESTIONS #097）。§5.1 の 10 件は P7 を織り込んでいない。
  `lostitem.retention_due` は宛先が `PROPERTY_MANAGER` で、§4.5 の
  「管理者へ」と合わない。
- **バッチの監査ログに人の ID を借りない**（DECISIONS #164）。
  組織の `OWNER` を借りると「その人が消した」と読める記録ができる。
  `systemActorId()` が実在しない ID を返す。**ULID 部は固定**
  （実行のたびに違うと「別々の誰かが操作した」ように読める）。
- **cron もキューも増やさない**（DECISIONS #165）。夜間の回に相乗りし、
  `pk-archive-restore` に `kind: "PHOTO_RETENTION"` で載せる。
- **版数が引けない組織へは投げない。** 「引けないから既定の 6 か月」に
  すると、上位プラン（13 か月）の写真を 7 か月早く消しうる。
- **上書きで短くはできない。** 版数の既定を下限にする。§4.5 MUST が
  求めているのは「必要なら期間**延長**できる」ことだけで、短くできると
  「設定を触ったら過去の写真がまとめて消えた」が起こりうる。

### 消す順序（いちばん大事）

**D1 の行を先に消し、R2 の実体を後に消す。** 逆にすると、途中で落ちた
ときに行が実体の無い写真を指し、**画面には出るのに開けない写真**ができる。
行を先に消せば、残るのは参照されない R2 オブジェクト（費用だけの問題）で、
後から掃除できる。`lib/offline/queue.ts` の `dropItem()` と同じ向き（INV-27）。

### 「退避」ではない

P7 固有の絶対ルール「アーカイブを『削除』と表現しない」は**年次アーカイブ
（§19.7）の話**で、あちらは R2 に写しが残る。こちらは**写しを作らずに消す**
ので言い換えない。消えたことが伝わらなくなる。
