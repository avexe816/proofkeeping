### 完了条件の確認
- **最終同期時刻が常時表示される** → §9 のリスク表「連携が止まって
  気づかない」への対策そのもの。`lastSyncAt` と `lastSuccessAt` を
  分けて出す（**取得を試みた時刻と成功した時刻は別**）。
- **未マッピング件数が表示される** → 外部 ID 側と客室側の両方向。
  `sync_log` ではなく**対応表そのもの**を数える（直近 1 回しか
  映さない値を状態として出さない）。

### 止まらずに判断したこと
- サーキットブレーカーが開いているとき、「稼働照合はこの連携が
  止まっていても実行されます」と明記した。§1.2 の設計をそのまま
  画面の文言にしている。**止まったのは取込であって業務ではない。**
- 失敗の理由（`lastErrorMessage` / `syncLog.errorMessage`）は
  **書き込む側が内部の理由まで詰めた値**を出す。外部システムの応答を
  そのまま画面へ出さない（個人情報が混ざりうる）。

  （P6-06 が人間待ち）。リポジトリ関数（`createIntegration()`）は P6-01 が
  置いてある。
- 「今すぐ同期」（§7.1）が無い。PULL 側の取込がまだ無い（P6-06 待ち）。
