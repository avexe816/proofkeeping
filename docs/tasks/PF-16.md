# PF-16 運営担当者の初期開通（bootstrap / 1 人目だけ）

**系列**: PF（起票 2026-08-20 / **オーナー判断** DECISIONS #240）
**依存**: PF-01・**PF-17**（初回ログインで 2FA 登録を必須にするため）
**見積**: 2日 **ステータス**: 完了（2026-08-21）

## 背景
本番に運営担当者を作る経路が無い。シードは local / staging でしか動かず
（`seed()` が production で落ちる）、PF-14 の招待画面はまだ無い。
**production seed は使わない**（オーナー判断）。**最初の 1 名だけ**を作る
別の手順を用意する。

## やること（**要件は 8 つ。1 つも落とさない**）
1. **人が明示実行する。** GitHub Actions の `workflow_dispatch` または
   管理用 CLI。自動実行の経路を作らない
2. 運営担当者の**メールアドレスを指定**する
3. **既定パスワードを作らない**（`seed()` のように値を埋めない）
4. **短時間だけ有効な 1 回限りの開通リンク**を発行する
   （使い切りで失効。有効期限は短く）
5. 初回ログインで**パスワード設定と 2FA 登録を必須**にする（PF-17）
6. **全操作を監査ログへ記録**する（`platform_audit_log`）
7. **運営担当者が既に存在する場合は再実行を拒否**する
   （**1 人目だけの経路**であることを実装で保証する）
8. **token・パスワード・2FA secret をログへ出さない**

## やらないこと
- production で `seed()` を動かせるようにすること
- 2 人目以降をここから作れるようにすること（PF-14 の招待が持つ）
- 既定パスワード・固定 token を置くこと

## 完了条件
- [x] 運営担当者が 1 名でも居ると**拒否**される（走査 + 実行テスト）
- [x] 開通リンクが**1 回で失効**する（2 回目は通らない）
- [x] 期限切れの開通リンクが通らない
- [x] パスワード設定と 2FA 登録を終えるまでログイン後の画面へ到達できない
- [x] token・パスワード・2FA secret が**ログにも監査ログの `detail` にも出ない**
- [x] 実行が `platform_audit_log` に残る

#### 流れ

```
人が Actions で押す
  → workflow が 1 回きりの管理鍵を登録・再デプロイ
  → POST /api/v1/platform/bootstrap を 1 回だけ叩く
  → 券（token のハッシュ）を 1 枚作り、**メール 1 通**でリンクを渡す
  → workflow が管理鍵を必ず削除（if: always()）
本人がリンクを開く
  → GET は消費しない（プレビューで燃やさない）
  → POST でパスワード設定・**券を原子的に消費**・1 人目を条件付き INSERT
  → PASSWORD_ONLY の札（10 分）で /plat/2fa/setup へ
  → TOTP 登録 + 復旧コード保管（PF-17）→ COMPLETE → /plat/*
```

#### 判断したこと（止まらずに / DECISIONS #245）

- **管理用 CLI を作らず workflow にした。** 手元に Cloudflare の資格情報を
  要求しない形へ揃える（`staging-bootstrap.yml` と同じ）。
- **券の段階で運営担当者の行を作らない。** 作ると `password_hash` を
  何かで埋めることになり、「既定パスワードを作らない」を型で満たせない。
- **メールが送れない環境では券を作らずに断る。** token をログへ出す
  代替は採らない（要件）。
- **失敗の理由を分けない**（無い・使用済み・失効・期限切れ → すべて 404）。

#### レビュー反映（2026-08-21 / DECISIONS #246）

- **開通の口の応答から「メールが未設定」と「送信に失敗」を読ませない。**
  初版は `DELIVERY_UNAVAILABLE` / `DELIVERY_FAILED` を分けて返しており、
  **無認証で公開されているこの口が、環境の設定状態を答える装置になっていた。**
  応答は **`DELIVERY_REJECTED` の 1 種類**（503）に統合し、
  `issuePlatformBootstrap()` の**戻り値の型からも内訳を外した**
  （型が持たなければ、後から応答へ載る事故が起きない）。
- 内訳は **`platform_audit_log` の `detail.cause`** にだけ残す
  （`DELIVERY_NOT_CONFIGURED` / `DELIVERY_SEND_FAILED`）。
  **`RESEND_API_KEY` の値も宛先も入れない**（テストで走査）。
- `OPERATOR_EXISTS`（409）と `INVALID_REQUEST`（400）は**そのまま。**
  どちらも押した人の入力から決まる話で、環境の構成を漏らさない。
- workflow のログと runbook §8 は「未登録です」と断定せず、
  **確かめる順序**（鍵の名前 → 宛先の綴り → 送信ドメイン）を出す形にした。
