# PF-16 運営担当者の初期開通（bootstrap / 1 人目だけ）

**系列**: PF（起票 2026-08-20 / **オーナー判断** DECISIONS #240）
**依存**: PF-01・**PF-17**（初回ログインで 2FA 登録を必須にするため）
**見積**: 2日 **ステータス**: 未着手

## 背景
本番に運営担当者を作る経路が無い。シードは local / staging でしか動かず
（`seed()` が production で落ちる）、PF-14 の招待画面はまだ無い。
**production seed は使わない**（オーナー判断）。**最初の 1 名だけ**を作る
別の手順を用意する。

## やること（**要件は 8 つ。1 つも落とさない**）
1. **人が明示実行する。** GitHub Actions の `workflow_dispatch` または
   管理用 CLI。自動実行の経路を作らない
2. 運営担当者の**メールアドレスを指定**する
3. **既定パスワードを作らない**（`seed()` のように値を埋めない）
4. **短時間だけ有効な 1 回限りの開通リンク**を発行する
   （使い切りで失効。有効期限は短く）
5. 初回ログインで**パスワード設定と 2FA 登録を必須**にする（PF-17）
6. **全操作を監査ログへ記録**する（`platform_audit_log`）
7. **運営担当者が既に存在する場合は再実行を拒否**する
   （**1 人目だけの経路**であることを実装で保証する）
8. **token・パスワード・2FA secret をログへ出さない**

## やらないこと
- production で `seed()` を動かせるようにすること
- 2 人目以降をここから作れるようにすること（PF-14 の招待が持つ）
- 既定パスワード・固定 token を置くこと

## 完了条件
- [ ] 運営担当者が 1 名でも居ると**拒否**される（走査 + 実行テスト）
- [ ] 開通リンクが**1 回で失効**する（2 回目は通らない）
- [ ] 期限切れの開通リンクが通らない
- [ ] パスワード設定と 2FA 登録を終えるまでログイン後の画面へ到達できない
- [ ] token・パスワード・2FA secret が**ログにも監査ログの `detail` にも出ない**
- [ ] 実行が `platform_audit_log` に残る
