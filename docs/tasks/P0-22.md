## やること
- 範囲一括登録（例 `301-320`、欠番除外に対応）

- `Room` に `isSellable` / `sourceType` / `externalRoomId` カラムを追加
- 清掃専用の部屋（パントリー・備品庫等）を `isSellable = false` で登録できるようにする

## 作業ログ

### 2026-08-12
- 完了条件 9 件のうち 8 件達成。残り 1 件は下記。
- `Room` の 3 カラム（`isSellable` / `sourceType` / `externalRoomId`）は
  **P0-06 の CREATE TABLE に既に入っている。** ALTER TABLE は不要だった。
- 範囲一括登録（`expandRoomRange`）と CSV 取込（`parseRoomCsv`）は
  DB を知らない純粋関数。**重複判定を持ち込まない**（リポジトリ層の
  `onConflictDoNothing()` が唯一の判定。2 か所に置くと画面の件数と
  実際の登録数がずれる）。
- 既存の部屋番号はエラーにせず見送り、件数を返す（§24.2 MUST）。
  100 室で 1 室ぶつかっただけで全部やり直しになると現場で使えない。
- 欠番除外は**利用者が明示した番号だけ。** 「4 を含む番号を自動で飛ばす」
  ような気の利かせ方をしない（施設によって慣習が違う）。spec で押さえてある。
- CSV は引用符を扱わない。§24.2 のフォーマットに引用符を要する列が無く、
  **壊れ方が読める形に留めた。** 1 行壊れていても他は取り込み、
  行番号付きで返す。
- 清掃専用の場所は `isSellable = false` で別セクション表示。客室数に数えない。
- 部屋番号の変更は `AuditLog` に旧番号を残す（§24.5）。物理削除の API は無い。
- `externalMapping` は**定義のみ**（§26。読み書きは P6 / §24.4）。
  越境テストは `UNCOVERED_TABLES` に理由付きで残してある。
- **未達 1 件: 客室の無効化時に「未完了タスクが N 件あります」を提示する**
  （§24.5）。`cleaningTask` が P1 の表で、数える対象が存在しない。
  タスクを作る task が件数の取得と提示を足すこと。
- **「清掃専用の部屋が稼働照合の対象外」は P4 で検証**（task の記載どおり）。
