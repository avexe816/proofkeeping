## 作業ログ

### 2026-08-14

**2 つだけ実装した。** レジストリは `[R001, R006]`。§実装順序 4 のとおり、
残り 12 個は P4-08（誤検知率の検証・人間が実施）を通してから。

**R001 は §3.2 のコードをほぼそのまま写した。** 変えたのは 2 点。
- 確信度の定数を名前付きで出した（`R001_BASE_CONFIDENCE` ほか）。
  §4.2 の調整は `confidence.ts` が掛けるので、ルールは素の値だけを返す。
- 早期 return（`MAINTENANCE` / 入室記録 / 自社利用）を残した。`evaluate()` が
  呼ぶ前に抑制するので通常は通らないが、**ルール単体で呼んでも同じ結論に
  なる**ようにしてある。

**`OccupancyFact` に `source` / `importedAt`、`ObservationFact` に
`recordedAt` / `recordedById` を足した。** §3.2 のコードがこの 4 つを
`evidence` に載せており、§6.2 の画面（「PMS / CSV取込 09/10 02:14」
「清掃 田中 / 09/09 10:22 記録」）がそれを出す。P4-03 の型に無かった。

**R006 の `requires` に `occupancy` を入れていない。** 入れると
`SOURCE_UNAVAILABLE`（§4.1）で常に抑制され、**A 系統が無いことを見る
ルールが A 系統を要求する**という形になって何も検出しない。§3.1 の表の
とおり必要系統は B。`occupancyLinked = true` の条件はルール自身が見る。

**確信度 50 は仕様に無い**（§3.7 に式が無い / DECISIONS #108）。
取込の遅延と連携の欠落をこの時点で区別できないため、R010 の固定 60 より
低くした。**P4-08 の実データで見直すこと。**
