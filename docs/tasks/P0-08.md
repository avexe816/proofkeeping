## 読むべきルール
security.md §2

## やること
管理系ロール（OWNER / ORG_ADMIN / AUDITOR / PROPERTY_MANAGER / VENDOR_ADMIN）の
ログインを実装する。識別子は **orgShortId + スタッフ番号 + パスワード** の 3 フィールド。
メールアドレスはログイン識別子に使わない（通知送信先のみ）。
セッションは Workers KV（`SESSION`）、レート制限は Workers KV（`RATELIMIT`）。

現場系（CLEANER / INSPECTOR）の PIN 4 桁ログインは P0-09 が同じ基盤の上に足す。

## 作業ログ

### 2026-08-11

- **OPEN_QUESTIONS #014（メールから組織を解決する手段が無い）を解決した。**
  ログイン識別子を orgShortId + スタッフ番号 + パスワードにしたため、組織の解決は
  SHARD_00 の `org_directory` を引く既存の `lookupOrganizationId()` で足りる。
  新しいディレクトリ表は作っていない（DECISIONS #018）。
- **ハッシュ方式を bcrypt から PBKDF2-SHA256 210,000 回へ変更した**（DECISIONS #019）。
  bcrypt は Workers に純 JS 実装しか無く、cost 12 で 1 回 344ms（実測）。
  ログインは Queue へ逃がせない同期処理なので、CLAUDE.md §4 の CPU 予算を守れない。
  PBKDF2 は WebCrypto のネイティブ実装で 210,000 回が実測 38ms。
  これに合わせて `.claude/rules/security.md` §2 を改訂した。
- **セッションに `role` / `allowedPropertyIds` を持たせていない**（DECISIONS #020）。
  P0-10 が毎リクエスト `findMembershipByUserId()` + `listAssignedPropertyIds()` から
  `TenantContext` を組み立てる前提。
- 5 回目のログイン失敗の監査ログ（security.md §6）は書いていない。
  `recordAudit()` が P0-11 で未実装のため。P0-11 が `login.ts` の該当箇所に足すこと。
- パスワード変更・リセットの API は作っていない（P0 に該当 task が無い）。
  再利用禁止を含む設定処理は `setUserPassword()` として関数で提供してある。
