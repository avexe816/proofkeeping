## この task が起票された理由

OPEN_QUESTIONS **#082**: 忘れ物（P2-11）と設備不具合（P2-12）は API だけがあり、
PC の一覧・管理画面が無かった。組織ダッシュボードの「要対応」は件数だけで、
**保管期限も対応状況も「誰も見ていない」まま過ぎる**状態だった。
PK-SPEC-P2 §12.1 は W-09 `/app/p/[id]/lost-found` と W-10 `/app/p/[id]/issues` を
定義済みで、画面を起こすだけの状態。OQ #082 は「P7 が自然な置き場所」としていた。

## 読むべきルール
- `.claude/rules/security.md` §1（CLEANER の境界）・§3（持ち主の情報を保存しない）
- `.claude/rules/ui-writing.md` §2（禁止語）・§3（赤の使いどころ）
- `docs/PK-SPEC-P2.md` §7.3（自動廃棄しない）・§8.3（客室を自動で戻さない）

## やること

### 1. W-09 忘れ物管理 `/app/p/:propertyId/lost-found`
- 一覧（状態フィルタ・保管期限と警告バッジ）＋ `?item=` で詳細・履歴。
- 状態の更新（`lostItem.manage`）: 保管場所・届出番号・処分理由の入力。
  **処分は理由必須**（§7.3 MUST の「明示操作」）。期限で自動処分しない。
- 「連絡済みにする」= `ownerContactedAt` の記録のみ。**連絡先・本文を取らない。**
- `CLEANER` は自分が登録した分だけ・保管場所非表示（lib の絞りをそのまま使う）。
- 期限の `URGENT` バッジは赤。ui-writing.md §3 の禁止（清掃者を急かす赤）とは
  別で、§7.3 が「発見直後から赤」と定める唯一の例外。

### 2. W-10 不具合管理 `/app/p/:propertyId/issues`
- 一覧（状態・程度フィルタ・「販売停止の報告」バッジ）＋ `?issue=` で詳細・履歴。
- 状態の更新（`issue.manage`）: **解決には対応内容が必須**（DECISIONS #081）。
- **客室を戻す操作を置かない**（§8.3。戻すのは客室ボードの明示操作）。

### 3. 導線
- サイドバー「記録の確認」に `nav.lostItems` / `nav.issues`（証跡一覧の直後）。
- 組織ダッシュボードの 2 行は**件数のまま**（施設単位の画面のため、全社ビュー
  からは施設が決まらない。理由を `actionRows()` に明記）。

## 完了条件
- [x] 一覧 → 詳細 → 状態更新（保管・届出・返却・処分・引継ぎ / 受付〜解決）が画面から行える
- [x] 処分に理由が無ければエラー。期限超過で状態が変わらない
- [x] 解決に対応内容が無ければエラー。解決しても客室は変わらない
- [x] `CLEANER` は自分の登録・報告だけが見え、保管場所が出ない
- [x] `pnpm check` 通過

## やらないこと
- **PC からの新規登録・報告。** 発見・報告は現場（M-13）で行う。PC は管理のみ。
- **写真の表示。** 詳細は証跡詳細（W-07）が担う。署名 URL の大量発行を避ける。
- **期限切れの一括処分・自動処分。**（§7.3 MUST）
- **忘れ物の保持日数の施設設定。**（OPEN_QUESTIONS #052 のまま）
