# P8-12 本人が自分の在留資格を見られるようにする（M-11）

**Phase**: 8（起票 2026-08-22 / **オーナー指示** / DECISIONS #261）
**仕様**: `docs/PK-SPEC-P8.md` §3（`CLEANER 自分のみ`）/ `.claude/rules/security.md` §5
**依存**: P8-02（在留資格の記録）
**見積**: 0.5日
**ステータス**: 未着手（**この task では実装しない。起票のみ**）

## 背景

**仕様と実装が食い違っている。** `docs/PK-SPEC-P8.md` §3 の権限表は
在留資格の閲覧を `CLEANER 自分のみ` と定めるが、**実装は `DENY`** で、
`residency.read` はどのロールでも「自分の行だけ」を表す形を持たない。

M-11（本人が自分の記録を見る画面）に在留資格は出ていない
（`routes/m/*.tsx` に在留資格を読む箇所が 1 つも無い / 2026-08-22 時点）。

security.md §5 は「**本人が自分の記録を閲覧できる画面（M-11）を用意する**」を
MUST に挙げており、**在留資格もその「自分の記録」に当たる。**

INV-08 v2（DECISIONS #261）は雇用主の側を広げたが、**本人の経路は触っていない。**
権限を広げたぶん、本人が自分の記録を確かめられる経路も要る。

## 論点（**実装前に決めること**）

1. **「自分のみ」を権限でどう表すか。** 現在の `PermissionScope` は
   `ORG` / `ASSIGNED` / `DENY` の 3 つで、**「自分の行だけ」を表せない。**
   `finding.read` などと同じく、スコープではなく**呼び出し側の絞り込み**で
   表すのが既存の形（`assertReworkVisible()` の類）。**新しいスコープを
   足すかどうかは設計判断。**
2. **何を見せるか。** 種別・期限・更新申請日まで見せるか、期限だけか。
   **就労可否は出さない**（PK-SPEC-P8 §1.4 MUST）。
3. **閲覧の記録を残すか。** 雇用主の閲覧は `residency.viewed` に残る
   （DECISIONS #261）が、**本人が自分の記録を見ることは記録に値しない**
   と考えられる（M-11 の他の項目も残していない）。
