## 背景
テナント側の `/app/settings/rules` は**その組織のルール設定**。ここは
**全テナントに効く元のルール定義**で、別物。混同しないこと。

## やること
- 表「🧠 ルール一覧」（ID / 名称と判定内容 / 重要度 / 確信度上限 / 今月の件数 /
  誤検知率 / 状態トグル / 編集）。R001〜R009 の 9 件
- 表「📐 確信度の算出ルール（全ルール共通）」（シグナル / 寄与 / 条件）
- カード「🔐 変更の承認フロー」＋表「承認が必要な変更」
- ヘッダー: 「変更履歴」「＋ ルールを追加」

## 逐語で置く注記
> **ルールの変更は全テナントに影響します**
> 閾値や重要度を変更すると、過去の差異の確信度も再計算されます。変更前に必ず「検証と再学習」画面でシャドー実行を行い、影響件数を確認してください。本番反映には承認者2名の承認が必要です。

> **単一シグナルで50を超えない制約は変更できません**
> アメニティ消費だけで「使用痕跡あり」と判定しないための安全弁です（PK-SPEC-P4 §14）。この制約はUIから解除できない仕様にしています。

## 語彙の注意
プロトタイプの文中にある **「誤検知」は禁止語 `検知` を含む**。
画面・API 応答・PDF に載せるときは **PF-07 の語彙表**（誤検知率 → 対象外率 ほか）
に従って言い換える。逐語で置くのは**言い換え後の文**で、
`検知` / `異常` が locales に 1 語も残らないこと（CI の grep）。

## やらないこと
- **単一シグナル上限 50 を UI から変えられるようにしない**（PK-SPEC-P4 §14）。
  コード上の定数として持つ
- 承認 1 名での本番反映（説明文の文言修正だけが 1 名）

## 完了条件
- [ ] 閾値・重要度・有効無効・寄与配点の変更が**承認者 2 名**を要する
- [ ] 単一シグナル上限 50 を変える経路が UI にも API にも無い
- [ ] 変更が `platform_audit_log` に残り、削除できない
- [ ] シャドー実行（PF-08）を経ていない変更を本番反映できない
