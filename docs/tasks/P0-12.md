- 実際の呼び出しは `assertEntitlement(env, ctx, "AUDIT", propertyId)`。
  task の記載（`assertEntitlement(ctx, "AUDIT")`）に `env` と対象が増えている。
  D1 を引くため `env` が要り、施設単位・組織単位を区別するため対象が要る。
- **`propertyId` は `string | null` で省略不可。** `null` が組織全体。
  省略を許すと「施設で見るべき操作なのに書き忘れた」場合と区別がつかず、
  静かに広い側へ倒れる（`base.ts` の `NO_PROPERTY_SCOPE` と同じ方針）。
- 施設単位の判定は組織全体の行（`property_id` が NULL）も許す **OR**。
  `schema/billing.ts`（P0-06）が決めた「1 行でも `isEnabled` が真なら許可」。
  帰結として**施設単位の行で「無効」を表現することはできない。**
- `valid_from` / `valid_until` を条件に含めた。トライアル終了後も
  真を返し続ける形にしない（PK-SPEC-P7 §2.5）。
- **`scopeToProperties()` を掛けていない**（`NO_PROPERTY_SCOPE`）。掛けると
  施設スコープロールに `property_id IN (...)` が立ち、組織全体の行が条件から
  外れて**契約が有効なのに全員 402** になる。
- 402 は `PaymentRequiredError` → `apiErrorHandler()`。
  **`NotFoundError`（404）の判定を先に置いた。** 逆にすると担当外施設へ
  「契約していない」と答えることになり、402 が施設の存在を示唆する。
  `API_ERROR_CODES` に `PAYMENT_REQUIRED` を追加した（403 は追加していない）。
