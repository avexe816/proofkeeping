## 作業ログ

### 2026-08-14

**配線した経路。**

```
cron 0 17 * * *（02:00 JST）→ dispatchReconciliation() → QUEUE_RECONCILIATION
POST /api/v1/reconciliation/runs（§5.4）           → 同じキュー
                                                   → handleReconciliationBatch()
                                                   → ReconciliationLock を取る
                                                   → 3 系統を読む → evaluate()
                                                   → 差分だけ INSERT → Run を閉じる
```

**cron を新設していない**（DECISIONS #113）。§5.1 の 02:00 JST は
タスク自動生成（P1-03）と同じ時刻で、`scheduled()` は cron 式で振り分ける。
同じ式を 2 本置いても分けられないので、`0 17 * * *` の分岐で 2 つを続けて
走らせる。**両方を `await` している。**

**`availableSources` は施設ぶんで判定する**（§5.3 の手順 1）。客室ごとに
判定すると、記録が届いていない客室だけ「系統が無い」ことになり、
**まさにそれを拾う R006 が黙る。**

**OPEN_QUESTIONS #063 を列なしで解いた**（DECISIONS #110）。
`occupancyLinked` は直近 30 日に稼働記録があるか、運用開始日は
`property.createdAt` を代用する。**migration を 1 本も足していない。**

**§5.3 の手順 9（rollup-update へ投入）はやっていない。** そのキューには
コンシューマが無く、宣言すると wrangler が起動しない。差異の集計を
rollup に載せる task が 1 行足すこと（`consumers/reconciliation.ts` に注記）。

**ベースラインを渡していない。** R003 / R008 / R009（P4-11 / P4-12）が
実装されるまで読む側が居らず、選び方（客室タイプ × 人数 × 作業種別）を
検証できないまま固定したくない。`RuleContext.baselines` は空配列。

**排他に 15 分の貸出期限を持たせた**（DECISIONS #109）。夜間バッチは
誰も見ていないので、`release()` を呼べずに落ちた実行がその施設・その
業務日を恒久的に塞ぐ形にしない。正常時は `finally` で必ず解放する。

**手動実行（§5.4）の口も作った。** `reconciliation.run` は §6.4 の表どおり
`OWNER` / `ORG_ADMIN` だけ。**それ以外は 404**（403 は存在を示唆する）。
遡れるのは 90 日まで。未来の業務日も断る。
