### 2026-08-12（2）— W-05 の画面（DECISIONS #048 / #049）

**やったこと**

- `/app/p/{propertyId}/plan`（`apps/web/src/routes/app/propertyPlan.tsx`）。
  §10.3 の 7 列（部屋・タイプ・OUT・IN・連泊・人数・清掃辞退）＋**入力元**。
- 表の組み立てとフォームの読み取りは純粋関数
  （`apps/web/src/lib/plan/grid.ts` ＋ spec 19 件）。CSV パーサ（`lib/plan/csv.ts`）は
  そのまま再利用した。
- **「全室アウト清掃として生成」を置いた**（§3.4 MUST）。既存の入力も
  上書きするので確認を 1 段挟む。売れる客室だけを対象にする（§24.3）。
- CSV 取込は読めなかった行番号と客室マスタに無い部屋番号を必ず数で出す。
- 業務日は `?date=` で切替。既定は `businessDateOf(now)`（カレンダー日ではない）。
- 未入力の客室数を画面に出す。**入力は強制しない**（§3.4 の逃げ道と同じ趣旨）。

**完了条件**

- [x] CSV 取込ができる → 画面の貼り付け欄から。
- [x] **「全室アウト清掃として生成」がある** → 確認つきのボタン。

**判断したこと（追加分）**

1. **人数の範囲外は 0 へ丸めず拒否する。** CSV（`parseCount()`）は 100 行の中の
   1 つの書式違いで取込を諦めさせないために 0 へ丸めるが、**画面の入力は
   目の前に人が居る。** 黙って 0 にすると直したつもりの値が消える。
   拒否した部屋番号を画面に出す。
2. **チェックの無い行も送る。** 「変更のあった行だけ」を選ぶと、外した
   チェックが「送られていない」と解釈されて戻ってしまう。
3. **タスクを作らない。** 客室状況は生成の材料で、生成は W-04 の
   「タスクを再生成」が行う。同じボタンにまとめない（入力の途中で
   タスクが立つと、着手済みのタスクとの関係が読めなくなる）。
4. 清掃専用の場所（`isSellable = false`）は**入力欄を出さず**部屋番号だけ並べる。

**未達（意図的・引き続き）**

### 2026-08-19（追記 / 人間の指示）

**やったこと**

- CSV 取込を**ファイルアップロード主・貼り付け従**に変更（DECISIONS #211）。
  - `input[type=file]`（multipart / 上限 1MB）。ファイルと貼り付けが
    両方あるときはファイルを採る。両方空なら「選ぶか貼るか」を案内。
  - 文字コードは UTF-8（fatal）→ Shift_JIS の順（`lib/csv/decode.ts`）。
  - 区切りはヘッダ行で判定（カンマ → タブ）。**Excel からのコピー
    （タブ区切り）が黙って 0 行になる問題もこれで直った。**
    稼働記録取込（P4-02 の `lib/occupancy/csv.ts`）も同じ reader のため
    タブ区切りが読めるようになる。
