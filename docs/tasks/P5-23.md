# P5-23 送信経路の確認（固定の文面を 1 通だけ送る）

**系列**: P5（起票 2026-08-21 / オーナー指示） **依存**: **P5-21**
**見積**: 0.5 日 **ステータス**: 実装済（実送信の確認は人が行う）

## 背景
P5-21 で `smtp-probe` を用意したが、あれが確かめられるのは
**接続・TLS・`EHLO`・`AUTH` の広告まで**（`AUTH LOGIN` を実行しない）。
認証が通るか・受理されるかは、実際に 1 通送るまで分からない。

**開通（PF-16 / `platform-bootstrap.yml`）で試さない。** あちらは 1 人目
専用で押し直せず、認証が未検証のまま使うと失敗時に券だけが消える。
**押し直してよい経路**を別に置く（DECISIONS #249）。

## 追加したもの
| もの | 中身 |
|---|---|
| `POST /api/v1/dev/smtp-send-test` | 鍵が無ければ 404。`{ to }` を受け、固定の文面を 1 通送る |
| `SMTP_SEND_TEST_TOKEN` | その鍵。workflow が作って消す（#247 の形） |
| `lib/mail/sendTest.ts` | 固定の件名・本文と `runSmtpSendTest()`。**`sendMail()` をそのまま呼ぶ** |
| `.github/workflows/smtp-send-test.yml` | 合言葉 `SENDTEST`。環境・宛先・合言葉が入力 |

## 守っていること
- **宛先をコードに埋めない。** 実行のたびに人が指定する（既定値を持たない）
- **本文にリンクも token も顧客のデータも入れない。** 固定の日本語だけ
- **SMTP の手順を複製しない。** 確認で通る道と本番で通る道を同じにする
- 応答は**成否・段階名・3 桁コード**まで。宛先も応答文字列も返さない
- `lib/mail/*` の `console` 禁止・`throw` 禁止をそのまま守る
- 鍵は `if: always()` で削除し、**名前が消えたことまで確かめる**

## 分かること・分からないこと
`accepted: true` は **Lark が `DATA` を受理した**という意味しか持たない。
届いたか・開かれたか・バウンスしたかは分からない（#248 / P5-22）。

## やらないこと
- 宛先や本文を入力で差し替えられるようにすること
- この経路を業務のフローから呼ぶこと（**運用者が手で押すときだけ**）
- `SMTP_PASSWORD` を workflow から登録・参照すること（登録は人が行う）
