## 読むべきルール
`.claude/rules/ui-writing.md` §2 / `docs/PK-IMPL-CONTRACT.md` INV-06 / INV-09

## 背景
**プロトタイプ 02 に週間シフトのグリッドは無い**（DECISIONS #221）。
あるのは 3 つ。

1. KPI 4 枚（出勤予定 26 名 / 出勤済み 24 名 / 欠勤 2 名 / 未割当 0 室）
2. 表「👥 本日の割当」（担当者 / 施設 / 割当 / 完了 / 進捗 / 状態）
3. カード「📅 今週のシフト」＝**出勤者数の棒グラフ 1 本**（月〜日）

仕様 §1.5 の「スタッフ × 曜日のグリッド」「必要人数の行」は**作らない。**

## やること

### `shiftPlan` テーブル
仕様 §1.5 の定義どおり（`staffProfileId` × `businessDate` で一意）。
`shiftType` = `WORK` / `OFF` / `PAID_LEAVE` / `SICK` / `TRAINING`。

### KPI の出し方（**`attendance` を作らない**）
- 出勤予定 = その業務日の `shiftType = WORK` の人数
- 出勤済み = その業務日に**タスクを 1 件以上開始した**人数
- 欠勤 = 出勤予定 − 出勤済み
- 未割当 = 当日タスクのうち担当者未設定の室数

### 画面 `/app/shifts`
- 日付セレクト＋「自動割当」「保存」（プロトタイプのヘッダーどおり）
- 本日の割当の表。カード見出しの右に **「担当者名は運営管理者のみ閲覧できます」**
- 今週のシフト＝棒グラフ（出勤者数）＋脚注「登録スタッフ N 名 / 週平均 N 名」
- カード「⚙️ 自動割当のルール」5 行（**上限室数 16 室・連続勤務 5 日は数値表示のみ。
  ここから変更できる形にしない** — 上限の変更はプラットフォーム側 PF-14 の
  「運用（変更可）」で承認 2 名を要する）

### 前週の複製
仕様 §1.5 MUST。「清掃会社は固定シフトが多い」。**冪等**にする（3 回押しても同じ）。

## やらないこと
- **週間シフトのグリッド**（プロトタイプに無い）
- **必要人数の自動算出行**（同上。近いのは注記の文章 1 本だけ）
- 出勤打刻（DECISIONS #221）
- シフト希望の提出（プラットフォーム 08 の要望一覧で「検討中」の段階）
