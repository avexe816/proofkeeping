## 作業ログ
2026-08-13。`packages/engine/src/observationDefaults.ts`（27 テスト）。

`estimateObservationDefaults(plan, roomType)` と
`estimateGuestCount(plan, roomType)`。DB・fetch・`Date.now()` を持たない。

- **空室**（稼働予定があり、退室も連泊も無い）→ 全項目 0 / ゴミ `NONE`。
- **稼働**（退室 or 連泊）→ 人数ぶんのタオル類、ベッドは
  `min(人数, ベッド数)`、バスマット 1、ゴミ `NORMAL`。
- **連泊**は稼働と同じ値。§3.3 の分岐が「空室か否か」の 2 つしか無く、
  連泊専用の式を独自に作らない（§12 の未決事項に触るため）。
- **稼働予定が無い**場合は稼働側に倒す。タスクがある部屋を全 0 で
  確定させると「使用実績なし」が残るため。人数は
  `guestCount` → `capacity` → `bedCount` → 1 の順で落ちる。

仕様 §3.3 が `...` で省いた 4 項目（ハンドタオル・スリッパ・グラス・
追加布団）の既定は DECISIONS #094 で決めた。
**アメニティ（`amenitiesUsed`）の既定値は作っていない。**
施設ごとに有効な品目が違い、この関数は品目一覧を知らない。M-05b（P3-04）で扱う。

仕様の `roomType.standardCapacity` は実際の列名では `capacity`。
