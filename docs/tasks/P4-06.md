## 作業ログ

### 2026-08-14
- API `GET /api/v1/findings`（`routes/api/v1/findings.ts`）と
  画面 `/app/audit/findings`（`routes/app/findings.tsx`）。
- `CLEANER` / `INSPECTOR` は `finding.read` が `DENY` なので
  `assertPermission()` が `NotFoundError` → **404**。DB へ 1 件も行かない
  ことを `findings.spec.ts` で固定した（存在を推し量れる差を作らない）。
- 「全施設」は `ORGANIZATION_TARGET` に対する判定なので、
  `PROPERTY_MANAGER` / `VENDOR_ADMIN`（`ASSIGNED`）は施設を指定した
  ときだけ読める。§6.4 の △ をそのまま写した形。
- 抑制の件数は `reconciliationRun.findingsSuppressed` の合計
  （`sumSuppressedFindings()`）。**差異の表からは数えられない**
  （抑制はルールを呼ぶ前に効くので行が残らない）。同じ施設・同じ業務日に
  `engineVersion` 違いの Run が並ぶと二重に数えるため、
  施設 × 業務日の最大値を採ってから合計している。
- 並びは `compareFindingsForDisplay()`（重要度 → 業務日 → 確信度 → ID）。
  リポジトリでは並べられない（`severity` は text で昇順が
  `HIGH < LOW < MEDIUM`）。`findings.spec.ts` が 7 件で固定。
- サイドバーの `nav.findings` を `READY` にした。`nav.findingDetail` は
  `PLANNED` のまま（ID の無いサイドバーから詳細は指せない）。
