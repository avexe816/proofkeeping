# PF-13 監査と法令（画面 11 / 一時アクセスの手続）

**系列**: PF（起票 2026-08-20） **依存**: PF-01 **見積**: 2日 **ステータス**: 未着手
**仕様**: `ui-prototypes/platform/pkplat-D-contract-audit-config.html` 11 / route `/plat/compliance`
**契約**: `docs/PK-IMPL-CONTRACT.md` **INV-10**

## 背景
運営は技術的にはテナントのデータへ到達できてしまう。**手続と記録で縛る**のがこの画面。
プロトタイプの文言がそのまま INV-10 の条件になっている。

> **運営側は清掃員の個人情報を自由には見られません**
> 技術的には可能なので、手続と記録で縛ります。必要な場合だけ、理由と承認を残して時間を限りアクセスします。

## やること

### `platform_access_grant`（SHARD_00）
| 項目 | ルール | 画面上の扱い |
|---|---|---|
| 理由の記録 | 必須 | 申請時に自由記述と対象範囲を残す |
| 承認者 | **2 名** | 申請者以外の 2 名が承認する |
| アクセス時間 | **最長 4 時間** | 終了時刻を自動で固定する |
| アクセス記録 | **削除不可** | 対象・理由・承認者・開始と終了を保存する |

**この 4 つを全部満たすまで開始できない。**

### 画面
- KPI 4: 直近のアクセス / 開示請求 / 清掃員本人 / 平均所要時間
- 表「🔐 顧客データアクセスの手続」（上の 4 行をそのまま）
- 表「📋 直近のアクセス記録」（日時 / 対象テナント / 理由 / 承認者 / 所要時間）
- カード「📨 開示請求を機能周知度の指標にする」
- 表「🗄 保存期間」（写真 90 日 / 清掃記録 3 年 / 請求関連 7 年 / **監査ログ 5 年・削除不可**）

## やらないこと
- **在留資格へのアクセス**。INV-08 が運営を名指しで除外しており、
  INV-10 の一時アクセスでも開かない（OPEN_QUESTIONS #110）
- 承認 1 名での開始、4 時間を超える延長、記録の削除・訂正

## 完了条件
- [ ] 理由・承認 2 名・4 時間の 3 つが揃わないとアクセスが始まらない
- [ ] 承認者に申請者本人を含められない
- [ ] 4 時間で自動的に失効する（終了時刻が申請時に固定される）
- [ ] `platform_access_grant` と `platform_audit_log` に UPDATE / DELETE の関数が無い
- [ ] 在留資格の列が一時アクセスでも返らない
