## やること
- KPI 4: 配信中 / 下書き / 既読率（清掃員）/ 今月の配信
- 表「📢 お知らせ一覧」（件名 / 対象 / 翻訳 / 既読率 / 状態 / 配信日）
- 表「📝 下書きの翻訳状況」（言語 / 状態 / 確認者）— 7 言語
- カード「📐 配信の設計」トグル 4 つ（すべて ON が既定）＋「お知らせの書き方」4 項

## 配信の規則（**トグルの既定を OFF にしない**）
1. 清掃員向けは**全言語完了後**に配信（一部言語のみでの配信を防ぐ）
2. 緊急時のみ日本語＋英語で先行配信
3. **既読を強制しない**（既読するまで操作できない画面を作らない）
4. **既読率を個人別に集計しない**（全体の既読率のみ）

## 逐語で置く注記
> **清掃員向けのお知らせは7言語で配信します**
> 日本語のみで配信すると、利用者の93%に伝わりません。翻訳が完了していない言語がある場合、その言語の利用者には配信されず、翻訳完了後に配信されます。

> **既読率78.2%を100%にしようとしません**
> 既読を強制すると、作業開始前に閉じるだけの操作が増えます。読まれるお知らせは短く、頻度を抑えることで実現します。

## やらないこと
- **個人別の既読集計**（security.md §5）
- 既読を強制するモーダル
- 機械翻訳をそのまま清掃員へ配信すること（現場確認を経る）

## 完了条件
- [ ] 未翻訳の言語の利用者へ配信されない（翻訳完了後に追いかけて配信される）
- [ ] 既読率が全体でしか出ない（個人別の口が無い）
- [ ] 既読しないと閉じられない画面が無い
- [ ] 通知が届かなくても業務が成立する（ui-writing.md §6）
