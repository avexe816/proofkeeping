### 走査で見つかったこと（§6.4 の再検証の中身）

**全 API 37 本・全画面 24 枚を走査した。** `assertPermission()` を
呼んでいない経路が 6 本見つかり、**すべて別の守りがあることを確かめて**
理由付きの免除にした。

| 経路 | 守り |
|---|---|
| `properties.ts` | 第 1 層が到達できる施設だけを返す（`listSelectableProperties`） |
| `evidenceList.tsx` | 第 1 層が絞る（`listEvidenceForProperty`） |
| `propertyBoard.tsx` | 到達できない施設は第 1 層が `NotFoundError`（INV-31） |
| `orgDashboard.tsx` | `ScopeForbiddenError` を捕まえて戻す |
| `dashboard.tsx` | loader を持たない。文言だけの画面 |
| `switchProperty.ts` | 第 1 層が絞る |

**免除は `Record`（理由を必ず書く形）にしてある。** `Set` だと理由の
無い免除が増える。**第 1 層に頼る免除が 1 本を超えたら三重防御を
読み直すこと**（spec が本数を固定している）。

### §6.4 の重点確認 5 件

4 件は `permission.spec.ts` が既に押さえていた。**5 件目
（`VENDOR_ADMIN` が受託外施設を見られない）はマトリクスでは表せない**
（action の可否ではなく見える施設の範囲の話）ので、`base.ts` の
`ORG_WIDE_ROLES` に載っていないことを確かめる形にした。
**名指しの除外ではなく「組織全体ロールに載っていない全ロールが絞られる」**
向きなので、ロールを足したときに既定で絞られる。

### 宿泊者の個人情報（§6.2 MUST）

**全 71 表の全列を走査。** 氏名・連絡先・住所・パスポート・カード番号に
当たる列は 1 つも無い。語彙に当たった 6 列はいずれも別物で、理由付きで
例外にした。

- `guest_count` 4 列 → **宿泊人数。個人を特定しない**
  （security.md §3 が「人数と予約参照番号のみで足りる」と明示）
- `credit_note_for_id` / `is_credit_note` → **赤伝**（billing.md §2）。
  クレジットカードとは無関係

**氏名・連絡先の例外は 1 つも無い**ことを spec が固定している。
忘れ物の所有者情報が無いこと・EXIF GPS の列が無いことも併せて確かめた。

### gitleaks は公式 action を使わない（DECISIONS #170）

最初 `gitleaks/gitleaks-action@v2` を置いたところ、CI が **403
`Resource not accessible by integration`** で落ちた。PR のコミット一覧を
GitHub API から引くため `pull-requests: read` が要る。

**検査そのものに API は要らない**（履歴はローカルに在る）ので、
CLI を docker で直接動かす形に変えた。権限を広げるより、要らない依存を
外すほうが安い。`--redact`（**見つかった値をログに出さない**）と
`--exit-code 1`（**報告するだけにしない**）を付けてある。
