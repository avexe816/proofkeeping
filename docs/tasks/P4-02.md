
**冪等は一意索引だけに頼っていない。** `upsertOccupancySnapshots()` は
既存行を先に読み、**内容が同じ行には書き込みを 1 文も出さない。**
3 回取込んでも行が増えないだけでなく `importedAt` も動かない（§10.2）。
「INSERT が 3 回走って 2 回落ちる」形も冪等には見えるが、それだと
いつ入った記録なのかが読めなくなる。

**取込元ごとに別の行**（DECISIONS #106 / 仕様どおりの `uq_occ`）。
PMS と CSV が食い違ってもどちらも残す。どちらを採るかは P4-05 で決める。

**`is_occupied` だけは既定値に倒さない**（DECISIONS #107）。空欄や未知の
表記を「空室」と読むと、**その部屋は使われていないという主張**になり、
R001（稼働記録のない使用痕跡）が根拠のない差異を出す。読めない行は
取り込まず、行番号を返す。他の列は `lib/plan/csv.ts` と同じで、
1 行の誤りで全体を落とさない。

**CSV の字句解釈を `lib/csv/reader.ts` へ切り出した。** 取込の口が
2 つになったので、行の割り方・BOM・真偽値の解釈を 1 か所に置いた。
`lib/plan/csv.ts` はそれを使う形に変えてある（**挙動は変えていない**。
既存の 16 テストがそのまま通る）。

**差分は `occupancy.imported` として監査ログに残す**（§8.1 MUST）。
`AUDIT_ACTIONS` に 1 行足した。**内容が変わらない再取込では書かない。**
3 回取込むたびに 3 行増えると、本当に上書きが起きた回を探せなくなる。
差分の内訳は `MAX_AUDIT_CHANGES`（100）で頭打ち。監査ログは消せない
永続データなので、5,000 室ぶんの内訳をそのまま載せない。件数は必ず残る。

**権限は `occupancy.read` / `occupancy.write` を足した。** §6.4 の権限表に
稼働記録の行が無いため、当日の客室状況（`roomPlan.*`）と同じ配り方に
した。**`CLEANER` / `INSPECTOR` は 404。**

**§8.1 に無い列は埋めていない。** `adultCount` / `childCount` /
`channelCode` / `ratePlanCode` / `isComplimentary` は CSV に列が無いので
既定のまま。推測で割らない。
