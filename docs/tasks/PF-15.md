## やること

### `platform_health_sample`（SHARD_00）
`checkHealth()` の結果を**時間単位に丸めて**溜める。
列: `id` / `hourStartMs`（時間の先頭）/ `state` / コンポーネントごとの状態 /
`createdAt`。**同じ時間に 2 行作らない**（`hourStartMs` で一意）。

### `platform_incident`（SHARD_00）
事象履歴。**必要最小限。** 列: `id` / `startedAtMs` / `resolvedAtMs` /
`component` / `note` / `createdAt`。

**開いている事象は 1 コンポーネントにつき 1 件。**
`degraded` を最初に観測したときに開き、`ok` に戻ったときに閉じる。

### 収集
- **既存の cron に相乗りする**（`*/10 * * * *` の 10 分ごとの回）。
  新しい cron 式を足さない（DECISIONS #232 と同じ判断）。
- 1 回の実行で `checkHealth()` を 1 度だけ叩き、時間の行を UPSERT する。
- **再計算方式**。同じ時間に何度走っても行が増えない（testing.md §4）。

### 集計の読み出し
- **稼働率** = 期間内の `ok` の時間数 ÷ 記録のある時間数。
  **記録が無い時間を分母に入れない**（デプロイ前の期間を「落ちていた」に
  しない）。記録が 0 時間なら `null`（**0% にしない**）。
- **事象件数** = 期間内に開いた `platform_incident` の数。
- **事象履歴** = 新しい順。**書き込みの口を画面に作らない。**
- **最終更新日時** = いちばん新しい `hourStartMs`。

## やらないこと（**DECISIONS #238 が明示的に禁じたもの**）
- **リクエスト単位の生ログを無期限に保存すること。** 持つのは
  時間単位・日単位の集計と、必要最小限の事象履歴だけ
- **p95 とエラー率**。リクエストごとの計測が要り、集計だけでは作れない
- **Analytics Engine の導入**
- 計測できない指標を 0 や仮値で埋めること（**「未計測」と明示する**）
- シャード番号・内部ホスト名を列や応答に出すこと（architecture.md §1）
