# PF-19 運営面の 2 段階認証を切り替え可能にする

**系列**: PF（起票 2026-08-21 / オーナー指示） **依存**: **PF-17**
**見積**: 0.5 日 **ステータス**: 実装済（**staging は 2026-08-22 に再有効化済み**）

## 背景
staging で TOTP の登録が繰り返し通らず、開通した運営担当者が `/plat/*` へ
入れないままになった。**実装を消さずに要求を止める**（DECISIONS #250）。

## 2026-08-22 追記 — **無効化は解除した**

**staging の `PLATFORM_2FA_REQUIRED` を `"true"` へ戻した。** 無効化は
一時的な措置で、役目を終えている。

原因は **端末の時刻ずれ系**（TOTP のコードが合わない）だった。
**登録そのものは成功していた** — 監査ログの並びが次のとおり（JST）。

```
01:10:42  platform.bootstrap.completed
01:14:34  platform.2fa.failed (enroll)
01:36:50 / 01:37:07 / 01:37:10 / 01:38:18  platform.2fa.failed (enroll)  … 計 5 回
02:23:20  platform.2fa.enrolled (recoveryCodes: 10)
02:23:20  platform.login (secondFactor: TOTP)
```

**5 回でロックに当たり、15 分ではなく 45 分空けてから成功している。**
PF-19 の merge は 02:26 で登録成功の約 3 分後なので、**結果として
無効化する必要は無かった。**

### 監査ログでの切り分けが効いた

`platform.2fa.failed` が**残っているかどうか**で 2 つを区別できる。

| | 時刻ずれ（今回） | 札の 10 分の期限切れ |
|---|---|---|
| `2fa.failed`（`phase: "enroll"`） | **行が残る**（検証まで届く） | **1 行も残らない**（404 で検証に入らない） |

この手順は runbook §10 の「登録に失敗するときに確かめる順序」の裏付けになった。

### 残したもの

**スイッチの実装（`lib/platform/twoFactorPolicy.ts`）は消していない。**
production は引き続き値を読まずに `true` 固定。再び止めるときは
`wrangler.toml` の 1 行と `tests/toolchain/wrangler.spec.ts` の期待値を
一緒に動かす（runbook §10）。

## 穴を作らないための線引き
- **門（`COMPLETE` の札を要求すること）は畳まない。** 外すのは
  `twoFactorConfirmedAt === null` の 1 行だけ
- 切替前に出た `PASSWORD_ONLY` の札は `false` でも 404
- セッションの寿命は 12 時間のまま（`state` が決める）
- **production は `false` にできない**（コードで固定）
