# P5-19 請求確認画面（月次締めの双方合意）

**Phase**: P5 の拡張（追加起票 2026-08-19 / P5-16〜18 と同じバッチの継続）
**仕様**: docs/PK-SPEC-P5.md §6（双方合意）・§9（API は実装済み）
**依存**: P5-12（合意 API・履歴）/ P5-16（CLIENT_VIEWER）/ P5-17（メールリンク）
**見積**: 1日
**ステータス**: 実装済み（2026-08-19）

## この task が起票された理由

OPEN_QUESTIONS **#082**: 月次締め（billingPeriod）は API（P5-05 / P5-12）だけが
あり、**PC の画面が無い**。組織ダッシュボードの「未締めの請求期間」は件数だけで
リンク先が無かった。さらに P5-16 で発注元ロール（CLIENT_VIEWER）を作ったのに、
**発注元がログインして承認・差戻しを行う画面が無く**、メールリンク（P5-17）しか
経路が無かった。

## 読むべきルール
- `.claude/rules/billing.md`（帳票・履歴の扱い）
- `.claude/rules/security.md` §1（CLIENT_VIEWER の境界・404）
- `docs/PK-IMPL-CONTRACT.md` §4（発注元の権限）

## やること

### 1. 共有実装への抽出（画面より先）
- `routes/api/v1/billingPeriods.ts` の `loadPeriodWithDraft()` / `snapshotOf()` /
  合意・差戻し・確認依頼の本体を `lib/billing/review.ts` へ移す。
  **同じ操作の入口が 3 つ**（API・画面・メールリンク）になるため、
  「合意した瞬間の明細を履歴に固定する」（§6.2 MUST）を 1 か所に寄せる
  （`lib/staff/register.ts` / DECISIONS #181 と同じ向き）。
- API とメールリンク（`routes/review/billingReview.tsx`）を共有実装に配線し直す。
  HTTP の応答（404 / 409 / 400）と履歴・監査の中身は変えない。

### 2. 画面 `/app/billing-periods`
- 一覧（取引先 × 期間 × 状態）＋ `?period=` で明細・履歴・操作。
- 門: 閲覧 `billing.read`（発注元はリポジトリ層が自分の取引先に絞る）/
  合意・差戻し `billing.review` / 確認依頼 `billing.write`。
- 明細は `buildPeriodDraft()`（発行と同じ計算）。単価未設定の警告を出す。
- 履歴に **actorId（個人）を出さない**（発注元にスタッフを特定させない）。
  主体は「発注元 / 組織内」の 2 値。
- 差戻しは理由必須。REVIEWING 以外に操作を出さない（押して 409 の導線を作らない）。

### 3. 導線
- サイドバー `nav.billingPeriods`（analysis / `billing.read` / BILLING）。
  **発注元に出る唯一の請求系項目**（`nav.billing` は billing.readInternal のまま）。
- 組織ダッシュボードの「未締めの請求期間」に `href` を配線（#082 の暫定対応の解消）。

  期間全体のコメントのみで開始する（API は `lineComments` 対応済み。
  需要を見て起票）。
- **忘れ物・設備不具合の PC 一覧。**（OPEN_QUESTIONS #082 の残り半分。P7 で起票）
- **証跡ドリルダウン（明細行 → タスク一覧）の画面。** API（P5-13）はあるが、
  画面は証跡一覧（W-06）への導線で代替する。
