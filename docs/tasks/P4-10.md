## 作業ログ

### 2026-08-14
- API `GET / POST /api/v1/room-access-logs` と
  リポジトリ `createRoomAccessLog()` / `listRoomAccessLogs()`（期間対応）。
- **事前・事後の両方を受ける**（§2.3）。`enteredAt` は過去 90 日
  （照合の遡及と同じ幅）・未来 30 日まで。未来側を無制限にしないのは、
  押し忘れた登録が抑制として効き続けるため。
- **業務日を受け取らない。** `enteredAt` と施設の日締め時刻から
  サーバーが決める（architecture.md §7）。入室した日と抑制が効く日を
  別々に指定できる経路を作らない。
- **更新・削除の口が無い。** この表は差異を抑制する根拠（§4.1）で、
  後から書き換えられると「抑制されたのは登録があったからか、
  登録が消えたからか」が読めなくなる。訂正は正しい記録を足す運用。
- 抑制そのものは P4-03 で実装済み（`suppression.ts` の
  `ACCESS_LOG_REGISTERED`）。R001 もルール単体で同じ結論を出す
  （`R001.ts` の `accessLogs.length > 0`）。両方に既存のテストがある。
- `actorId` を書いていない。立ち入るのは外部業者のこともあり、
  組織内の `membership` に必ず対応するとは限らない。名前だけ残す。

## 止まらずに判断したこと

  照合される側（現場ロール・受託先）には与えていない。
