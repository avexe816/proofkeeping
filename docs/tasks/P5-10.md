## 作業ログ

- `lib/billing/webhookSignature.ts` — Svix の HMAC-SHA256 検証。
  **鍵が未設定なら通さない**（設定漏れが「誰でも叩ける」として
  現れないようにする）。5 分の窓は**未来方向も**拒否。
  署名の比較は長さに依らない時間で行う。
- `lib/billing/webhookEvent.ts` — payload の読み取り。
  **不達の理由に宛先も本文も入れない。**
- `routes/api/v1/webhooks.ts` — **セッションを持たない経路**（`app` 側、
  認証 middleware の前段）。守っているのは署名。
  受信は 200 を即返し、処理は Queue（security.md §7）。
  `getNow(c)` を使わないのは、`now` を積むのが session middleware だから。
- `consumers/notification.ts` — 組織の解決（`lookupOrganizationId()`）は
  **コンシューマ側**。あれは「リクエストハンドラから呼ばない」と
  定められている（`orgDirectory.ts` の注記）。
- `routes/api/v1/deliveries.ts` — 送付履歴と**不達の一覧**。
  `/failed` を `/` より前に置く（Hono は先に一致した経路を使う）。
- 送信の順序を変えた。**先に送付ログを起こしてから Resend を叩く**
  （ID を渡す必要があり、送ってから採番すると webhook が先に
  届いたときに引けない）。
