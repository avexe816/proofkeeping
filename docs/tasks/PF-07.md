## 逐語で置く注記
> 誤検知率の目標は重要度ごとに異なります。HIGH は10%以下、MEDIUM は30%以下、LOW は40%以下です。HIGHの誤検知はオーナーが宿泊者に問い合わせる可能性があるため、最も厳しく設定しています。

> **誤検知の多くは記録側の問題です**
> 上位3件（フロント記録の不備・運用上の使用・デイユース漏れ）はいずれもPMS側の記録に起因します。エンジンの改善だけでなく、導入時にPMS運用の確認を強化することが有効です。

## 語彙（**プロトタイプをそのまま使えない唯一の点**）

プロトタイプは「誤検知率」を全面に使うが、**`検知` は禁止語**
（ui-writing.md §2 / ESLint `pk/no-forbidden-words` / CI の grep）。
CLAUDE.md §4 の絶対禁止は**プロトタイプに優先する**（差分台帳の方針どおり）。

既存の実装は `FINDING_STATUSES` の `FALSE_POSITIVE` を
**`finding.status.falsePositive` = 「対象外」**と訳している。これに揃える。

| プロトタイプ | この画面で使う |
|---|---|
| 誤検知率 | **対象外率** |
| 誤検知の原因 | **対象外とした理由** |
| HIGH の誤検知 | **HIGH の対象外** |
| 正しい検出 | **要確認だったもの** |

**辞書のキーだけでなく、画面・API 応答・PDF のすべてで揃えること。**
