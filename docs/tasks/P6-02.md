## 作業ログ

2026-08-14 完了。`apps/web/src/lib/integration/credentials.ts`。

**KV に置くだけでは足りない。** `CREDENTIAL_ENCRYPTION_KEY`（既に `EnvSecrets`
にあった）で AES-GCM 暗号化する。KV のダンプが 1 本流出しても、それだけでは
外部システムへ到達できない。保存形式は `pkenc$v1$<iv>$<ciphertext>` の
自己記述文字列（`pbkdf2$...` と同じ形。鍵の交代を段階移行できる）。

**AAD に参照キーを入れた。** 暗号文を別の KV キーへコピーしても復号できない。
「他組織の連携に自分の資格情報を差し込む」経路が塞がる。

**参照キーに組織を焼き込んだ**（`cred:{orgShortId}:{integrationId}:{slot}`）。
KV は 16 シャードの外側にあり全組織で 1 namespace を共有するので、
`assertCredentialRefBelongsToTenant()` が KV を引く前に落とす。
**403 ではなく `NotFoundError`。**

**TTL を付けない。** 失効すると連携が「設定済みなのに認証できない」状態に
静かに落ちる（`SHARD_MAP` と同じ理由 / architecture.md §1）。

枠は 2 つ（`API` / `WEBHOOK`）。外部へログインする値と、受信した署名を
検証する鍵は用途が違うので同じ封筒に入れない。
