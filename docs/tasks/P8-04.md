# P8-04 スキルと言語を自動配分へ反映する

**Phase**: 8（起票 2026-08-20 / DECISIONS #219）
**仕様**: `docs/PK-SPEC-P8.md` §1.7 / `ui-prototypes/ops/pkops-A-daily-quality.html` 02（自動割当のルール）
**依存**: P8-01 / P8-03
**見積**: 1日
**ステータス**: 実装済み（2026-08-20）

## 背景
プロトタイプ 02 のカード「⚙️ 自動割当のルール」が持つ 5 行のうち、
P1-14 の自動配分に効くのは 3 つ。

| 項目 | 説明（逐語） | 既定 |
|---|---|---|
| 同一施設内でまとめる | 移動時間を最小化します | ON |
| 経験年数を考慮する | 1年目には難易度の高い客室を割当てません | ON |
| 前回の担当を優先する | 客室に慣れた人を割当てます | OFF |

残り 2 つ（上限 16 室・連続 5 日）は**数値表示のみで、ここから変えない。**

## やること
- `staffProfile.skills` に無い作業を割り当てない（仕様 §1.7）
- `hiredOn` から在籍年数を出し、「経験年数を考慮する」が ON のとき
  1 年目に難易度の高い客室（`roomType` の標準時間が上位）を割り当てない
- 在留資格が期限切れのスタッフを**新規配分の候補から外す**（P8-02 と接続）
- 判定は `packages/engine` の純粋関数に置く。**DB・`Date.now()` を持ち込まない**

## やらないこと
- スキルの自動判定・学習（CLAUDE.md §4「AI による自動判定を実装しない」）
- 個人の速度を根拠にした配分（security.md §5）

## 完了条件
- [x] スキル外の作業が割り当たらない（正例・負例 5 件ずつ / testing.md §3。
      `packages/engine/src/assignment.spec.ts` に 10 件）
- [x] 1 年目に高難度の客室が割り当たらない（高難度 = **特別清掃（DEEP）**。
      客室ごとの難易度の指標がどこにも無く、推測のスコアで選別すると
      「なぜこの部屋が高難度なのか」を説明できないため、作業種別で表す）
- [x] 期限切れのスタッフに新規タスクが割り当たらない（P8-02 で実装済み）
- [x] シフト・スキルが未登録でも従来どおり配分できる（**未入力を制約に
      しない** — 台帳なし・入社日なし・スキル空はすべて「制約なし」）

## 作業ログ

- 2026-08-20 実装。engine の `planAutoAssignment()` に**データとしての
  適格判定**を足した（`skills` / `avoidHardTasks` / `hardTaskTypes`）。
  **engine は在籍年数も研修も知らない** — 「1 年目か」は
  `lib/staff/traits.ts`（純粋関数）が台帳から導き、`assign.ts` が
  候補へ写す。研修中（`workStatus = TRAINING`）は自動配分の候補から
  外す（プロトタイプ 08「研修中は同行作業のみとし自動割当から除外する」。
  **手動の割当は通す** — 同行での割当は責任者の判断）。
- **トグルの保存は作らなかった。** プロトタイプの「経験年数を考慮する」は
  ON が既定で、OFF にする口を作ると設定の保存先が要る。常時 ON とし、
  必要になったら PF-14 の「運用（変更可）」に載せる（簡素化）。
  「前回の担当を優先する」（プロトタイプで OFF）も作っていない。
  「同一施設内でまとめる」は配分が施設ごとの操作なので既に満たされている。
