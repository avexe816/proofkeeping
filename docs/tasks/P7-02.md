## 実装計画

1. **QR の符号化**（純粋・ブラウザで動く）
   - バイトモード・誤り訂正 M・自動バージョン選択で足りる
     （載せるのはログイン URL 1 本）。
   - **誤った QR は「読めない」より悪い**（別の場所へ飛ぶ）。
     符号語列の検証を spec で持つこと。既知のベクタと突き合わせる。
2. **印刷用の画面**
   - `cleaner-guide.html`（P7-15）と同じ作り。`@page` は A4、余白 0。
   - **PIN は画面を生成するリクエストの中だけ。** loader へ渡さない
     （loader は GET で、URL にも履歴にも残る）。
   - スタッフを登録した直後の `action` の戻り値としてだけ現れる。
3. **走査で押さえる**
   - `pk-pdf-generation` へ案内カードを投げていないこと。
   - PIN を `recordAudit` / `console` / R2 へ渡していないこと。

## 前提

- スタッフの登録は `POST /api/v1/users`（P7-01）。**PIN はその応答に
  1 回だけ現れる**（DECISIONS #177）。**保存し直さないこと。**
- 登録の**画面**はまだ無い（OPEN_QUESTIONS #103）。この task で
  画面を作るなら、そこが案内カードの出口になる。

| ファイル | 役割 |

| `tests/security/initialPin.spec.ts` | **PIN の経路を走査で固定** |

- QR の検証は 122 件（`gf.spec.ts` / `encode.spec.ts`）。
  **spec 側に独立した読み取り器**を置き、符号化した行列から元の文字列を
  復元できることを版 1〜10 すべてで確かめている。加えて
  ISO/IEC 18004 の既知値（版 1-M の誤り訂正符号語・形式情報表 C.1・
  版情報表 D.1）と突き合わせている。
- **実際に 1 つ踏んだ。** ジグザグ走査で 6 列目（タイミングパターン）を
  避けるとき、列を一時変数で逃がすと以降の列の対が 1 つずれ、
  **4 列目を 2 度書いて 0 列目を書かない**状態になる。訪問の総数は
  変わるので `freeModuleCount()` の検算では気づけない。読み取り器が
  落として見つかった。同じ誤りを直接押さえる spec を足してある。
- 登録の実装を `lib/staff/register.ts` へ寄せた（DECISIONS #181 と同じ向き）。
  これに伴い `tests/security/accessMatrix.spec.ts` に**委任**の仕組みを
  足した。**免除ではない**（委任先が `assertPermission()` を呼ぶことを
  テストが追いかける）。
- `setup.tsx` の `STEP_HREF.staff` を繋いだ（OPEN_QUESTIONS #103 の半分が解消）。
