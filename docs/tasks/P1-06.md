### 2026-08-12（2）— W-16 の画面（DECISIONS #048 / #049 / #051）

**やったこと**

- `/app/settings/checklists`（`apps/web/src/routes/app/checklists.tsx`）。
  3 階層（組織共通 / 施設別 / 客室タイプ別）を**浅い順**に並べる。
  入れ子の見た目で階層を表さない。
- **「この施設で使用中」の印を付ける**。表示中の施設について
  `resolveEffective()` → `resolveTemplate()`（`@pk/engine`）を通す。
  **生成と同じ関数**を使う（判定の実装を 2 つ持たない）。並べただけでは
  「結局どれが現場に出るのか」に答えられない。
- 項目は **1 行 1 項目のテキスト**で編集する（DECISIONS #051）。
  書式は `セクション / 項目名 / 必須または任意 / 写真`。項目名に `/` を
  含めるときは `//`。読めなかった行は行番号で返す。
- 保存は `replaceTemplateItems()`。**版が 1 つ上がることを画面に明示する。**
  すでに展開済みのタスクは `templateVersion` で当時の版のまま。
- **訳文（`labels.en`）を日本語ラベルの一致で引き継ぐ**（`mergeTranslations()`）。
  管理画面は日本語のみ（§12.1）でこの画面から訳を入れられないため、
  項目を保存するたびに訳が消えるのを防ぐ。並び順で対応づけると
  行を 1 つ挿入しただけで以降の訳がずれる。
- 無効化は `deactivateTemplate()` のみ。**削除の口を作らない**
  （過去の `taskChecklistResult` が項目行を参照している）。
- ロジックは純粋関数（`apps/web/src/lib/checklist/settings.ts` ＋ spec 34 件）。

**完了条件（追加分）**

- [x] 3 階層の継承が画面から読める → 階層ごとの節＋「この施設で使用中」の印。
- [x] 版が上がることが画面から読める → 保存ボタンの文言と注記。

**判断したこと（追加分）**

1. **一括で必須を付け外しする欄を置かない。** §6.3 の「すべてチェック」を
   置かないのと同じ理由で、必須をまとめて外せる操作は記録の質を落とす
   方向にだけ効く。
2. **新しいテンプレートの施設 ID をフォームから受け取らない。** 表示中の
   施設（セッション）から解く。客室タイプもその施設のものに限る（INV-32）。
3. 未翻訳の件数を出す（§12.2）。**項目名の横の「日本語のみ」は M-04 側**で、
   ここは件数だけ。
