## やること
### サーバー側検証
- `taskId` から `propertyId` を解決
- `membership.allowedPropertyIds` に含まれるか検証
- 含まれなければ **404**（403 ではない）
- 送信時にクライアントから送られた `propertyId` を信用しない

### UI 側
- M-03 の上部に施設名を常時表示（部屋番号だけにしない）
- 前のタスクと異なる施設のタスクを開始する場合、施設名を含む確認を 1 回出す
- 同一施設内の連続タスクでは確認を出さない（1タップ開始を維持）
- M-11 に施設別内訳を追加（自分の分のみ）

## 完了条件
- [x] 担当外施設の `taskId` で `start` すると 404
      → `runTransition()` が `findTaskById()` で解決した施設で
      `assertPermission()` を掛ける（P1-05 から）。**404。403 ではない。**
      `routes/api/v1/tasks.spec.ts` に検査を足した（これまで無かった）。
- [x] クライアントから送られた `propertyId` を信用していない
      → `taskTransitionRequestSchema` に `propertyId` が無く、送られても
      Zod が落とす。担当施設を名乗っても 404 になることをテストで固定した。
- [x] M-03 の上部に施設名が常時表示される
      → `pk-m-head__property`。**部屋番号より上**に置いた（§19.8）。
- [x] 施設が変わるタスクの開始時に確認が 1 回出る
      → `lastWorkedPropertyId()`（直前に手を付けたタスクの施設）と比べる。
      P1-21 の並び順ベースの判定を置き換えた（DECISIONS #045）。
- [x] 同一施設内の連続タスクでは確認が出ない
      → 同上。押した直後は手元の値で上書きし、2 件目に出さない。
- [x] M-11 に施設別内訳が表示される
      → 「施設別（今月）」。**2 施設以上のときだけ**・件数のみ（DECISIONS #047）。
- [x] M-11 に他人との比較・ランキングがない
      → `summarizeOwnWorkByProperty()` は担当者 ID も比較対象も引数に取らない。
      集計の入力は `listTasks({ assigneeId: 自分 })` のみ。
- [x] 「個人の評価には使用されません」の注記がある
      → `m.me.noComparison`（P1-17 から。**この 1 行を消さないこと**）。
