**① 一括承認の削除（§13.1）**

W-03 に「一括で検査済にする」の**画面も API も無かった。** P1 が作らなかった。
残っていたのは受け皿だけで、次の 3 か所を消した。

- `packages/engine/src/roomStatus.ts` … `RoomStatusTrigger` の `bulkApprove`
- 同 `housekeepingStatusFor()` の `case "bulkApprove"`
- `packages/db/src/repositories/audit.ts` … `task.bulkApproved`

監査ログの `AUDIT_ACTIONS` は「一度使った文字列を変えない」規則を持つが、
**`task.bulkApproved` は一度も書き込まれていない**（到達経路が無かった）。
既存の監査ログに現れない値なので消した。security.md §6 の列挙には
「一括承認」の語が残っている。文書側の扱いは人間の判断を待つ。

型は実行時に消えるので、`housekeepingStatusFor("bulkApprove", true)` が
`undefined` を返すことを見るテストを添えた。ここが緑でなくなったら戻っている。

**② 検査方式の移行（§13.2 / OPEN_QUESTIONS #044）**

`0011_p2_16_inspection_policy_backfill.sql`。**手書きのマイグレーション**
（スキーマは変わらない。移すのはデータ）。

仕様の SQL は `gen_random_cuid()` を使う PostgreSQL 前提で、D1 には無い。
SQL で ULID は作れないので、**ID は施設 ID の ULID 部分を流用した。**

```
o7k2m9__prop_01JBXQ… → o7k2m9__ipol_01JBXQ…
```

1 施設 1 行なので衝突せず、決定的なので `WHERE NOT EXISTS` と合わせて冪等。
実 SQLite に 0000 + 0003 + 0007 の DDL を組んで流し、
**3 回流しても件数が変わらないこと・設定済みの施設（`SAMPLE`）が
上書きされないこと**を確認した。

対応は `policyFromLegacyFlag()` と同じ（`true` → `ALL` / `sampleRate 100`、
`false` → `NONE` / `sampleRate 0`）。同じ対応表が 3 か所にある
（engine / `packages/db` の `legacyPolicyValues()` / SQL）。
`@pk/db` を `@pk/engine` に依存させないための写しで、**揃えて変えること。**

**旧列 `property.inspectionRequired` は消していない**（architecture.md §6 の
3 段階の②）。読み取り側の `policyFromLegacyFlag()` も残した。
移行が届いていないシャードで既定の `ALL` に落ちると、
**全タスクが検査待ちで滞留する。** ③（旧列の DROP と関数の削除）は次リリース。

行が無い施設が生まれ続けると移行が終わらないので、`createProperty()` と
`seed()` が施設と検査方式を一組で書くようにした。

**③ 残存タスク（§13.3）**

2 経路を足した。

```
GET  /api/v1/inspections/stranded?propertyId=
POST /api/v1/tasks/:taskId/inspection/override   { "reason": "…" }
```

一覧は**業務日で絞らない。** 取り残しは古い日付に溜まるので、M-08
（その日の検査待ち）では見つからない。施設の検査方式を一緒に返す
（`NONE` の施設に残ったものは二度と検査されない）。

上書きは **1 件ずつ・理由必須・監査ログ。** §13.1 で消した一括承認を
名前を変えて戻さないため（DECISIONS #090）。配列も「施設ぶん全部」も
受け取らない。権限は新設の `inspection.emergencyOverride`
（施設責任者以上。**`INSPECTOR` は DENY**）。

書くのは `inspectionSkipped = true` と
`inspectionSkipReason = EMERGENCY_OVERRIDE` だけ。**`inspectionResult` を
書かない**（§2.3）。検査の行も作らない（§13.3「後付けで Inspection を
作らない」）。客室は `READY` へ進める（`INSPECTING` のまま残すと、
二度と検査されない客室が客室ボードで作業中に見え続ける）。

検査が始まっているタスクは横取りしない（`INSPECTION_ALREADY_STARTED`）。
再送は状態そのもので弾く（2 回目は `COMPLETED` かつ `EMERGENCY_OVERRIDE` を
見て `unchanged: true`）ので、`Idempotency-Key` の表を増やしていない。

**画面は作っていない**（OPEN_QUESTIONS #057）。移行のときにしか使わない
操作を管理画面に常設すると、「検査せずに閉じる」ボタンが残り続ける。

**止まらずに判断したこと**: DECISIONS #090 / #091。
