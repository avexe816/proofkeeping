`packages/db/src/env.ts` と `router.spec.ts` は allowlist 不要。前者の
`SHARD_00: D1Database` は `TSPropertySignature` であって member access ではなく、
後者は fake env を計算キー（`shards[key] = ...`）で組んでいるため。

`no-raw-drizzle` に `repositories/**` は**含めていない**。仕様 §19.4 の文面は
リポジトリを例外にできると読めるが、P0-07 のリポジトリは `getTenantDb()` から
db を受け取る設計で `drizzle(` を呼ぶ必要がない。含めれば穴が広がるだけ。

**適用範囲の与え方**
アーキ 2 本は全域が禁止・例外が数ファイルなのでルール側に allowlist を持たせた
（`files` override に散らすと「例外ファイルで警告が出ない」を RuleTester で
検証できない）。文言 2 本は適用対象がファイルの種類なので flat config の `files`
で絞った。`no-forbidden-words` を全 TS に当てないのは、PK-IMPL-CONTRACT §5.1 の
禁止語に「エラー」「失敗」「異常」が含まれ、`throw new Error` 周りの通常の
コードまで落ちるため。§5.1 自身が対象を「UI文言」と限定している。

**検出できないもの（意図的）**
- `env[key]`（キーを実行時に組み立てる形）は静的に追えない。これを行うのは
  router.ts 自身だけで allowlist 済み。ルールの doc コメントに明記した。
- PK-IMPL-CONTRACT §5.1 の「チェック（監視の意味）」は文脈依存で
  「チェックリスト」と区別できないため機械判定に載せていない。

**申し送り: `.tsx` は現在 ESLint で検査できない**（OPEN_QUESTIONS #001 に追記）
`apps/web/tsconfig.json` の `include` が `src/**/*.ts` のみで、`jsx` コンパイラ
オプションもどの tsconfig にも無い。`.tsx` を置くとルール実行前に parse error に
なる。`jsx` の値はフレームワークの決定に依存するため P0-04 では決めていない。
