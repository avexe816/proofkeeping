### 止まらずに判断したこと
- **#157 画面ではなく運用者の CLI にした。** §4.3 MUST の
  「管理者向けダッシュボード」と CLAUDE.md §4 の「シャード番号を露出しない」が
  衝突し、**運用者のロールがそもそも無い。** migration が
  「シャード番号を出力」する先例（architecture.md §6）に合わせた。
  認証機構を新設するのは仕様に根拠のない設計選択（workflow.md §6）。
- **#158 測れていない使用率を `ok` に混ぜない。** 0 で埋めると
  「空のシャード」と区別できず緑に見える。**いちばん危ないのは
  測れていないまま埋まっていくこと。**

### 残したもの
- **「常時表示」が満たせていない**（OPEN_QUESTIONS #095）。出し先が決まれば
  `collectShardUsage()` がそのまま繋がる形にしてある。
- §4.3 の監視項目のうち「**1 日の書き込み行数**」と「**平均クエリ時間**」を
  出していない。前者を数える表が仕様に無く（作ると仕様に無い表を足すことに
  なる）、後者は D1 が返す `meta.duration` の平均を貯める場所が無い。
  代わりに 1 回ぶんの計測時間（`probeDurationMs`）を持たせてある。
