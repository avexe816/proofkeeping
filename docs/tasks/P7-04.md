## この task を実装しない理由

オーナー指示（2026-08-20）が **「Stripe なしで、銀行振込式で」**。
`ui-prototypes/platform/` 12 画面の HTML 全文を検索しても
**Stripe / クレジット / カード / 決済 / 振込 / 口座 が 1 件も無い。**
画面 10「契約と収益」が持つのは**価格の台帳と集計だけ**で、
決済処理・支払方法の選択・カード登録の UI が 1 つも存在しない。

課金モデルも変わった。プロトタイプ（`REVISED`）は
**版数 × 客室数 ＋ 最低利用料**で、PK-SPEC-P7 §3.1 のモジュール別価格を
名指しで否定している（OPEN_QUESTIONS #108）。

## 引き取り先

この task の完了条件のうち**残るもの**は PF-12 が持つ。

| 元の完了条件 | 行き先 |
|---|---|
| Webhook でエンタイトルメントが即時反映される | **PF-12**。ただし Webhook ではなく**運営が契約を登録・変更したとき**に書く |
| 従量課金が「実際に使った室数」で計算される | **PF-12**。「当月に 1 回でも清掃タスクが発生した客室数」は変わらない |
| `PAST_DUE` でも 14 日間は全機能が使える | **PF-12**（PK-SPEC-P7 §3.4 は生きている） |

**この task を待って止まっていたもの**（エンタイトルメントの書き込みが
1 本も無い / PROGRESS.md 申し送り オ）は、外部の API キーを待たずに
PF-12 で解ける。
