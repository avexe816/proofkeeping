## 作業ログ

### 2026-08-12 実装

**枠組みだけを作り、個別画面の権限設定は各 task へ送った。**
`PERMISSION_ACTIONS` は 11 件。security.md §1 が「絶対に守る境界」として
明記した項目と、P0 に実体のある資源（組織・税務プロファイル・ユーザー・施設）に限る。
**PK-IMPL-CONTRACT §4 のビジネス表は 1 行も転記していない**（OPEN_QUESTIONS #011。
§4 の `OWNER` は security.md §1 の `OWNER` と別概念で、写像が推測になる）。
security.md §1 に根拠が無いセルはすべて `DENY` に倒した。

- `assertPermission(ctx, action, target)` は `void` を返し、拒否で `NotFoundError` を投げる。
  `boolean` を主にしないのは、`if (!can(...))` の書き忘れが型で通って素通りするため。
  `can()` は同じ表を引く従属関数（ナビの出し分け用）で、
  **フロントの非表示は権限制御とみなさない**（security.md §1）。
- マトリクスは `Record<PermissionAction, Record<Role, PermissionScope>>`。
  **セルの書き漏れはコンパイルエラー。** 既定値・フォールバックを持たない。
- `scopeToProperties()` は P0-07 のものを**変更していない。** P0-10 が作ったのは
  その入力（`ctx.allowedPropertyIds`）を毎リクエスト組み立てる経路。
- 拒否は一律 404（DECISIONS #022）。**403 を返す経路をコードベースに作っていない。**
  未定義の経路も `apiNotFoundHandler()` で同じ本体を返す（経路の実装有無を漏らさない）。
- 認証の失敗だけは 401。資源の有無を語らず、入り直せば直る種類の失敗のため。

**実装中に見つけた 3 点**（いずれも黙って壊れ、テストが無ければ気づけない）:

1. **Hono では `await next()` を try で囲んでも下流の例外を捕まえられない。**
   各ハンドラの呼び出しを Hono が内側で try/catch し、`onError` を適用してから
   上流へ戻すため。middleware で写像すると **404 のはずが 500 になる。**
   `app.onError()` / `app.notFound()` に登録する形へ直した。
2. **`c.req.param()` は `app.use("*")` の middleware から呼ぶと空になる。**
   マッチしたルートに紐づくため、middleware 自身の経路（`*`）には変数が無い。
   ここを見落とすと第 2 層の前半が丸ごと効かない。パスを `/` で割り、
   自己記述 ID の形（`__` を含む）をした区切りすべてを見る形へ直した。
   `%5F%5F` での回避を塞ぐため復号してから照合する。
3. **`app.route()` は子アプリの `notFoundHandler` を引き継がない**（`errorHandler` は
   包み直して保つ）。子に登録すると合成した瞬間に黙って効かなくなり、
   未定義経路だけ Hono 既定のテキスト 404 に戻る。**応答の形の違いで経路の
   実装有無が読める**ので、`apiNotFoundHandler()` は最上位の `app` に置いた。
