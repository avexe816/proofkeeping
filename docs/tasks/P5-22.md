# P5-22 配信状態（配達・開封・バウンス）を取り戻す

**系列**: P5（起票 2026-08-21 / OPEN_QUESTIONS #118）
**依存**: **P5-21**（Lark SMTP への移行）と、staging の実送信確認
**見積**: 未定（方式が決まっていない） **ステータス**: 未着手

## 背景
P5-21 で Resend から Lark Mail SMTP へ移した。SMTP で分かるのは
**「サーバーが `DATA` を受理したか」**までで、最終的に届いたか・
開封されたか・バウンスしたかは分からない（DECISIONS #248）。

Resend には webhook があり、`documentDelivery` の `DELIVERED` /
`BOUNCED` / `openedAt` をそこから立てていた。**いまは立たない。**

## いま残っているもの（消していない）
- `DELIVERY_STATUSES` の `SENT` / `DELIVERED` / `BOUNCED` / `FAILED`
- 受信側の実装一式（`routes/api/v1/webhooks.ts` /
  `lib/billing/webhookEvent.ts` / `webhookSignature.ts` /
  `consumers/notification.ts` の `handleDeliveryEvent()`）
- `document_delivery.provider_message_id` 列（いまは常に `null`）
- `PK_DELIVERY_TAG` / `PK_DELIVERY_HEADER`

**webhook を足せば戻せる形にしてある。**

## 決めること（**着手前に人間が選ぶ**）
1. Lark の Open API / 管理機能に webhook 相当があるか
2. バウンスを `noreply@stek.ai` で受けて読み取るか
3. 配信状態を諦めるか（`DELIVERY_UNCONFIRMED` のまま運用する）

## 影響を受ける完了条件（P5-10 から移送）
- 「Resend の webhook で bounce を受け取る」
- 「不達が画面に警告表示される（`GET /api/v1/deliveries/failed`）」
  → いまは `SMTP_REJECTED`（送信時の拒否）だけに縮んでいる

## やらないこと
- **`DELIVERED` / `BOUNCED` / `openedAt` を推測で埋めること。**
  分からないものを分かったことにしない（#248 の決定 D）。
