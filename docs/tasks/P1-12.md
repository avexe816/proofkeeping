## 完了条件

- [x] 直列送信・指数バックオフ
- [x] 5 回失敗で赤バッジ
- [x] 楽観的更新が動く
- [ ] **機内モードで「開始→写真3枚→チェック16項目→完了」ができ、復帰後に自動送信される**
- [x] 24 時間超過で赤い警告

## 作業ログ
2026-08-12 実装。`apps/web/src/lib/offline/{policy,idb,queue}.ts` /
`apps/web/src/ui/mobile/{useOfflineQueue,OfflineBar}.tsx`。

- **判断（policy）と IndexedDB / fetch（queue）を分けた。** テスト環境は node で
  `indexedDB` も `fetch` も無いため、再送の規則を直接押さえられる形にしてある。
- Background Sync API は使わない。flush は 5 トリガー（online / visibilitychange /
  未送信バーのタップ / 30 秒ポーリング / 完了操作の直後）から明示的に呼ぶ。
- 直列送信・指数バックオフ 1s→2s→4s→8s→16s・5 回で `requiresManualRetry`（赤バッジ）。
  **409 は成功として扱いキューから消す**（§8.2 MUST）。
- 楽観的更新はキューの id で畳む。id がキューから消えたらサーバーの値へ戻す。
- 24 時間以上残っている未送信があれば帯を赤にする（§8.1）。
- IndexedDB が使えない環境（プライベートブラウズ）はメモリへ退避する。
  **画面を止めない。**
- **機内モードの一連操作は実機テスト（P1-19）でしか確かめられない。**
  自動テストは規則の側だけを固定してある。この 1 項目は P1-19 で消すこと。
