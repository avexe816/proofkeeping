## 背景
`ui/navigation.ts` の `nav.inspection` は **`PLANNED`（準備中）のまま**で、
到達先が無い。検査そのもの（API・状態遷移）は P2 で実装済みなので、
**足りないのは一覧画面 1 枚。**

## やること
検査待ちのタスクを施設横断で並べる一覧。**清掃会社の担当者が
「次に検査するもの」を選ぶための画面。**

- 検査待ち（`READY_FOR_INSPECTION`）のタスクを業務日で絞って一覧
- 施設・客室・担当者・完了時刻を表示
- 行から検査画面へ遷移する
- `nav.inspection` を `PLANNED` → `READY` にする

## やらないこと
- **検査の実装そのもの**（P2-05 が持つ）
- **自動の優先度付け・スコア表示**（CLAUDE.md §4「個人評価を作らない」）
- 経過時間の赤色表示（ui-writing.md §3「急かさない」）

## 実装したときの差異

- **担当者を表示しない。** 上の「やること」は担当者の表示を挙げているが、
  `docs/PK-IMPL-CONTRACT.md` の INV-09「検査結果を入力するまで担当者名を
  表示しない（清掃会社の画面でも同様）」が優先する（CLAUDE.md §7）。
  API も担当者を返さない。DECISIONS #193。
- **状態の名前は `AWAITING_INSPECTION`。** 上の `READY_FOR_INSPECTION` は
  `TASK_STATUSES`（`packages/db/src/schema/task.ts`）に存在しない。
- **抜き取り率・抜き取りの選び方・本日の再清掃**はプロトタイプ 04 にあるが
  「やること」に無いため作っていない。
