# P5-21 メール送信を Lark Mail SMTP へ移す（第一段階）

**系列**: P5（起票 2026-08-21 / **オーナー判断** DECISIONS #248）
**依存**: なし（PF-16 の開通が通らない原因の 1 つ）
**見積**: 2日 **ステータス**: 実装済み（**staging の疎通確認は未実施**）

## 背景
stek.ai は Lark Mail を使っており、`noreply@stek.ai` を送信専用にする。
Resend は今後使わない。直接の引き金は PF-16 の staging 開通が
`DELIVERY_REJECTED` で失敗し、差出人が `billing@example.invalid`
（実在しない）だったこと（OPEN_QUESTIONS #117）。

## やること
1. `cloudflare:sockets` を使う SMTP クライアント（implicit TLS / 465）
2. 送信の口を `lib/mail/send.ts` の 1 本にし、3 経路をそこへ寄せる
3. `SMTP_PASSWORD` を Worker Secret として読む（**秘密はこれだけ**）
4. 疎通確認の口と workflow（**メールを送らない**）
5. 分かる事実だけを送付ログへ書く（`SMTP_ACCEPTED` ほか 3 状態）

## やらないこと
- `DELIVERED` / `BOUNCED` / `openedAt` の推測・代用（**後続 P5-22**）
- 既存の 5 状態と webhook 受信側の削除（**残す**）
- `RESEND_API_KEY` などの削除（**移行完了と実送信確認まで残す**）
- 添付ファイル（PDF は引き続き署名付き URL で配る）
