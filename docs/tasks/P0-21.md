## 作業ログ

### 2026-08-12
- 完了条件 10 件すべて達成。
- `dailyPropertyRollup`（§19.6）を追加し、`GET /api/v1/properties/summary`
  を新設。**施設サマリーはこの表からのみ取る**（§26 の絶対ルール）。
  客室数だけは客室マスタから数える（rollup に室数の列が無い）。
- 60 秒キャッシュは `CONFIG` KV。**`SHARD_MAP` へ相乗りさせない**
  （あちらは TTL 禁止 / architecture.md §1）。
- **キャッシュのキーにロールと担当施設を含める。** 組織 ID だけをキーに
  すると、施設責任者のキャッシュをオーナーが引く（またはその逆）。
  担当施設は並べ替えてから連結する（順序違いで別キーにしない）。
- `"ALL"` は全社ビューを持たないロールに **403**（DECISIONS #029）。
  施設 ID の拒否は 404 のまま。403 の語彙は `SCOPE_ERROR_CODES` に閉じ、
  共通の `API_ERROR_CODES` へ足していない。
- `"ALL"` への切替のみ `AuditLog` に記録（§23.4）。施設どうしの切替は記録しない。
- URL は `/app/p/:propertyId/board` と `/app/org/dashboard`。
  **URL を正としてセッションを更新する**（§23.5）。権限外の propertyId は 404。
- 9 施設以上で検索入力（§23.2 の「8 を超える場合」）。
- **集計が無い施設に 0 を出さない。** `hasRollup` が偽ならバッジを出さず
  「集計はまだありません」と述べる。0 と出すと 1 件も終わっていないように読める。
- **仕様の食い違いを 1 件起票: OPEN_QUESTIONS #029。** §23.3 の
  `ready` / `inProgress` / `dirty` は客室状態の数で、rollup が持つのは
  タスクの数。対応が仕様に無いので rollup の列名のまま返した（DECISIONS #030）。
