### 2026-08-12（2）— W-17 の画面（DECISIONS #048 / #049 / #050）

**やったこと**

- `/app/settings/standard-times`（`apps/web/src/routes/app/standardTimes.tsx`）。
  客室タイプ（行）× 清掃種別（列）の表。**設定の対象は表示中の施設**
  （`standardTime` の一意制約が施設を含むため）。
- 表の組み立てと入力の読み取りは純粋関数
  （`apps/web/src/lib/standardTime/matrix.ts` ＋ spec 20 件）。
- **未設定のセルには §3.1 の既定分数を初期値として置き、「既定値」の印を
  付ける**（DECISIONS #050）。空欄にすると、いま現場で何分が使われて
  いるのかが画面から読めない。保存するのは触られたセルだけ。
- 列は `CHECKOUT` / `STAYOVER` の 2 種。`DEEP` / `COMMON_AREA` / `RECHECK` は
  生成経路が P2 以降なので**表に出さない**（設定できて効き先が無い欄を作らない）。
- 客室タイプを列挙する `listRoomTypes()` を `packages/db/src/repositories/property.ts`
  に追加した（**それまで `roomType` を読む関数が無かった**）。越境テスト 5 件と
  `repositories.spec.ts` への登録つき。
- API を通らずリポジトリを直接呼ぶ（DECISIONS #049）。`assertPermission()` は
  loader と action の両方で呼ぶ。

**完了条件**

- [x] 客室タイプ×清掃種別で標準時間を設定できる
      → 画面から `upsertStandardTimes()`。**API 側（`PUT /api/v1/standard-times`）
      はそのまま残す**（外部連携と将来の一括投入の口）。

**未達（意図的・引き続き）**

- 設定を消す操作は作っていない（上と同じ理由）。
- **既存タスクの標準時間は変えない**（PK-SPEC-P0 §24.5）。画面にその旨を出した。
