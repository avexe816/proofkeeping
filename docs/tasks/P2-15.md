### 7 指標の対応（§10.1）
| 仕様 | 出力 | 分母 |
|---|---|---|
| 完了率 | `completionRate` | `CANCELLED` を除いたタスク数 |
| 初回検査合格率 | `firstPassRate` | 検査対象 |
| 再清掃率 | `reworkRate` | 検査対象 |
| 平均検査待ち時間 | `inspectionWaitMinutes` | 待ち時間を測れた件数 |
| 平均実作業時間 | `actualMinutes` / `actualMinutesByGroup` | 実作業分の記録がある件数 |
| SLA 超過率 | `slaBreachRate` | 待ち時間を測れた件数 |
| 自己検査率 | `selfInspectionRate` | 検査対象 |

### 決めたこと
- **「検査対象」は検査の記録があるタスク**（`dailyReport.ts` と同じ定義）。
  `inspectionRequired` の設定で数えると、抽出検査の施設で読めない率になる。
- **完了率の分母から `CANCELLED` を外す**（DECISIONS #088）。
- **率は千分率の整数**。分子・分母も一緒に返す（DECISIONS #089）。
- **平均検査待ち時間は Round 1 だけ。** 2 回目以降の開始までは再清掃の
  待ちで、検査の着手の遅さではない。SLA 超過も同じ待ち時間から出す。

### 個人指標を作らない担保（INV-01〜03 / security.md §5）
入力の型（`PropertyMetricsTaskInput` など）に**担当者の項目が 1 つも無い。**
個人別に分解しようとすると、まず関数の形を変えることになる。
型は実行時に消えるので、モジュール本文に `assignee` / `staff` / `inspector` /
`ranking` などの語が入っていないことを見るテストを添えてある。
§10.3 の「20 タスク未満」が効くのは本人が自分の記録を見る M-11 だけで、
そちらは `MINIMUM_TASKS_FOR_AVERAGE`（`ownWork.ts` / P1-17）が持っている。

### 入れていないもの（意図的）
- **指標の API と画面。** §12.1 にも §14 にも無く、P2-15 の完了条件も
  「算出される」だけ。読み手は P5 の W-02（OPEN_QUESTIONS #056）。
- **日報サマリーの置き換え。** 日報は件数（起きた事実）、指標は率と平均
  （事実から作った値）。分母も違うので別モジュールにしてある。
