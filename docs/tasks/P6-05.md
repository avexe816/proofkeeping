## 作業ログ

- 2026-08-14 完了。
  - `packages/integrations/src/core/autoMapping.ts`（純粋関数）。
    `autoMapRooms()` が部屋番号の**完全一致**だけを結ぶ。正規化は前後の
    空白・全角英数・英字の大小まで。**前ゼロを落とさない**（§7.2 の
    見本が `305 ←→ 0305` を「手動設定」と描いている / DECISIONS #142）。
  - 同じ番号が片側に 2 つ以上あるときは**どちらも結ばない**
    （`AutoMapResult.ambiguous`）。片方を選ぶと外れたときに気づけない。
  - W-23 `/app/settings/integrations/:integrationId/mappings`。
    自動マッピングの実行・1 件ずつの手動設定・対応の無効化。
    **未マッピングを両側とも行として出す**（`— ←→ 9001` / `601 ←→ —`）。
  - 権限は `integration.read` / `integration.write` を新設。
    `OWNER` / `ORG_ADMIN` だけ（`AUDITOR` は読み取り / DECISIONS #143）。
  - 対応の作成・無効化に `integrationMapping.updated` の監査ログ。
    **対応を 1 行間違えると客室を取り違える**ので、CLAUDE.md §5 の
    「破壊的操作」に当たると判断した。

### 止まらずに判断したこと
- **外部システム側の一覧は利用者の貼り付けで受ける**（DECISIONS #144）。
  アダプタが 1 つも無いため `listRooms()` を呼べない。入力元を
  差し替えるだけで済む形にしてある。
- 受信中に落ちた外部 ID を個別に出せない（OPEN_QUESTIONS #087）。
  件数だけを `sync_log.recordsSkipped` の合計として出した。
