## 完了条件
- [x] 2 施設担当時、施設グループヘッダ付きの単一リストが表示される
      → `routes/m/today.tsx` の `PropertyGroup`（濃色帯 `--brand2` ＋件数）。
- [x] 施設間に移動ブロックが表示される（`dailyRoute` 設定時）
      → `travelMinutesToNext`。**最後のグループには出さない**（帰り道の指示に読める）。
- [x] `dailyRoute` 未登録でもタスク一覧が動作する
      → 施設名の昇順へ落ちる。`myDay.spec.ts` が固定。部分登録の扱いは DECISIONS #039。
- [x] 完了した施設グループが自動で折りたたまれる
      → `allDone`。**利用者が開いたらそちらを優先する**（自動判断で閉じ直さない）。
- [x] フィルタが全施設をまたいで適用される
      → 空になったグループは落とす。ボタンの件数は絞る前の値のまま。
- [x] `my-day` が 1 リクエストで全施設分を返す
      → `GET /api/v1/tasks/my-day`。担当者はセッションから解決する。
- [ ] `my-day` の p95 が 400ms 未満（3 施設 30 タスク）
      → **未計測。** 実 D1 が 1 本しか無い（P0-02 待ち）。クエリは 4 本で、
      施設数に依らず一定であることまでは実装で担保した。
- [x] オフライン時に最後の `my-day` が表示され、取得時刻が明示される
      → `lib/offline/myDayCache.ts`。**1 日単位**（施設単位にしない / §19.7 MUST）。
      取得時刻はサーバーの `fetchedAt` を使う（端末の時計を信用しない）。
- [x] 送信キューが施設をまたいで 1 本になっている
      → P1-12 の `QUEUE_STORE` をそのまま使う。施設の次元を持たせていない。
