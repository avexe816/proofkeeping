**関連文書** PK-SPEC-P1（タスク管理）／PK-SPEC-P3（記録・ベースライン）／PK-SPEC-P4（稼働照合エンジン）

## 0. 本書について

### 0.1 目的

本書は ProofKeeping の清掃員向けモバイル画面16面について、画面構成・状態遷移・文言規則・データ項目を確定するための設計文書です。実装着手前の合意形成と、実装後の受け入れ判定の基準として使用します。

### 0.2 想定利用者

| 読者 | 本書の使い方 |
|---|---|
| 開発担当 | 画面要素・状態遷移・データ項目の実装仕様として |
| 運営管理者 | 現場運用との整合確認、文言の最終確認 |
| 施設オーナー | 記録範囲とプライバシー方針の確認 |
| デザイン担当 | デザイントークンとコンポーネント定義の参照 |

### 0.3 利用者像（本書の前提）

本アプリの主要な利用者は、日本語の読み書きが十分でない外国人清掃員です。以下を前提として全画面を設計しています。

- 日本語の漢字は読めない場合がある
- スマートフォンの操作経験には大きな差がある
- ゴム手袋を着用したまま、濡れた手で操作する
- 1日20室以上を担当し、1室あたりの入力に使える時間は数十秒
- 客室内は電波が届かないことが多い

### 0.4 本書で扱わない範囲

管理者向けWeb画面、施設マスタ管理、シフト作成、請求関連、P4稼働照合エンジンの判定ロジックは本書の対象外です。別途フェーズ2以降で定義します。

## 1. 設計原則

全16画面に共通して適用する原則です。個別の画面設計が本原則と矛盾する場合、本原則を優先します。

### 1.1 記録は業務改善のために使い、個人の評価には使わない

これが本アプリの根幹の方針です。清掃員が「記録が自分の評価に使われる」と感じた時点で、正確な記録より見た目のよい記録を選ぶ動機が生まれ、P4稼働照合エンジンの入力データとしての価値が失われます。

この方針は画面上にも明記します。

| 画面 | 明記箇所 |
|---|---|
| 06 入室時の記録 | 「清掃品質の管理と業務改善のために使用します」 |
| 11 完了確認 | 「清掃員の評価には使用されません」 |
| 13 検査画面 | 検査結果の入力まで担当者名を表示しない |
| 14 個人実績 | 「比較や順位は表示されません」 |

### 1.2 判断させず、観察したことだけを記録させる

清掃員に「この部屋は使われたか」を判断させません。「ベッドはいくつ使われていたか」を答えてもらい、判定はサーバー側で行います。判断を求めることは、清掃員に宿泊客へ疑いを向ける役割を負わせることであり、入力が歪みます。

| 禁止する設問 | 許可する設問 |
|---|---|
| この部屋は使われましたか | ベッドはいくつ使われていましたか |
| 不審な点はありましたか | ゴミの量は |
| 宿泊人数は何人だと思いますか | 使用済みタオルは何枚ありましたか |

### 1.3 赤色を人に向けて使わない

赤色は「異常」「失敗」を意味します。清掃時間が長くなる理由、リネンの数が合わない理由、チェック項目を実施できない理由は、そのほとんどが清掃員の責任範囲外にあります。

| 状況 | 使用する色 |
|---|---|
| 目安時間の超過 | オレンジ→グレー（赤は使わない） |
| リネンの回収と補充の差分 | 情報色（青）。警告にしない |
| オフライン状態 | オレンジ（赤は使わない） |
| 再清掃の指示 | 赤（作業に対する指示のため許容） |
| 入室不可 | 赤（業務連絡として許容） |

### 1.4 正直に記録できる選択肢を必ず用意する

「できなかった」「わからない」「該当しない」を選べない画面は、嘘の入力を誘発します。

- チェックリストは3値入力（○／×／該当なし）
- 入室時の記録に「今回は記録しない」を常設
- 詳細記録は全項目任意
- 中断・入室不可の理由に必ず「その他」を置き、説明は求めない

### 1.5 キーボードを出さない

数値はステッパー、選択は大きなボタン、状態は3値タップで入力します。日本語入力・多言語入力の負担を排除し、手袋着用時の誤入力を防ぎます。自由記述は全画面で任意入力のみです。

### 1.6 文言規則

| 使わない語 | 使う語 |
|---|---|
| 不審な点 | 気づいたこと |
| 異常 | 通常と違う点 |
| チェック（監視の意味） | 記録 |
| 報告義務 | 記録のお願い |
| 未実施の項目 | できなかった項目 |
| エラー／失敗 | （使わない。状態を事実として述べる） |
| 接続してください | 接続が戻ると自動で送信されます |

## 4. 画面定義

### 01 ログイン

**目的** 日本語が読めなくても認証を完了できるようにする。

**画面要素**

- 言語選択（国旗＋自国語表記、7言語）
- 電話番号入力（数字キーパッド、ハイフン自動挿入）
- PIN入力（4桁、数字キーパッド）
- ログインボタン
- 「PINを忘れた場合」（管理者へ連絡する案内）

**確定事項**

1. メールアドレスは使用しない。電話番号＋PINとする
2. 言語選択を認証より前に置く
3. パスワードではなくPIN（4桁）とする
4. 入力キーはすべて数字キーパッド。文字入力は発生させない
5. PIN再発行は管理者経由とし、アプリ内では完結させない
6. 認証失敗時の文言に「エラー」を使わない

**データ項目** `phoneNumber` / `pin`（ハッシュ化して照合）/ `preferredLanguage`

---

### 02 タスク一覧

**目的** 当日担当する部屋を施設ごとに把握し、1タップで作業を開始できるようにする。

**画面要素**

- 日付・担当者名・担当施設数
- 進捗（完了件数／総件数）
- 施設ごとのグループヘッダー（施設名・残件数）
- 施設間の移動表示（所要時間の目安）
- タスクカード（部屋番号／作業種別／階／客室タイプ／目安時間／状態タグ）
- 開始ボタン（カード内）

**状態**

| 状態 | 表示 |
|---|---|
| 未着手 | グレータグ、開始ボタン活性 |
| 作業中 | オレンジ枠、経過時間表示 |
| 完了 | 緑枠、実作業時間表示 |
| 保留（入室不可） | 一覧下部へ移動 |
| 再清掃 | 赤枠、指示箇所を表示 |

**確定事項**

1. 施設ごとにグループ化し、施設名を常時表示する
2. 部屋番号を最大の文字サイズで表示する
3. 開始は1タップ。確認ダイアログは施設変更時のみ
4. 前回清掃者・過去の指摘履歴は表示しない
5. 完了済みタスクも一覧に残す（作業量の可視化）

**データ項目** `taskId` / `propertyId` / `roomNumber` / `taskType` / `floor` / `roomType` / `standardMinutes` / `status`

---

### 03 空状態

**目的** タスクが割り当てられていない日に、清掃員を不安にさせない表示をする。

**画面要素**

- イラストまたはアイコン
- 「本日のタスクはまだ割り当てられていません」
- 「割り当てが完了すると通知が届きます」
- 更新ボタン
- 過去の記録を見るリンク（14へ）

**確定事項**

1. 「仕事がありません」という表現を使わない
2. 割り当て前と休業日を区別して文言を出す
3. 更新ボタンを置き、能動的に確認できるようにする
4. 責任の所在を示す表現（「管理者に確認してください」等）を使わない

---

### 04 施設変更の確認

**目的** 複数施設のタスクが1画面に並ぶため、別施設のタスクを誤って開始する事故を防ぐ。

**画面要素**

- 前施設 → 次施設の表示
- 部屋番号（大）・作業種別
- 住所
- 担当フロア
- この施設の残件数
- 「移動が完了しているかご確認ください」
- キャンセル／開始する（幅比 1 : 1.35）

**確認を出す条件**

| 状況 | 確認 |
|---|---|
| 直前のタスクと同一施設 | 出さない |
| 直前のタスクと別施設 | 出す |
| 当日の初回タスク | 出さない |
| 中断からの再開 | 出さない |
| 同じ施設に戻ってきた | 出す |

**確定事項**

1. 施設が変わる瞬間のみ確認する。同一施設内では確認しない
2. 住所を表示し、同系列ホテルの誤認を防ぐ
3. 「今日はもう確認しない」は設けない
4. UIの確認とは別に、サーバー側で `allowedPropertyIds` を検証する
5. 権限外の施設IDには **404** を返す（403は資源の存在を示唆するため使わない）

---

### 05 タスク詳細

**目的** 作業中の中心画面として、進捗と残作業を一目で把握できるようにする。

**画面要素**

- 3段タイマー（目安／経過／チェック進捗）
- 進捗バーと残り時間の目安
- 補助情報（次のチェックイン時刻、リネン記録の有無）
- チェックリストへの遷移カード（残必須件数を表示）
- 入室時の記録への遷移カード（記録済み表示）
- 写真サムネイルと追加ボタン
- メモ（任意）
- 中断／入室不可ボタン
- 完了ボタン（条件未達時は非活性＋残件数表示）

**タイマーの色分け**

| 経過 | 表示 | 意図 |
|---|---|---|
| 目安以内 | 通常色 | 問題なし |
| 目安を超過 | オレンジ | 気づかせるが責めない |
| 目安の1.5倍 | グレー | 超過の意味を薄める |
| 2倍以上 | グレー（変えない） | 長時間でも責めない |

**確定事項**

1. 3段タイマー（目安・経過・チェック）を採用する
2. 超過表示に赤を使わない
3. 完了ボタンは条件未達で非活性とし、残件数を併記する
4. チェックリスト・写真・リネンは別画面に分ける
5. メモは任意。入力を強制しない
6. 前回清掃者・過去の指摘は表示しない

**データ項目** `startedAt` / `elapsedMinutes` / `actualMinutes` / `checklistProgress` / `photoCount` / `pauseCount`

### 06 入室時の記録

**目的** P4稼働照合エンジンの唯一の入力源。15秒で完了できることを要件とする。

**必須項目（5項目）**

| 項目 | 入力方式 |
|---|---|
| ベッドの使用 | 3択（0台／1台／2台） |
| ゴミの量 | 4択（なし／少ない／通常／多い） |
| 使用済みバスタオル | ステッパー |
| 使用済みフェイスタオル | ステッパー |
| 使用済みバスマット | ステッパー |

**既定値の推定ロジック**

| 稼働予定 | 既定値 |
|---|---|
| チェックアウトあり・2名 | ベッド2台／ゴミ通常／タオル各2 |
| チェックアウトあり・1名 | ベッド1台／ゴミ通常／タオル各1 |
| 空室予定 | ベッド0台／ゴミなし／タオル0 |
| 稼働記録なし | 客室タイプの標準定員から推定 |

**画面要素**

- 既定値の説明（「稼働記録から推定した値を入れています」）
- 必須5項目
- 「この内容で記録」ボタン
- 「詳しく入力する」（07へ）
- 「今回は記録しない」
- 「清掃品質の管理と業務改善のために使用します」

**確定事項**

1. 全項目に既定値をプリセットし、変更がなければ1タップで確定できる
2. キーボードは一切出さない
3. 必須項目は5つまで
4. 「今回は記録しない」を常設し、理由は聞かない
5. スキップは `observationSkipped` に記録し、P4の照合対象から除外する
6. 既定値のまま確定した場合 `usedDefaults = true` を記録する
7. `usedDefaults` の比率が90%を超える施設は、P4で該当差異の確信度を20下げる
8. 入力所要時間を `inputDurationMs` に記録し、中央値20秒以内を受け入れ基準とする（PK-SPEC-P3 §0.3）

**データ項目** `bedsUsed` / `trashLevel` / `towelCounts` / `usedDefaults` / `inputDurationMs` / `observationSkipped`

### 07 詳細記録

**目的** アメニティ等の補助データを、任意入力で収集する。

**品目マスタ**

| コード | 品目 | 入力方式 | 既定 |
|---|---|---|---|
| `TOOTHBRUSH` | 歯ブラシ | 数量 | ON |
| `RAZOR` | カミソリ | 数量 | ON |
| `SHAMPOO` | シャンプー類 | トグル | ON |
| `SLIPPERS` | スリッパ | 数量 | ON |
| `BOTTLED_WATER` | ミネラル水 | 数量 | OFF |
| `TEA_BAG` | お茶・コーヒー | 数量 | OFF |
| `YUKATA` | 館内着 | 数量 | OFF |

**確定事項**

1. 全項目任意。未入力でも完了できる
2. 品目は施設ごとに `observationConfig.enabledItemCodes` で有効化する
3. 数量とトグルを品目の性質で使い分ける（詰め替え式シャンプーは残量が測れないためトグル）
4. キーボードは出さない
5. 「入力せずに戻る」を必ず用意する
6. P4では補助データとして扱い、単独では差異を生成しない（重要度LOW）
7. 単一シグナルで確信度80以上を出さない原則に従う（PK-SPEC-P4 §14）

### 08 チェックリスト

**目的** 作業項目の実施状況を、正直に記録できる形で収集する。

**3値の定義**

| 値 | 意味 | 扱い |
|---|---|---|
| ○ | 実施した | 完了として計上 |
| × | できなかった | 理由の選択が必要。管理者に通知 |
| — | 該当なし | 分母から除外。完了扱い |

操作方法：タップで○、再タップで×、長押し（0.55秒）で該当なし。

**項目数の上限**

| 区分 | 上限 |
|---|---|
| 1タスクの総項目数 | 30 |
| うち必須項目 | 15 |
| うち写真必須 | 5 |
| カテゴリ数 | 6 |

**確定事項**

1. 3値入力（○／×／該当なし）とする
2. ×は理由選択が必要。責める表現は使わない
3. 写真必須項目は 📷 マークで明示し、撮影なしでは○にできない
4. 上部に必須残り件数を常時表示する
5. 項目数の上限をシステムで強制する（超過するテンプレートは保存不可）
6. 進捗の分母は「該当なし」を除いた項目数とする
7. 完了ボタンの有効化は必須項目のみで判定する

### 09 写真の撮影

**目的** 用途を先に選んでから撮影し、後から分類する作業を発生させない。

**用途（初期セット）**

| 用途 | 撮影ガイド | 必須 |
|---|---|---|
| シーツ交換後 | 交換後のベッド全景 | ○ |
| 浴槽清掃後 | 清掃後の浴槽内部 | ○ |
| 備品棚 | 棚全体が入るように | ○ |
| 客室全景 | 入口から客室全体 | ○ |
| その他 | — | — |

**プライバシー処理**

| 処理 | 内容 |
|---|---|
| EXIF GPS | アップロード前に端末側で削除 |
| 撮影時刻 | サーバー時刻で上書き |
| 端末情報 | 機種名・シリアルを削除 |
| サムネイル | EXIF内の縮小画像も削除 |
| 顔検出 | 実装しない |

**画像の仕様**

| 項目 | 値 |
|---|---|
| 長辺 | 1600 px |
| 形式 | JPEG（WebP fallback） |
| 品質 | 78 |
| 目標サイズ | 1枚 250KB 以下 |
| 1タスク上限 | 20枚 |
| 保存期間 | 90日（施設ごとに設定可） |

**確定事項**

1. 用途を先に選んでから撮影する
2. EXIFのGPSは端末側で削除する
3. 撮影時刻はサーバー時刻を使用する（オフライン時はキュー投入時刻を記録し、同期時に差分をログに残す）
4. 顔検出は実装しない
5. オフラインでもチェックリストを進められる
6. 画面に「位置情報は保存されません」を明記する

### 10 リネン記録

**目的** 回収と補充を記録し、差分を事実として残す。

**画面要素**

- 施設単位の日次集計（回収合計／補充合計／差分）
- 品目ごとの2列入力（↙回収／↗補充）
- 品目直下の差分表示
- 既定値タグ（変更すると「変更あり」に切り替わる）

**既定値の根拠**

| 品目 | 既定値 |
|---|---|
| シーツ | ベッド数と同数 |
| バスタオル | 宿泊人数と同数 |
| フェイスタオル | 宿泊人数と同数 |
| バスマット | 1室1枚 |
| 館内着 | 宿泊人数と同数 |

**差分を警告にしない理由**

| 差分が出る理由 | 責任の所在 |
|---|---|
| 前回の補充が不足していた | 前日の運用 |
| 客が持ち帰った | 誰の責任でもない |
| 汚損で廃棄した | 誰の責任でもない |
| ワゴンの在庫が切れていた | 供給側 |
| 数え間違い | 起きて当然 |

**確定事項**

1. 回収・補充を左右2列に配置し、矢印で物の流れを示す
2. 差分は事実として表示する。警告にしない
3. 差分の理由は聞かない
4. 既定値をベッド数・宿泊人数から自動設定する
5. 上部に施設単位の日次集計を常時表示する
6. 入力せずに戻ることもできる
7. 日次差分は在庫発注の参考値としてP2に連携する

### 11 完了確認

**目的** 取り消しできない完了操作の前に、自分で誤りに気づける機会をつくる。

**画面要素**

- 部屋番号・施設名・作業種別
- 作業時間（開始／終了／実作業）
- できなかった項目（ある場合のみ、理由付き）
- 記録した内容の一覧（チェックリスト／入室時の記録／写真／リネン／詳細記録／メモ）
- 作業時間の内訳（開始・終了・中断回数・実作業・目安）
- 超過時のお知らせ（青。「問題ではありません」で終わる）
- 完了する／戻って修正する

**×の項目の見せ方**

| 使わない | 使う |
|---|---|
| 未実施の項目 | できなかった項目 |
| 不備あり | 記録された内容 |
| 警告：1件失敗 | できなかった項目（1件） |

×の欄に「清掃員の評価には使用されません」を明記します。

**完了後の操作可否**

| 操作 | 可否 |
|---|---|
| 写真の追加 | 24時間以内は可 |
| メモの追記 | 24時間以内は可 |
| チェックリストの修正 | 管理者の承認が必要 |
| 入室時の記録の修正 | 管理者の承認が必要 |
| 完了の取り消し | 不可（再清掃として新規作成） |

**確定事項**

1. 完了前に記録内容を一覧表示する
2. ×の項目は隠さないが責めない
3. 「評価には使用されません」を明記する
4. 時間超過は青いお知らせのみとする
5. 評価・順位・平均比較は表示しない
6. 「戻って修正する」を必ず用意する
7. 修正操作はすべて `auditLog` に修正前後の値を残す

### 12 中断と入室不可

**目的** 「今は作業できない」を、理由の選択だけで記録できるようにする。

**2つの区分**

| | ⏸ 中断 | 🚫 入室不可 |
|---|---|---|
| 入室したか | している | していない |
| タスクの状態 | 作業中（一時停止） | 保留 |
| 管理者通知 | しない | する |
| 再開方法 | 本人がその場で | 時間をおいて再訪 |
| P4での扱い | 照合対象 | 照合対象外 |

**理由の選択肢**

中断：リネンが足りない／休憩／他の業務が入った／備品・設備の不具合／応援に呼ばれた／その他

入室不可：DNDの札が出ている／お客様が在室している／鍵が開かない／工事・修繕中／フロントから待機指示／その他

**時間計算への影響**

| 時刻 | イベント | 実作業に計上 |
|---|---|---|
| 14:02 | 開始 | ○ |
| 14:25 | 中断（リネン待ち） | — |
| 14:38 | 再開 | ○ |
| 15:04 | 完了 | ○ |

上記の例では経過62分・中断13分・実作業49分となります。中断を3回挟んでも `actualMinutes` が正しく計算されることをテストの必須項目とします（PK-SPEC-P1 §14.1）。

**入室不可のあとの流れ**

1. タスクは「保留」になり一覧の下部に移動する
2. 保留のまま当日の他タスクを続けられる
3. 30分後に一覧上部へ「再訪しますか」を表示する
4. 3回連続で入室不可の場合は管理者に再通知する
5. 当日中に入室できなかった場合は翌日に繰り越す

**確定事項**

1. 中断と入室不可を明確に分ける
2. 理由は選択のみ。キーボードは出さない
3. 「その他」を必ず用意し、説明は求めない
4. 中断時間は実作業時間から除外する
5. 入室不可のみ管理者に通知する（清掃員への注意ではなく、フロントとの調整が必要という業務連絡）
6. 「評価には影響しません」を画面に明記する
7. 「その他」の比率が30%を超えたら選択肢を見直す
8. 選択肢は施設ごとに追加・並び替え可。最大8つまで

### 13 検査画面（管理者用）

**目的** 清掃員が記録した内容を管理者が確認し、必要なら再清掃を指示する。

**画面要素**

- 部屋番号・施設名・完了時刻
- 記録された内容の一覧
- 記録写真のサムネイル
- 作業の記録（時系列）
- 検査結果（問題なし／再清掃が必要）
- 再清掃の箇所選択（浴室／ベッド／床／水回り／備品の不足／その他、複数選択可）
- 「担当者名は結果を記録したあとに表示されます」

**時系列から読み取れること**

| パターン | 読み取れること |
|---|---|
| 開始直後に入室記録 | 通常の流れ |
| 完了直前にまとめて記録 | 後追い入力の可能性 |
| 写真が完了間際に集中 | 同上 |
| 中断が複数回 | 供給や設備の問題かもしれない |

「後追い入力の可能性」は疑いではなく、業務フローの改善点を探す手がかりとして扱います。

**検査の運用方針**

| 項目 | 方針 |
|---|---|
| 検査の対象 | 全室ではなく抜き取り（既定10%） |
| 抜き取りの選び方 | ランダム＋P4の差異がある部屋 |
| 検査の期限 | 完了から24時間 |
| 未検査の扱い | 24時間後に自動で合格 |
| 再清掃率の表示 | 個人別には出さない |

**確定事項**

1. 検査結果の入力まで担当者名を表示しない（完全に隠すのではなく、順序を変える）
2. 記録を時系列で並べる
3. 再清掃の理由は選択式とし、自由記述は任意
4. 元のタスクの記録は削除せず保持する
5. 再清掃タスクは新規タスクとして作成する
6. 抜き取り検査を既定10%とする
7. 個人別の再清掃率は表示しない（管理指標になると検査者が指摘を控えるため）

### 14 個人実績

**目的** 自分の記録だけを確認できるようにする。

**表示する項目**

| 項目 | 表示理由 |
|---|---|
| 完了した部屋数 | 自分の作業量が分かる |
| 1部屋の平均時間 | 自分のペースが分かる |
| 撮影した写真数 | 記録の量が分かる |
| 作業の種別 | どんな仕事をしたか分かる |
| 直近7日の推移 | 自分の変化が分かる |

**表示しない項目**

| 表示しない | 理由 |
|---|---|
| 他人との比較 | 速さの競争になる |
| チーム内の順位 | 同僚を競争相手にする |
| 平均との差 | 平均以下という感覚を生む |
| 目標達成率 | 未達が失敗に見える |
| 評価スコア | 記録が評価の道具になる |
| 連続達成日数 | 休むことに罪悪感が出る |
| 目安時間との比較 | 目安は施設の想定であり個人の評価基準ではない |

ゲーミフィケーション（バッジ、連続記録）は意図的に排除します。短期的に入力率を上げますが、記録の目的が「バッジを取ること」に変わり、データの質が落ちます。

**記録の書き出し**

- 期間を選んでPDF出力（日・週・月）
- 完了した部屋、作業時間、中断の記録を含む
- 検査結果や再清掃の履歴は含まない
- 7言語すべてで出力できる
- 出力操作は `auditLog` に記録するが通知はしない

労働時間の記録を本人が保持できることは、外国人労働者にとって特に重要です。雇用トラブルの際に自分の側の記録があるかどうかで立場が変わります。

**誰が何を見られるか**

| 役割 | 見える範囲 |
|---|---|
| 清掃員 | 自分の記録のみ |
| 現場責任者 | 担当施設のチーム全体 |
| 運営管理者 | 契約範囲の全施設 |
| 施設オーナー | 自施設のみ・個人名なし |

施設オーナーに個人名を出さないのは、清掃会社の従業員の個人成績を発注元が閲覧できる構造にすると、圧力が個人に向かうためです。

### 15 言語と表示設定

**目的** 初回起動時に、説明文なしで言語を選べるようにする。

**画面要素**

- 言語選択（国旗＋自国語表記＋日本語名を小さく）
- 文字サイズ（小／標準／大）＋同画面プレビュー
- テーマ（ライト／ダーク）
- 操作音／振動／高コントラスト

**現場に必要な配慮**

| 機能 | 必要な理由 |
|---|---|
| 振動 | 手袋着用時はタップの感触が分かりにくい |
| 操作音 | 入力できたかを音で確認できる |
| 高コントラスト | 窓際や屋外通路で画面が見えにくい |
| ダークモード | 早朝・深夜のシフトで目が疲れにくい |

これらは「あると良い機能」ではなく、清掃現場の物理条件から必要になる機能です。

**確定事項**

1. 7言語に対応。国旗＋自国語表記で選択する
2. 「言語を選択してください」という説明文に頼らない構成とする
3. 選んだ瞬間に画面全体を切り替える（保存前でも）
4. 文字サイズは3段階。プレビューを同画面に置く
5. 端末の文字サイズ設定も反映する
6. 振動・操作音・高コントラストを個別に設定できる
7. 最小タップ領域48×48px

### 16 オフライン状態

**目的** オフラインを例外ではなく通常の状態として扱い、記録が失われる不安を与えない。

**オフラインでの機能可否**

| 機能 | オフラインで可能か |
|---|---|
| タスク一覧の閲覧 | 可能 |
| タスクの開始・完了 | 可能 |
| 入室時の記録 | 可能 |
| 写真の撮影 | 可能 |
| チェックリスト | 可能 |
| リネン記録 | 可能 |
| 当日タスクの再取得 | 通信が必要 |
| 他人の実績の閲覧 | 通信が必要 |

当日のタスクは朝の初回同期で全件を端末に取得します。1日分のデータは数百KB程度なので、朝一度つながれば1日オフラインでも作業を完遂できます。

**不安を与えない文言**

| 使わない | 使う |
|---|---|
| エラー：接続できません | オフラインで動作中 |
| 保存に失敗しました | 端末に保存されています |
| 未送信のデータがあります | 送信待ちの記録 |
| 接続してください | 接続が戻ると自動で送信されます |

**同期の仕組み**

1. 記録は即座に IndexedDB へ保存（暗号化）
2. 接続を検知すると自動でキューを送信
3. 送信順は 完了記録 → 入室記録 → 写真（写真はサイズが大きく回線を占有するため最後）
4. 写真は1枚ずつ送信し、失敗しても他は進む
5. 3回失敗した項目は指数バックオフで再試行
6. 同期完了まで端末内のデータは削除しない
7. 写真キューは1端末あたり最大200枚。超過時は古い任意写真から削除し、必須写真は残す

**競合の解決**

| 状況 | 解決方法 |
|---|---|
| 同じタスクを2端末で完了 | 先に届いた方を採用。後着は競合として記録 |
| オフライン中に担当者が変更 | 記録は保持。管理者に通知して判断を仰ぐ |
| オフライン中にタスクが削除 | 記録は保持。削除は取り消さない |
| 端末時刻がずれている | サーバー時刻で補正し差分をログに残す |

競合が起きても清掃員の記録を消すことはしません。採用されなかった記録も `conflictLog` に残し、必要なら管理者が確認できます。

**確定事項**

1. オフラインで全ての記録機能が動作する
2. 端末内データは暗号化して保存する
3. オフラインは赤ではなくオレンジで表示する
4. 「失敗」「エラー」という語を使わない
5. 同期完了まで端末内データを削除しない
6. 競合時も清掃員の記録を消さない

## 5. 横断仕様

### 5.1 権限とデータ可視範囲

| 役割 | タスク | 検査 | 個人実績 | 施設設定 |
|---|---|---|---|---|
| 清掃員 | 自分の担当のみ | — | 自分のみ | — |
| 現場責任者 | 担当施設全体 | 可 | チーム全体 | 一部 |
| 運営管理者 | 契約範囲全施設 | 可 | 全員 | 可 |
| 施設オーナー | 自施設・個人名なし | 閲覧のみ | — | — |

サーバー側では `taskId` から `propertyId` を解決し、`allowedPropertyIds` に含まれるかを必ず検証します。含まれない場合は 404 を返します。クライアントから送られた `propertyId` は信用しません。

### 5.2 監査ログ

以下の操作は `auditLog` に記録します。修正操作は修正前後の値を保持します。

- ログイン／ログアウト
- タスクの開始・中断・再開・完了
- 入室時の記録の登録・修正
- チェックリストの修正
- 写真の追加・削除
- 検査結果の登録
- 再清掃の指示
- 個人実績の書き出し

### 5.3 多言語対応の実装方針

- 全UI文字列を辞書化し、ハードコードしない
- 数値・日付・時刻はロケールに応じて整形する
- ミャンマー語・ネパール語は行高を1.2倍確保する（文字の縦幅が大きいため）
- 言語切り替えは再起動を要求せず、即時反映する
- 翻訳は現場の用語に合わせる（機械翻訳のまま使用しない）

## 6. 受け入れ基準

| # | 基準 | 判定方法 |
|---|---|---|
| 1 | 入室時の記録の入力所要時間が中央値20秒以内 | `inputDurationMs` の実測 |
| 2 | 全画面が日本語を読めずに操作できる | 日本語非話者による操作テスト |
| 3 | 中断を3回挟んでも実作業時間が正しい | 単体テスト（PK-SPEC-P1 §14.1） |
| 4 | オフラインで全記録機能が動作する | 機内モードでの通しテスト |
| 5 | 全タップ領域が48×48px以上 | 実装検査 |
| 6 | 7言語すべてでレイアウト崩れがない | 全画面 × 7言語の目視確認 |
| 7 | ライト／ダーク両モードでコントラスト比4.5:1以上 | 自動検査 |
| 8 | 写真1枚が250KB以下 | 実測 |
| 9 | 権限外の施設IDに404を返す | APIテスト |
| 10 | 画面上に「失敗」「エラー」の語が存在しない | 文字列検査 |

## 7. 用語集

| 用語 | 定義 |
|---|---|
| アウト清掃 | チェックアウト後の客室清掃 |
| ステイ清掃 | 連泊中の客室清掃 |
| 再清掃 | 検査で指摘があった箇所の再作業。新規タスクとして作成する |
| 入室時の記録 | 清掃開始直後に、客室で観察した状態を記録すること |
| 稼働照合 | 入室時の記録と稼働記録を突き合わせ、差異を検出すること（P4） |
| 目安時間 | 施設が想定する1室あたりの作業時間。個人の評価基準ではない |
| 実作業時間 | 中断時間を除いた作業時間 |
| 保留 | 入室できず、後で再訪する状態 |
| 送信待ち | 端末に保存済みで、サーバーへ未送信の状態 |

## 8. 未決事項

第2フェーズ着手前に決定が必要な項目です。

| # | 項目 | 現案 | 判断が必要な理由 |
|---|---|---|---|
| 1 | 抜き取り検査の比率 | 10% | 施設規模により負荷が変わる |
| 2 | 写真の保存期間 | 90日 | ストレージ費用と証跡としての必要期間の兼ね合い |
| 3 | 移動時間の経過チェック | 実装しない | 早着時に警告が邪魔になる懸念 |
| 4 | 「その他」選択時の任意入力欄 | 設けない | 改善のヒントは得られるが入力負担が増える |
| 5 | 通知の送信手段 | アプリ内のみ | SMS併用は費用と到達率の検討が必要 |
| 6 | 個人実績のPDF出力に検査結果を含めるか | 含めない | 本人の労働記録としての完全性との兼ね合い |
