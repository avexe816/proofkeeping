# プロトタイプと実装の差分台帳

**方針**: 見た目と挙動の正は `ui-prototypes/`（DECISIONS #195 / 人間の指示 2026-08-16）。
CLAUDE.md §4 と security.md に反するものは作らない。
**2026-08-20 のオーナー指示で、P8 とプラットフォーム運営 12 画面が実装対象に入った**
（DECISIONS #219）。それ以前の「P8 に当たるものは作らない」は解除済み。
**2 つの原則を両立させる**（人間の指示 2026-08-16）:
1. **プロトタイプが上限。** 無い機能・画面・項目を足さない。
2. **簡素化は必須。** プロトタイプの範囲内でも、目的に効かない
   装飾・フィルタ・列は削ってよい。迷ったら少ない方を選ぶ。
画面ごとの判断は本台帳の行に書く。

**版**: 2026-08-20（第2版 / P8・プラットフォームの解禁を反映）。閉じたら行を更新すること。消さない。


## セッションの分担（人間の指示 2026-08-20）

並行して 2 セッションが動いている。**同じ task を 2 度実装しないための分担**
（P8-04 / PF-01 の 2/2 で実際に重複が起きた）。

| 担当 | 範囲 |
|---|---|
| 実装計画のセッション | `docs/PROGRESS.md` の task（PF-02 以降・P8 ほか） |
| 画面のセッション | **本台帳の差分**・UI の一貫性・人間からの画面指示 |

**画面側は `docs/PROGRESS.md` の未着手 task に手を出さない。**
逆に実装計画側が画面を作ったら、その行をこの台帳で閉じること。

## 表のカード化（DECISIONS #234 の残り / 画面側の担当）

プロトタイプは**表をカードに入れ、アイコン付きの見出しと右端の補足**を持つ。
実装は 21 画面が素の表だった。**見出しはプロトタイプに実物があるものだけ**を
使う（無い画面で発明すると、ページ見出しと同じ言葉が 2 段に並ぶ）。

**終わり。** カード化は 2026-08-20 に完了した。

**済み（10 画面）**: 稼働の差異（#224）/ 客室ボード（#226）/ 検査キュー・
進捗モニタ・清掃記録（#234）/ スタッフ管理・標準時間（2 バッチ目）/
研修と資格（3 バッチ目）/ 監査ログ・請求確認（4 バッチ目）。

**もともとカードだった画面**: 契約と請求・施設設定・権限と監査（#213 / #214）。
チェックリスト定義は表を持たない。

**素の表のままにする画面**（プロトタイプに見出しが無い / #234 の判断）:
忘れ物・設備不具合（P7-22）/ データ品質（P3-12）/ 客室予定（W-05）/
ベースライン（P3-10）/ 客室タイプ・ルール設定・取引先と料金（設定の小画面）/
支払集計・支払ルール（PK-SPEC-PAY に画面のプロトタイプが無い）/
月次レポート（印刷レイアウトを崩さない）/ 組織ダッシュボード（月次で、
プロトタイプ owner 02 は日次のダッシュボード＝`/app/dashboard`）/
清掃会社ダッシュボード（表が取引先別で、ops の「施設別の請求」と対象が違う）。

**やり方**（次に表を足すときも同じ）
- 表は `.pk-grid` → `.pk-tbl`。横に長い表はカードの本文に `.pk-scroll-x`
- **空状態もカードの中**（表が無いときだけ枠が消えると読み込み失敗に見える）
- **消してはいけない文言は `.pk-panel__foot` へ**（INV-06 の担当者名の注記・
  在留資格の免責・「評価には使用しません」など）。**文言を変えない**
- 保存ボタンなど表に属さない操作もフッターへ
